# t15 · todo 列表流程梳理与状态刷新修复（2026-07-01）

参考 `claude-code-haha` 的 todo / task 系统，把天枢 todo 的「建 — 更新 — 展示」三条链路补齐。

## 背景：三个症状

1. **模型拿到任务不直接建 todo**：建 todo 的引导原本只散落在计划方法论（仅 plan 路由注入）、`glm` 模型专属校准、和 todo 工具那 5 行弱描述里。普通模型在非计划流程下几乎没有「任务 3 步以上就先建 todo」的明确指令，也没有「该建却没建」的运行期提醒。
2. **todo 不更新**：① `plan_task` 工具会写库（`setTodos`）但工具名不是 `todo`，TUI 立即刷新分支只认 `todo`，面板要等下一次轮询/回合结束才更新；② `turn-end.ts` 只在第 3 轮后才把 todo 回灌进提示词，前 3 轮模型看不到自己的清单，容易「忘了在跟」。
3. **状态展示**：任务面板本身（三态图标、进行中高亮、完成项折叠、智能可见窗口）已经成熟；缺口在顶部状态栏只显示计数，没显示「当前正在做哪一条」。

对照 claude-code-haha 的取舍（已与需求方确认）：力度用「软提醒为主 + 复杂任务升级硬提示」；**不**引入 `activeForm` 字段，只优化展示。

## 改了什么

### 1. 强化 todo 工具描述（`src/tools/todo.ts`）
把工具说明从干巴 5 行改成清晰守则：何时用（3+ 步 / 多子任务 / 收到新指令立即捕获）、何时不用（一步搞定的小事）、状态规则（同一时刻恰好一个 in_progress、完成即刻标记不批量、重写时不丢已完成项）。schema（`id/content/status`）保持不变，不动前缀缓存契约。

### 2. 新增「催建 / 催更」运行期提醒（`src/agent/hooks/todo-reminder-hook.ts`）
postTurn hook，仿 `typecheck-reminder-hook` 走 `advisoryBus`（统一劝导总线，system-reminder 通道）：
- **软提醒**：多步实际工作已发生但 todo 为空（第 3 轮起）→ 温和建议建清单，单步琐碎任务可忽略。
- **硬升级**：任务已展开 6 轮仍无 todo → 提高优先级、措辞更强。
- **陈旧提醒**：清单写过但 ≥10 轮未更新 → 提醒核对，并附当前清单快照回灌（对齐 claude-code 的 10 轮门槛）。
- 噪声控制：每条 ttl=1、`todo` 分类受总线每类上限保护、触发后进入 5 轮冷却；清单本轮刚写过则不提醒。
- 在 `src/agent/create-runtime-hooks.ts` 装配（有 `advisoryBus` 即常驻）；`src/agent/advisory-bus.ts` 新增 `todo` 劝导分类。

### 3. 修复刷新与回灌时机
- `src/tui/engine/app.ts`：工具结果立即刷新面板的分支从只认 `todo` 扩为也认 `plan_task`。
- `src/agent/turn-end.ts`：只要清单非空就从第 0 轮起回灌（清单是模型自己的目标分解）；启发式兜底仍保持「第 3 轮后且无清单」才用。决策抽取保留不变。

### 4. 状态展示打磨（`src/tui/format/glance-bar.ts` + `app.ts`）
顶部状态栏 todo 段，宽屏时把当前 in_progress 任务的 content 也显示出来（过长按显示宽度截断为 24 列），一眼看到「正在做哪一条」；窄屏仍退化为纯计数。用 content，不引入 activeForm。主区与右侧面板均读 `state.todos`，数据同源。

## 设计偏差 / 不做的部分
- **桌面多会话共享 `TODO_TOOL` 单例**（`src/tools/todo.ts` 内已标注的已知限制）本次未动——它牵动每个 `createDefaultToolRegistry` 调用方，属独立改造。
- 硬升级只「强提示」不真正阻断工具执行，避免误伤一步搞定的小任务。
- 未引入 `activeForm`（保留现 schema 与缓存契约）。
