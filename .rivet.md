# 天枢 (Tiānshū) — Terminal Coding Agent

Node.js 22 + TypeScript strict + Ink 6 (React TUI) + DeepSeek V4 API.

## Commands

```bash
npx tsc --noEmit                         # typecheck
npx tsx --test src/**/__tests__/*.test.ts # all 162 tests (node:test + assert/strict)
npm run build                             # tsup bundle
npm run dev                               # tsup --watch
node dist/main.js                         # launch
```

Typecheck + tests is the minimum verification after any code change.

## Files to Read First

| Task | Files to read |
|------|--------------|
| Add a tool | `src/tools/types.ts` → `src/tools/registry.ts` → an existing tool like `src/tools/grep.ts` → `src/main.tsx` (register) → `src/prompt/static.ts` (tool list) |
| Change system prompt | `src/prompt/static.ts` → `src/prompt/engine.ts` → `src/prompt/volatile.ts` |
| Fix agent loop behavior | `src/agent/loop.ts` → `src/agent/context.ts` → `src/tui/app.tsx` |
| Fix TUI rendering | `src/tui/app.tsx` → `src/tui/log-state.ts` → relevant component file |
| Fix API/streaming | `src/api/client.ts` → `src/api/sse.ts` → `src/api/deepseek.ts` |
| Fix tool output display | `src/tools/output-store.ts` → `src/tui/tool-card.tsx` → tool file |
| Fix compaction | `src/compact/auto.ts` → `src/compact/micro.ts` → `src/agent/loop.ts` |
| Fix config/CLI | `src/config/schema.ts` → `src/config/manager.ts` → `src/main.tsx` |

## Testing

- Framework: `node:test` + `node:assert/strict`
- Test files: `src/**/__tests__/*.test.ts` (mirrors source structure)
- Run single file: `npx tsx --test src/tools/__tests__/grep.test.ts`
- Tests use real filesystem + temp dirs (no heavy mocking)
- Pre-existing flaky: `compact.test.ts` — "truncates old messages iteratively" sometimes fails

## Code Conventions

- TypeScript strict mode, `noUncheckedIndexedAccess: true`
- No classes for data — use `interface` + plain objects
- Async/await with try-catch, never bare Promise chains
- Tools return `ToolResult { content, isError?, rawPath?, uiContent? }`
- Agent callbacks via `AgentCallbacks` interface (onToolResult, onCheckpoint, onEvidence)
- New tools must register in `src/main.tsx` and have tests

## Active Feature: Subagent Orchestration (P2.4)

Design doc: `docs/superpowers/specs/2026-05-16-rivet-subagent-orchestration-design.md`

Final design: **Cache-first Bounded Coordinator** (V2+V3). Primary AgentLoop decomposes tasks into typed WorkOrders, headless WorkerSessions execute with independent SessionContext, results return as schema-valid WorkerResult packets.

### Key Runtime Seams (from design doc)

| Seam | File | Why it matters |
|------|------|---------------|
| AgentCallbacks | `src/agent/loop.ts` | Narrowest lifecycle bridge between AgentLoop and outside world — text delta, tool use, approval, turn complete, abort, checkpoint |
| Tool.isConcurrencySafe() | `src/tools/types.ts` | Exists but never wired to runtime — coordinator must consume it as scheduling signal |
| SessionContext (mutable push) | `src/agent/context.ts` | Cannot be shared across workers — must fork or create independent sessions |
| ModelCapabilityCard | `src/model/capability.ts` | recommendModelForTask() exists as pure function but never called at runtime |
| VerificationMetadata | `src/agent/verification.ts` | Can extend to WorkerResult.verification |
| EvidenceTracker | `src/agent/evidence.ts` | Can extend to coordinator-level facts ledger |
| checkpoint v2 agentTouchedFiles | `src/agent/checkpoint.ts` | Can become worker write scope boundary |

### Phase 1 Hard Constraints

These are non-negotiable per the design doc:

1. **SessionContext isolation is mandatory** — worker messages must never enter primary session. Only compressed WorkerResult packets.
2. **Read-only workers only** — tool allowlist: `read_file`, `grep`, `glob`, `diff`, `inspect_project`, `repo_map`, `related_tests`. No write/edit/bash.
3. **Schema-valid results** — every WorkerResult must pass zod validation. Repair once on failure, then mark blocked.
4. **Primary authority** — only the primary AgentLoop decides final actions. Workers produce evidence, not decisions.
5. **Prefix cache preservation** — workers share the same system prompt and tool definitions as primary. No custom system prompts per worker.
6. **Budget gate** — tasks completable in 1-2 tool calls should NOT be dispatched. Default max 2 workers.

### Phase 1 Deliverables

- `src/agent/work-order.ts` — WorkOrderKind, WorkOrder, WorkerResult, AggregationPolicy, WorkerBudget types
- `src/agent/coordinator.ts` — research / code_search / review work orders only
- Independent WorkerSession with read-only ToolRegistry allowlist
- Schema-valid result parsing with repair fallback
- Primary session receives only compressed worker packets

## Common Mistakes

- **Don't use `execSync`** — tools use `spawn` or `execFile` for async, non-blocking execution
- **Don't import from `src/tools/bash.ts` directly** — use `ToolRegistry.execute()`
- **Don't add fields to `openclaw.json` that aren't in schema** — crashes Discord gateway
- **Don't amend commits** — always create new commits (git hook requirement)
- **System prompt changes invalidate prefix cache** — expect cache miss on the turn after changing static.ts
- **Tool output is truncated at 20 lines by default** — raw content is always at the rawPath
- **SessionContext is mutable shared state** — never pass primary session to a worker. Always create independent sessions.
- **Tool.isConcurrencySafe() is not wired** — coordinator must check it; don't assume it's enforced automatically
