### C — 根本缺口（不补则 A 做完也只是空转）⚠️

| # | 项 | 证据 | 后果 |
|---|----|------|------|
| C1 | **无 PlanStep[] 生产者** | `createTrace:104-116` `steps: steps ?? C1 的方向选项（待拍板）：

1. **LLM 驱动**：planning 阶段让模型产出 3–8 条结构化步骤（需输出解析或专用工具）。最贴合「自主规划者」愿景，成本最高。
2. **plan 文件派生**：从 `docs/superpowers/plans/*` 或 `plan_close` 流解析步骤。复用已有规划资产，中等成本。
3. **task-contract 派生**：从 6 态合同 + `successCriteria` 机械生成步骤骨架。最便宜，但步骤粒度可能粗。

## 4. 关键判断

**C1 优先级高于 A。** W4-deep 的 4 件接线全做完，只要缺 C1，trace 永远 0 步：`detectDeviation` 只剩 `blocked`/`stalled`，而这俩 `convergence-detector` 已经在用。即**照 W4-deep 直接接线：投入 ≈ 60 行 loop.ts 改动 + 高风险（2000+ 行、多会话共享），产出 ≈ 零新增能力**。

## 5. 建议次序（下阶段 U6）

```
C1（定 PlanStep 来源 + 实现步骤生产者）
  └─► B（补 PromptEngine 两个 setter + loop latestConvergenceResult 字段）
        └─► A（loop.ts 接线 A1→A2→A3→A4）
              └─► D（清 stepCounter 技术债）
                    └─► 集成测试（W5d 场景 + 反证）
```

不要直接照搬 U5/W4-deep 接线计划——它会产出「空 trace + 回声 replan」。U6 应以 C1 为起点重新规划接线波次。

## 6. 缰绳（沿用 U5 计划）

- 不改 loop.ts 回合控制流——只在已有 step 之间插入。
- 前缀缓存安全——trace 走动态附录（同 task-anchor / planCacheAdvisory），不碰冻结前缀。
- 零开销 for chat turn——`planTrace` 为 null 时全短路。
- 多会话安全——`planTrace` 是实例字段（同 `taskContract`）；D1 修掉后步 ID 也会话隔离。
