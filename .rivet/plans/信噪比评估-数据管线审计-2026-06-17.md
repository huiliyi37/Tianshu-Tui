## 信噪比分级

### 🟢 HIGH — 有用信号，保留


| 管线                                  | token/turn | 进 prompt  | 依据                             |
| ----------------------------------- | ---------- | --------- | ------------------------------ |
| `<task-contract>`                   | 80–200     | 是         | 反漂移锚点，防 compaction 丢目标         |
| `<verification-gap>`                | ~24        | 是         | 交付门禁，防未验证就声称完成                 |
| `<cognitive-mirror />`              | 45–72      | 是         | **性价比最高**：单行数值，无废话             |
| `<git-status>` + `<recent-commits>` | 50–300     | 是         | 代码注释明确：丢弃会诱发 bash 重取 doom-loop |
| `<task-progress>`                   | 30–150     | 是         | 直接支撑执行连续性                      |
| `<star-domain>`                     | 80–400     | 是         | 方法论/验证纪律                       |
| `<immune-signal>`                   | 0–150      | 条件触发      | 历史错误闭环，consume-once            |
| `<plan-execution-trace>`            | 50–300     | 有 trace 时 | salience 0.7，防 compaction 丢计划  |
| project-memory Tier1                | frozen     | 是         | decision/rule/constraint，高置信   |
| Meridian DB immune/mistake          | N/A        | 间接        | 有完整写入→读取→注入→影响决策闭环             |


### 🟡 MEDIUM — 有条件价值，可优化


| 管线                         | token/turn | 问题                               | 优化方向           |
| -------------------------- | ---------- | -------------------------------- | -------------- |
| `<historical-lessons>`     | 50–200     | 质量取决于 store；无 freshness TTL      | 加冷却 + TTL      |
| `<tool-history>`           | 80–250     | 摘要有用，但完整 history 已在 messages     | 压缩到 top-3 或仅失败 |
| `<decisions>`              | 20–300     | 与 session-state 重复               | 合并             |

| `<intent-retrieval-route>` | 125–375    | 多 direction 时噪声                  | 仅首条 user msg   |
| `<cross-session-memory>`   | 0–500      | 单 session 常空                     | 保留，无害          |

## 关键架构矛盾

### 1. CVM Throttle 管不住真正的浪费

```
shouldThrottleCvm = true 时：
  ✅ 清空 cognitive-mirror 的 sensorium 输入 (~50 tok 省下)
  ❌ affordance-hint 仍用完整 sensorium 注入 (~70 tok)
  ❌ policy-guidance 仍用完整 sensorium 注入 (~95 tok)
  
  省了 50，放过了 165。Throttle 几乎无效。
```

### 2. 三重进度/决策重复

```
<task-progress>  → todo 状态 (done/next)
<decisions>      → 决策列表
<session-state>  → task + plan + modified + decisions + failed

三者信息高度重叠，每 turn 合计 ~175-575 tokens。
```

### 3. 产出-消费断链

```
failure bullets → importance 0.3 → query(minImportance: 0.6) → 永远命中不了
claims → 标记 prompt consumer → 但不进 prompt → promotion 计数虚假
stigmergy → 注释"跨 session" → 实际 session 级 → Meridian 未接线
```

## 1M 窗口下的真正问题

1M 窗口下 token 占比已不是瓶颈（认知元数据全量 <0.05%），**appendix 硬顶 48K chars（~12K tok）也仅占 ~1.2%**。

问题不在 token 压力，而在 **行为影响**：


| 问题类型        | 具体表现                                                                      | 严重度                  |
| ----------- | ------------------------------------------------------------------------- | -------------------- |
| **工具选择犹豫**  | affordance 推 top-3 + policy 推 top-5 概率排名，模型可能"想选哪个"而非直接做                  | 高                    |
| **自我关注过度**  | vigor/season/confidence/exploration 多处暴露，模型可能自省而非执行                       | 中                    |
| **信号淹没**    | decisions + session-state + task-progress 三处重复进度，真正有价值的 immune-signal 被稀释 | 中                    |
| **数据垃圾积累**  | failure bullets 写了读不出、claims 空转 promotion、telemetry 落盘无人读                 | 低（不影响 runtime，但维护债务） |
| **假闭环误导开发** | 看起来接线了（有 set/get/render），实际数据到不了模型（strategyShift/impactHint/claimLines）   | 高（浪费开发精力）            |


**1M 窗口的核心判断标准不再是"省 token"，而是"这条数据注入后，模型行为变好还是变差"。**

## 推荐整治优先级

### Wave 1：消除行为降级（模型做更好的决策）


| #   | 动作                                                                             | 核心理由                             |
| --- | ------------------------------------------------------------------------------ | -------------------------------- |
| 1   | **合并 affordance + policy 为单块** `<tool-context>`，只保留 top-3 + 一行 EFE 摘要          | 消除双份工具推荐导致的选择犹豫                  |
| 2   | **删除死字段** (strategyShift/impactHint/behaviorMirror/activeClaims/planModeState) | 清理假闭环，不再误导后续开发                   |
| 3   | **合并 decisions + session-state + task-progress** 为单一 `<progress>` 块            | 减少重复信号对高价值信号（immune/contract）的稀释 |


### Wave 2：修复断链（让有价值的数据真正流通）


| #   | 动作                                                             | 核心理由                                 |
| --- | -------------------------------------------------------------- | ------------------------------------ |
| 4   | **Playbook failure importance 提升到 0.6** 或 failure 源单独低阈值 query | 失败经验是最有价值的学习信号，当前完全浪费                |
| 5   | **Claims 停虚假 prompt consumer 标记**                              | promotion 计数空转导致 memory.jsonl 写入判断失真 |
| 6   | **harness-advisory 与 system-reminder 星域感知去重**                  | 同类纠偏信号双份出现（appendix + 历史消息）          |


### Wave 3：数据卫生（减少垃圾积累）


| #   | 动作                                                       | 核心理由                      |
| --- | -------------------------------------------------------- | ------------------------- |
| 7   | **Telemetry 落盘改为可选 `RIVET_DEBUG_TELEMETRY`**             | sensorium.jsonl 无运行时读者    |
| 8   | **Fingerprint 按项目分区**（cwd hash → registry key）           | 消除跨项目假阳性 pattern          |
| 9   | **Stigmergy honest 降级**：文档改为 session-only，删 Meridian 死接口 | 代码与文档一致，不给未来开发制造幻觉        |
| 10  | **Dream project-memory.md 清理历史噪声条目**                     | 与当前高门槛 curation 不一致的旧格式数据 |
