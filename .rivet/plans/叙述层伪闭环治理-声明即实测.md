# 叙述层伪闭环治理 — 「声明即实测」

> 来源：天梁（`102264b9`）与天枢（`c8b804ae`）review 提炼的**共性问题**。
> 视角：瑶光（看循环、断循环）。详见 `docs/design/star-domain-eval-log.md`。
> 性质：跨域共性失效，治本靠机制、广覆盖靠公用提示词。本计划只定方案，待排期。

## 一、共性问题（一个 loop）

两者代码层均过关（typecheck/测试绿），出问题的都是**对自己交付物的声明**：

| 域 | 声明 | 实测 | 方向 |
|---|---|---|---|
| 天梁 | 注释/常量「字节」「行」 | 实为字符/条目 | 量纲 overclaim |
| 天枢 | 提交「19/19」 | 实为 17/17 | 数量 overclaim |

**根因**：现有「反伪闭环」纪律只施加在**代码与数据流**（`static.ts <workflow>` 读→改→diff→tsc+test、`star-domain.ts` 各域「全链路追踪」suffix），但对 agent **自己写出的交付叙述**——commit message 的数字、常量名/注释断言的量纲——从不要求回对账。叙述是凭意图/记忆产出，不是从实测抄。**代码伪闭环雷达灵敏，叙述伪闭环是盲区。**

## 二、修复方案（三层，按杠杆排序）

最高杠杆顺序 = **机制 > 公用提示词 > lint**。可机械化的部分用机制压死（LLM「凭记忆报数字」本就不可靠，提示约束不住）；不可机械化的用提示词广覆盖兜底；结构可判的用 lint。

### 层 1a（已交付 ✅ `58a523e3`）— deliver_task 回显最近验证实测数字

- **做什么**：`deliver_task` 输出新增 `Latest: N pass N fail N skip — <command>` 行，从 `VerificationMetadata` 提取最近一次验证的真实 pass/fail/skipped 计数。agent 写交付报告时从工具输出抄数字，不再凭记忆书写。
- **改动**：`DeliveryGateResult`/`DeliveryReport` 新增 `latestVerificationTotals` 字段（3 行）；`assess()` 从 `allVerifications` 末项提取（5 行）；`deliver-task.ts` 回显 Latest 行（7 行）。共 +27 行。
- **验证**：typecheck ✓、delivery-gate-v2 22/22 ✓、loop 33/34（1 pre-existing）✓。
- **局限**：只回显不强制——agent 仍可选择忽略 Latest 行自行报数。层 1b（门禁校验数字一致性）可补强制。

### 层 1b（待排期）— 门禁强制校验数字一致性

- 在 deliver_task commit 前校验：agent 自述的测试数是否与 `latestVerificationTotals` 匹配。不匹配则 YELLOW 警告。
- 依赖：需要一个「agent 自述数字」的提取点（commit message 或 checklist 参数）。

### 层 2（广覆盖·公用提示词）— `static.ts` `<output-style>` 加「声明即实测」铁律

- **为什么是这里**：`BASE_PROMPT` 是**唯一共用面**，所有域共享；星域 `systemPromptSuffix` 每域一份，改那里要动 9 个域。三项报告规范（`static.ts:93-96`）正是交付叙述落点，一处生效全域。
- **插入文案（草案，置于「任务完成时必须报告三项」之后）**：

  ```
  交付叙述的数字与量纲必须取自实测，不得凭记忆/意图书写：
  - 测试数、通过率等定量声明 → 从工具实际输出抄，不手写累加（"19/19" 必须等于 runner 真实汇总行）。
  - 标识符/注释声称的量纲（字节/行/字符/条目）必须与实现实际兑现的量纲一致——
    名为 BYTES 就不能用 .length/.slice 按码元算。声称与实现不一致时，改名或改度量，二选一。
  反伪闭环不止于代码，也包括你对代码的声明。
  ```

- **⚠ 前缀缓存代价（硬约束）**：动 `BASE_PROMPT` 会让**所有会话的前缀缓存失效**（系统提示是缓存锚点，见 CLAUDE.md「Prefix cache is the core optimization」）。因此本条**不单独提交**，必须**与下一批 static 提示调整合并一次性落地**，避免单条规则触发全局 invalidate。
- **验收**：插入后 `buildSystemPrompt` 输出含该块；与其它待办 static 改动同批；提交说明标注「本批 static 变更一次性 invalidate 前缀缓存」。

### 层 3（结构可判·lint/review）— 量纲一致性窄规则

- **做什么**：`*_BYTES`/`*_LINES`/`*_MS` 这类带量纲后缀的常量，若被语义不符的操作消费（`*_BYTES` 被 `.length`/`.slice`/`.push` 按码元/条目计数）则告警。
- **锚点**：挂到 code-review-graph 的 review 通道（`detect_changes`/review 规则），或一条轻量自定义检查；非阻塞，提示性。
- **验收**：对 `capToolAccumulator`（`app.ts`，`TOOL_ACCUMULATOR_MAX_BYTES` 配 `.length`）能命中告警。
- **优先级**：最低，可与「字面精度收敛」计划（M1/M2）合并验证。
