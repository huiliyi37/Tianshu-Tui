# 桌面端会话关闭/归档功能

## 问题

桌面端（Tauri）会话创建后没有关闭/退出机制——侧边栏线程列表越来越长，无法清理已完成的会话。需要一个关闭按钮，关闭后归档会话（从列表移除）。

## 根因

后端 `RuntimeSessionManager` 只有 `createSession` / `abort`，没有关闭/归档/删除的 API；桌面端 `client.ts` 和 `queries.ts` 也没有对应的调用；UI 侧 `ThreadView` 头部和 `ProjectSidebar` 线程卡片都没有关闭按钮。

## 方案：归档（软删除）而非硬删除

用户说"归档掉"——会话历史数据保留（events.jsonl / artifacts 不删），只是从活动列表中隐藏。比硬删除更安全，未来可恢复。

### 改动范围（5 文件）

**后端（3 文件）**

1. **`src/server/session-manager.ts`**
   - `SessionRecord` 加 `archived?: boolean` 字段
   - 加 `archiveSession(id): boolean` 方法：标记 `archived=true`，如果运行中则先 abort，持久化记录，释放 registry claims
   - `listSessions()` 过滤掉 `archived=true` 的会话

2. **`src/server/session-routes.ts`**
   - 加 `DELETE /sessions/:id` 路由 → 调用 `manager.archiveSession(id)`
   - 更新文件头注释的路由列表

3. **`src/server/__tests__/session-routes.test.ts`**
   - 加测试：DELETE 归档后 listSessions 不包含该会话、getSession 仍可访问、404 for missing

**桌面端（3 文件）**

4. **`desktop/src/runtime/client.ts`** + **`desktop/src/runtime/types.ts`**
   - client 加 `closeSession(id)` → `DELETE /sessions/:id`
   - types.ts `SessionRecord` 加 `archived?: boolean`

5. **`desktop/src/state/queries.ts`**
   - 加 `useCloseSession()` mutation hook → 调用 `closeSession`，成功后 invalidate sessions

6. **`desktop/src/surfaces/ThreadView.tsx`** + **`desktop/src/surfaces/ProjectSidebar.tsx`**
   - ThreadView header 右侧加一个关闭按钮（× 图标）
   - ProjectSidebar 线程卡片加 hover 显示的关闭按钮
   - 关闭后清除 activeSessionId（如果关的是当前线程）

## 验证计划

- `npx tsc --noEmit` 通过
- session-routes 新测试 + 已有测试全通过
- 手动验证路径：创建会话 → DELETE → listSessions 不再包含

## 风险

低。归档是纯软删除，不涉及数据丢失。持久化层不需要改——`archived` 字段通过 `saveRecord` 自然写入 index.json，`rehydrate` 读取时自动恢复。
