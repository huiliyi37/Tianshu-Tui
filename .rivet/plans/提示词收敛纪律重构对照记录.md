# 提示词收敛纪律重构对照记录

## 背景

`src/prompt/__tests__/kernel-budget.test.ts` 红线：

```
BASE_PROMPT is 222 lines (limit: 210)
```

触发提交：`fea4fd85 feat(agent): add batch convergence discipline for parallel tool results`

该提交在 `src/prompt/static.ts` 的 `<tool-usage>` 段落新增 5 行“收敛纪律”，把 BASE_PROMPT 从 217 行推到 222 行，超过 kernel-budget 守卫阈值 210。

## 根因分析

1. **静态提示词与运行时 hook 重复**：`src/agent/hooks/batch-convergence-hook.ts` 已承担“单 turn ≥5 个工具时注入三层收敛 advisory”的职责，static.ts 再写一遍属于同义重复。
2. **验证类规则重叠**：`evidence-scope`、`external-source-verification`、`lossy-observation-discipline` 三段都在讲“不要信单一来源、要交叉验证”，可合并压缩。

## 目标

- 不抬 `kernel-budget.test.ts` 的 210 行阈值。
- 不修改 `src/prompt/__tests__/static.test.ts` 的既有断言。
- 不改动 `prompt/engine.ts`、`volatile.ts`（遵守性能优化计划 Wave 5 约束）。
- 把 BASE_PROMPT 从 222 行压到 205 行左右，恢复绿灯。

## 改动二：移除 tool-usage 中的收敛纪律重复描述

### 当前状态

`src/prompt/static.ts` 第 132–136 行：

```xml
收敛纪律（硬性闸门）：并行只读工具返回后，必须完成三层收敛再下结论：
1. 分类层 — 将返回结果按类型分桶：存在性判断（glob/bash ls）、内容读取（read_file）、模式搜索（grep）。不跨桶比较。
2. 交叉验证层 — 关键结论（"X 不存在""Y 等于 Z"）在用于推理前，至少用另一条独立结果确认一次。单来源 = 待验证假设，不得作为结论。
3. 综合判断层 — 前两层完成后再给结论。跳过任一层 → 适得其反的信息过载。
并行上限：单批只读工具不超过 5 个；存在性探测和内容读取不得混在同一批。
```

共 5 行。

### 改动后状态

保留硬约束，删除重复的方法论描述：

```xml
并行上限：单批只读工具不超过 5 个；存在性探测和内容读取不得混在同一批。
```

共 1 行。

## 风险与注意事项

1. **有损观测语义不丢**：`lossy-observation-discipline` 规则名删除，但内容并入 `evidence-scope`，且 `src/agent/hooks/lossy-observation-hook.ts` 仍会动态注入更强烈的提醒。
2. **收敛纪律不丢**：`batch-convergence-hook.ts` 在工具数 ≥5 时注入的 advisory 文案与删除的 4 行内容等价。
3. **不要顺手改测试**：`src/prompt/__tests__/static.test.ts` 的断言已按保留短语对照表核对，无需改动。
4. **不碰 engine/volatile**：本次仅调整 `static.ts` 的 BASE_PROMPT 常量，符合性能优化计划 Wave 5 的“不改 prompt/engine.ts”约束。
