# 缓存命中率数据流排查 — 三处断裂点

> 排查时间：2026-06-14
> 触发：用户反馈 UI 终端缓存命中率显示异常，怀疑数据未正确记录
> 当前配置：GLM 5.2（commit 39658f62）

## 断裂点分析

### 断裂点 A — GLM 5.2 API 字段名不匹配（最可能根因）

**位置**：`src/api/openai-client.ts:645-651`

**现状代码**：
```typescript
// L645
const cacheRead = usage.prompt_cache_hit_tokens ?? usage.prompt_tokens_details?.cached_tokens ?? 0
const cacheCreation = usage.prompt_cache_miss_tokens ?? 0
```

**问题**：
- `prompt_cache_hit_tokens` / `prompt_cache_miss_tokens` 是 DeepSeek 特有字段
- 当前配置已从 DeepSeek 切换到 GLM 5.2（commit 39658f62）
- GLM（智谱）API 的缓存字段格式尚未确认，可能是：
  - OpenAI 标准格式：`prompt_tokens_details.cached_tokens`（有 fallback）
  - 智谱私有格式：可能完全不同的字段名（无 fallback）
- `cacheCreation`（`prompt_cache_miss_tokens`）**没有 OpenAI 格式 fallback**，GLM 不返回此字段时恒为 `0`
- 当 `cacheRead = 0` 且 `cacheCreation = 0` 时，`getCacheHitRate()` 返回 `0`，`getRecentTurnHitRate()` 返回 `null`

**影响**：缓存命中率永远显示 `⚡0%` 或不显示

**验证方法**：
1. 在 `processDelta` 的 usage 解析处加临时 log，打印原始 `chunk.usage` 对象
2. 发一条消息，观察 GLM API 实际返回的 usage 字段结构
3. 确认 GLM 是否返回缓存相关字段，字段名是什么

### 断裂点 B — usage chunk 没到达时的 fallback 传空对象

**位置**：`src/api/openai-client.ts:602-606`

**现状代码**：
```typescript
// 无 usage chunk 时的 fallback
if (this.pendingStopReason) {
  callbacks.onStopReason?.(mapFinishReason(this.pendingStopReason), {})
  this.pendingStopReason = null
}
```

**问题**：
- 传空对象 `{}` 给 `onStopReason`
- `turn-stream.ts:170` 检查 `usage.cache_read_input_tokens !== undefined` — `{}` 中该字段是 `undefined`
- 条件不满足，`recordTurnCache` 不被调用
- `turnCacheHistory` 为空 → `getRecentTurnHitRate(3)` 返回 `null`
- `getCacheHitRate()` 返回 `0`（因为 totalUsage 也是 0）
- `app.tsx:1166`：`null ?? 0` = `0`
- GlanceBar 显示 `⚡0%`（因为 `0 !== undefined` 为 true）

**影响**：即使 API 不返回 usage，UI 仍显示 `⚡0%` 而非隐藏缓存指标

### 断裂点 C — usage chunk 被 choice 条件拦截

**位置**：`src/api/openai-client.ts:634`

**现状代码**：
```typescript
// Usage-only chunk (final chunk with include_usage)
if (chunk.usage && choice === undefined) {
```

**问题**：
- 如果 GLM 在最后一个 chunk 同时携带 `choices` 和 `usage`，`choice` 不为 `undefined`
- 这个分支不会执行，usage 被跳过
- 需要确认 L710-719 是否有第二路径捕获这种情况

**位置**：`src/api/openai-client.ts:710-719`

需要确认这个路径是否覆盖了 GLM 的 usage+choice 组合 chunk。
