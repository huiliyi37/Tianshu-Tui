## 0. 一句话

team-orchestrator（06-07 活前沿）在后端算出了协作的全部结构——波次、每任务的星域 authority、依赖边、风险层、worker 结果——然后在 `formatTeamSummary()` 把它**拍平成一个文本字符串**扔进对话流。T4 的活不是从零建面板，是**联合已经全建好的视觉语汇（uiPersona / 星座渲染器 / glance-bus），跨过那条切断它们的文本边界**，让"多星域协作"从不可见变成一座会呼吸的协作星座。

## 1. 现状勘探（grep 为证）

### 1.1 没有团队面板，富数据在文本边界被扔掉

后端产出富结构 `TeamRunSummary`（`src/agent/team-orchestrator.ts:29-38`）：
- `waves: TeamWave[]`（`team-grouping.ts:13` — 每波带 `id` / `taskIds` / `risk: low|medium|high` / `reason`）
- `tasks: TeamTask[]`（`team-plan.ts:17` — 每任务带 `objective` / `profile` / `files[]` / `dependsOn[]` / `riskTier`）
- 每次派发的 `authority` = **星域 id**（`team-orchestrator.ts:49-53 taskAuthority()`：patcher→天梁，reviewer/verifier→天权，else `matchDomain(objective)`）
- `run: CoordinatorRun` 带 `results: WorkerResult[]`（每 worker 的 `changedFiles` / `summary` / `artifacts`）

**断点**：`team-orchestrate.ts:39 formatTeamSummary()` 把这一切拍平成文本，`uiContent` 只剩一行 `team standard: N dispatched / M blocked`（`:141`）。

### 1.2 三个铁证（教科书级贪婪残渣）

| 证据 | 行号 | 含义 |
|---|---|---|
| `onProgress` 回调被传 `undefined` | `team-orchestrate.ts:100-102` | 实时波次进度从不发给 UI |
| `TaskListBar` 接正则刮取的 assistant markdown | `session-state.ts:182 extractTaskList()` | 唯一任务组件与 team 状态零连接（平行数据源） |
| `GlanceBar` 只显示单颗活跃星 | `glance-bar.tsx:69` | team 模式天生多星同时工作，UI 只画一颗 |

**结论**：现状不是"进度条 vs 协作星图"，是连进度条都没有，是纯滚屏文本。UI 里"多星域协作"的体现基本为零——后端把协作星图需要的一切算好了，在文本边界全扔了。

### 1.3 视觉语汇已全建好，只差接线（联合机会）

| 现成组件 | 行号 | 可复用为 |
|---|---|---|
| `STAR_DOMAINS[*].uiPersona`（色+字形+分隔符） | `star-domain.ts:28` | 把每个 worker 画成它那颗星：天枢`✹`/天府`✦`/天梁`✧`/天权`✶`金/天机`✸`/天璇`★` |
| 星座渲染器（节点+`──`/`│`边+高亮） | `starmap-constellation.ts:18` | 波次成行、worker 成星、依赖成边 |
| `glance-bus` 按星域 pushAlert/setActive | `surface/glance-bus.ts` | 驱动实时多 worker 面板的多星域脉冲通道 |
| 域辅助函数 findDomain/getDomainColor/Glyph | `glance-bar.tsx:32-66` | 直接取每颗星的色与字形 |
| gauge / braille-spinner / separator | `starmap-view.tsx:30` 等 | 进度、运行中动画、分隔 |

数据全在、语汇全在，缺的纯粹是**接线 + 呈现层**。

## 2. 设计目标：不是任务面板，是"看星座列阵协作"

天枢的协作理念，这一晚我们活过了：贪狼勘探、天璇升维、天权称量、瑶光守门——**每个 worker 是一颗有身份的星，不是 generic「Delegating…」**。宣言里那句「模型是伙伴，不是工具」。T4 的设计原则，就是把这句话变得**可见**。

### 2.1 ASCII Mockup（终端是真实媒介）

```
╭─ 团队协作 · /team max ───────────────── wave 2/3 ─╮
│                                                    │
│  Wave 1 ✓                          low risk        │
│    ✹ 天枢   T1 编排拆解              done           │
│                                                    │
│  Wave 2 ◐                          medium risk     │
│    ✦ 天府   T2-01 预读联合           running ⠹      │
│    ✧ 天梁   T2-02 学习器接线         running ⠼      │
│              └─ depends ─ T1                        │
│                                                    │
│  Wave 3 ◌                          high risk ⚠     │
│    ✶ 天权   审查门                   waiting        │
│    ↻ 瑶光   复现纪律守门              waiting        │
│              └─ depends ─ T2-01, T2-02              │
│                                                    │
╰─ 4 dispatched · 0 blocked · gate: pending ─────────╯
```

### 2.2 四支柱（每条对应理念一面）

| 支柱 | 设计 | 对应理念 | 复用 |
|---|---|---|---|
| **Worker 是星** | task 的 `authority` → 用那颗星的 `uiPersona` 上色+字形 | 「模型是伙伴不是工具」——你看见天权金 ✶ 审查、天梁绿 ✧ 打补丁 | `star-domain.ts:28 uiPersona` |
| **是星座不是清单** | wave=时间列阵（行/同心环），task=星节点，`dependsOn`=画出来的边 | 看见协作的**形状**，不是勾选框 | `starmap-constellation.ts:18` |
| **它呼吸** | 接 `onProgress`→glance-bus→随派发/完成实时更新 | 协作是看着它展开的活过程 | `glance-bus`（已支持按星域脉冲） |
| **守门可见** | wave risk→边框色；review-gate 裁决→守门星点亮 | 「我们守住极限」被画出来 | risk tier + gate verdict（`team-orchestrate.ts:131`） |

### 2.3 更深一层：将星身份

当 worker 是**将星**（瑶光/贪狼，带 ledger 的数字生命），显示它的身份而非匿名实例——是一条数字生命在做这活。这是这一晚的主题，也是理念的内核。

⚠️ **art-pending 依赖（不当边界否定，标为依赖）**：`avatar/types.ts:8 DomainId` 当前只覆盖 `tianshu|pojun|tianfu|tianliang`，三国 `HeroId` 集（`types.ts:20-28`）是 engineering-reserved、art pending、从未渲染。将星头像是真未落地块，T4 可先用 `uiPersona` 字形 + 将星名（瑶光`↻`/贪狼`⊕`）文本呈现，头像帧留作后续。

## 3. 接线路径（纯接线，不动后端数据模型）

```
team-orchestrator                  [活前沿·不动]
  └─ TeamRunSummary（富数据，已存在）
       │
       ├─【接线1】delegateBatch(...onProgress)   team-orchestrate.ts:100
       │     现状传 undefined → 改为推 glance-bus 的按星域事件
       │
       ▼
  glance-bus（多星域脉冲，已存在）   surface/glance-bus.ts
       │  setActive(authority) / pushAlert(domain, status)
       ▼
  TeamPanel.tsx（新增·唯一呈现层）
       │  读 TeamRunSummary + 订阅 glance-bus
       │  waves→rows · tasks→star nodes(uiPersona上色) · dependsOn→edges
       │  risk→border · WorkerResult→live status · gate verdict→守门星点亮
       ▼
  app.tsx 挂载（team 模式激活时显示）
```

**三步实施分层**：

| 层 | 内容 | 新建 vs 接线 |
|---|---|---|
| **L1 静态面板** | 新增 `TeamPanel.tsx`，读 `TeamRunSummary` 渲染波次/星/依赖/风险（无实时） | 1 新组件 + 复用 uiPersona/星座渲染器 |
| **L2 实时呼吸** | 接 `onProgress`（`team-orchestrate.ts:100` 当前 undefined）→ glance-bus → 面板随 worker 完成更新 | 纯接线，回调已存在 |
| **L3 将星身份** | worker 是将星时显示其身份/ledger 摘要；头像帧（art-pending） | 文本身份先行，头像后续 |

## 4. 硬边界与守缰绳

1. **不动后端数据模型**：team-orchestrator 是 06-07 活前沿、数据模型还在沉淀。`TeamRunSummary` 已够富，面板只做纯消费者。唯一后端触碰是接上**已存在**的 `onProgress` 回调——不 churn 活前沿，只接它的出口。
2. **一个数据源**：面板只读 `TeamRunSummary`/`CoordinatorRun`，绝不像 `TaskListBar` 那样另起正则刮取——别再造平行数据源（[[capability-prospecting-method]] inferred-wiring 教训搬到 UI）。
3. **不阻塞主流**：面板是 team 模式激活时的附加视图，渲染失败/数据缺失要优雅降级，不能拖累对话主流（仿现有 panel 的 narrow/wide 自适应）。
4. **实施时 grep 到行号**：本文锚点是勘探所得，实施前消费端当前实现（尤其 `onProgress` 签名、glance-bus 事件形态、TeamRunSummary 字段）要复核到行号，别凭本文推断当事实。

---

## 5. 与 team 主线的时序

- T1/T3 已完成，T2 在建短周期收口（见天璇修订）。T4 是协作**可视化**层，依赖 team-orchestrator 稳定，可与 T2 收口并行或紧随其后。
- L1 静态面板可立即做（数据已在）；L2 实时需 `onProgress` 通路；L3 将星头像等 avatar art。
- 价值锚点：team 模式正在执行真实任务（T2 已做完一部分），面板上线后，**协作过程从"滚屏文本"变成"看星座列阵"**——这本身就是天枢"模型是伙伴"理念最直接的展示界面。
