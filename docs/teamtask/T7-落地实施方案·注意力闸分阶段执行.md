## 0. 落地前已 fail-closed 核实的两处技术前提（不取信声称，自跑代码核过）

| 审查声称 | 自核结果 | 对落地的意义 |
|---|---|---|
| 天璇③：`<git-status>` short/long parser 错配 | **坐实，且更严重**：`volatile-git.ts:21` 跑 `git status --short`（产 `M file`/`?? file`），但 `git-status-summary.ts` 的 parser 认 long status（`On branch`/`modified:`）。`summarizeGitStatus` 仅在 `length>1200` 走 parser → short 喂 long parser → branch=unknown、列表全空。**文件越多结构丢得越彻底**，这是既有真 bug，非 T7 引入 | 阶段 2 必须先补 short-status parser，且顺路修这个 bug |
| 天权⑤：`fs.watch` 回调 filename 可能为空 | **坐实**：`fs-watcher.ts:74,82` 两个 watch 回调签名是 `() =>`，根本没接 filename。要按路径分类得先改签名接住，且 filename 确实可能为空（rename/平台差异） | 阶段 1 第一坑：unknown filename 必须 fail-toward-signal，不得静默 |
| 当前实现确认：`buildStableVolatileBlock` 已剥离 gitStatus | **坐实**：`volatile.ts:145` 的 stable builder 显式把 `gitStatus: undefined`，`volatile.ts:272` 才在 dynamic appendix 取 `gitStatusCache` 并 `summarizeGitStatus` | 阶段 2 可只改 dynamic 渲染路径；测试必须证明 folded status 不进入 frozen，避免 prefix-cache 退化 |
| 当前实现确认：6 个 surface 的名单确实分裂 | **坐实**：`inspect-project.ts:12`、`glob.ts:8`、`repo-map.ts:6`、`meridian-indexer.ts:16` 各有不同 EXCLUDE/IGNORE；`fs-watcher.ts:74,82` 与 git-status 动态渲染链路无 attention 判定 | 阶段 3 不能一刀“删名单”；每个 surface 先定义 explicitness，再区分 attention 语义、性能剪枝与项目 ignore 语义 |
| 当前工作区压力样本真实存在 | **坐实**：当前 `git status` 中 `.agents/ .codex/ .obsidian/ .rivet/tasks/ .test-tmp/ layout.log docs/teamtask.zip` 同时出现 | T7 的第一组验收样本必须覆盖这些真实噪音族；但同伴文档仍应 L3 在场，不能把 `docs/teamtask/*.md` 折叠掉 |

### 0.1 本次执行补充意见（写入后作为硬门）

1. **阶段 0 只做纯函数与测试，不接任何 surface。** 这一步的价值是建立可证明的分类语义；任何行为变化都属于偷跑。
2. **阶段 1 先以可控单测模拟 `recordEvent(filename)`，再考虑真实 `fs.watch` 时序测试。** 真实 watcher 可作为补充，但硬断言应落在可复现的分类→计数数据流上，避免平台抖动造成 false-red/false-green。
3. **阶段 2 先写 RED 复现：大于阈值的 short-status 当前会退化成 `[unknown]` 且丢路径。** 不复现这个既有 bug，不准声称 parser 修复已验证。
4. **阶段 3 每个工具都必须先写 explicitness 表。** `path`、`pattern`、“是否宽泛扫描”、点名 L1/L2 的判断不清楚时，不接 attention filter；宁可延后，也不让默认沉默滑成工具不可达。
5. **提交粒度不变：文档补充可随阶段 0 一起提交；阶段 1/2/3 各自独立提交。** 若阶段 0 后验证未过，停在阶段 0，不带病进入 watcher。

## 2. 四个阶段（对应 T7 §6 四笔，第四笔按天权要求拆小为逐工具）

### 阶段 0 — 权威分类器（纯新增，零接入，零风险）

- **做**：`src/context/attention-filter.ts` — `classifyPath(relPath): AttentionVerdict`，输出 `{tier: L0|L1|L2|L3, silent, reason}`，纯函数。
- **守**：C1（不读 git/配置/内容）、C5（兜底 L3）、C8（L2 基线只 `.agents/.codex/.obsidian/.claude`；`.vscode/.idea` → L3）。
- **测**：四层分类正确 + fail-toward-content（陌生无扩展名→L3）+ **无 `.git` 目录下结果不变**（解耦铁证）+ L2 基线边界（`.vscode`→L3）。
- **门**：测全绿 + `tsc --noEmit` EXIT 0 → 独立提交。**此笔不改任何现有行为**，最安全，先落建信心。

### 阶段 1 — fs-watcher 接入（链路 A，与 git 解耦，先收最普适的伤）

- **做**：watch 回调 `() =>` 改 `(event, filename) =>`；有 filename → `classifyPath`，L0–L2 不计 eventRate；无 filename → 照常计入。
- **守**：C6（unknown→fail-toward-signal，本阶段第一坑）。
- **测**：根目录高频写 `layout.log` → eventRate 不升；**filename 缺失事件不被吞**（反证）；已监听子目录内 `.ts` 变动 → 正常计入。
- **门**：测全绿 → 独立提交。

### 阶段 2 — git-status 折叠（链路 B，最敏感，单独一笔）

- **做**：先补 **short-status 结构化 parser**（`M file`/`?? file`/`A `/`D ` → `{path, xy}`），替掉认 long status 的旧逻辑；再按 verdict 分层——L3 列出、L1/L2 折叠成 `[N 个运行碎片已折叠]`、L0 不现。
- **守**：C7（只在 dynamic appendix，先解析后折叠，不在字符串尾硬贴）、C3（结果折叠非删除）。
- **测**：47 文件混合 → L3 列/L1L2 折叠计数/L0 不现；**fingerprint stable across buildRequest**（cache 没破）；**回归 short/long 错配 bug**：大 status（>1200B）不再退化成空摘要。
- **门**：测全绿 + fingerprint 稳 → 独立提交。
- **附带价值**：顺路修掉 §0 那个既有真 bug（非 T7 引入，T7 顺路治）。

### 阶段 3 — discovery surface 逐个接入（天权硬要求：拆小，不准一次改四个）

- **做**：`inspect-project / meridian-indexer / glob / repo-map` **一工具一笔**，每笔：① 定义该工具 explicitness（path/pattern/点名）；② 默认 broad 扫描消费 verdict 降噪；③ 显式目标可达；④ glob 的 `GitignoreFilter` 保留；⑤ 独立回归测试通过后才进下一个。
- **守**：C2（显式不吞）、C3（剪枝≠折叠）、C4（不删 GitignoreFilter，不混项目 ignore 与注意力）。
- **门**：**每工具一笔独立提交**，共四笔。天权明令不许一次性改四个 discovery surface。
