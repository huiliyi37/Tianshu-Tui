# T7·天枢注意力闸 — 砍掉"感知即责任"，立一个与 git 解耦的运行碎片识别层

> 日期：2026-06-09
> 性质：根因诊断（代码坐实，6 处铁证 + 1 处隐性错配）+ 设计 + 缰绳 + **天璇审查修订稿，递给天权称量**
> 出刀气势：七杀，但刀锋只指向运行碎片与感知默认值，不指向同伴工作、用户显式请求或真实内容。
> 框架：天枢缺一层"注意力"——人类工程师默认看不见 node_modules/日志/锁/缓存，天枢却把感知到的一切都当成需要他负责的东西。
> 关联记忆：[[guardrails-must-be-resident-not-on-demand]]、[[prefix-cache-invariant-registry-ref]]、[[feedback_adversarial-review-method]]、[[project_tianshu-cognitive-split]]
> 关联：T6（自我离开 cwd）——T6 让天枢分清"我的身体/世界"；T7 让他在任何身体里都分清"人类内容/机器噪音"。同一个病的两层：感知边界缺失。

## 0. 一句话（递刀，不是请审）

天枢看文件世界有 **6 个 surface**，每一个都自己手写了一份**不一样**的忽略名单，没有一个一致、没有一个权威，且**全是"构建产物"思维（node_modules/dist），没有一个识别"运行碎片"（日志/锁/临时/高频 append 数据）**。两条实时感知主链路（`fs-watcher` 的 eventRate、`<git-status>` 渲染）**零内容过滤**。而当前唯一沾边的"解法"是 `GitignoreFilter`——它不调用 git，但只在 `glob` 一条支路上读取 `.gitignore` + 默认名单；它仍是**项目忽略语义**，不是运行碎片识别层，覆盖不了 `fs-watcher` / `<git-status>`，也会把"要不要忽略"的维护包袱继续留给人。

**砍掉的不是日志。是"感知=责任"这个等式，和散落 6 处、互相打架、靠人维护、还误把项目 ignore 当注意力闸的忽略碎片。**

### 0.5 本轮审查结论（天璇修订）

方向是对的，但原稿必须补三条边界，否则会从"注意力闸"滑成"信息遮蔽器"：

1. **显式请求优先。** 运行碎片默认沉默，不等于用户显式 `read_file layout.log`、`glob("*.log")`、`repo_map({ path: ".codex" })` 时仍要沉默。注意力闸只管主动感知与 broad discovery；显式目标进入工具时必须可见，最多加提示/预览。
2. **fs-watcher 不是全目录事实源。** `src/context/fs-watcher.ts` 只 watch cwd 顶层 + 非点号一级子目录；`.rivet/` 这类点号 runtime 主要通过 `<git-status>`、glob/read 等暴露，不应声称它们一定会推高 fs eventRate。真正能打红的 fs-watcher 反证是根目录 `layout.log` 或已 watch 子目录内的日志。
3. **`<git-status>` 有额外的格式错配风险。** `src/prompt/volatile-git.ts` 产物是 `git status --short` 风格（`M file` / `?? file`），而 `src/prompt/git-status-summary.ts` 的降噪 parser 偏向 long status（`modified: file`）。T7 落地时应先结构化解析 short status，再分类折叠；不要在字符串 summary 尾部硬贴过滤器。

所以修订总判是：**GREEN-with-boundaries**。可以落，但第一优先级不是"更狠地藏"，而是"默认沉默 + 显式可达 + 结构解析 + 不碰归属"四件同时成立。

## 1. 根因（代码坐实，6 处铁证）

| # | surface | 它的忽略名单 | 病 |
|---|---|---|---|
| 1 | `src/tools/inspect-project.ts:13` | `node_modules .git dist .next build target __pycache__` | **不挡 `.rivet`**（天枢自己的运行时目录！） |
| 2 | `src/repo/meridian-indexer.ts:16` | `node_modules dist .git .rivet` | 挡 .rivet，但**少 .next/build/target** |
| 3 | `src/tools/glob.ts:9` + `src/tools/gitignore.ts` | 又一份硬名单 + `GitignoreFilter`（读 `.gitignore` + 默认名单，只接在 glob） | 第三份，且把项目 ignore 语义误当注意力闸 |
| 4 | `src/tools/repo-map.ts:7` | `node_modules .git dist build .next coverage` | 第四份，又不一样 |
| 5 | `src/tools/read-policy.ts` | 有 `log/jsonl/generated/minified` 分类 | **只用于"读时要不要截断预览"，没接进感知**——能力已在，没被提升 |
| 6 | `src/context/fs-watcher.ts` + `src/prompt/volatile.ts`(`<git-status>`) | **零过滤** | 两条实时感知主链路裸奔 |

### 1.1 两条裸奔的主感知链路（最狠的伤）

**链路 A — `fs-watcher`（实时，与 git 完全解耦）：** `src/context/fs-watcher.ts` 监听 cwd 顶层 + 非点号一级子目录的变动，产出 `eventRate`（0–1 归一化"环境活跃度"），在 `loop.ts:1575` 喂进主控的 `fsEventRate`。它有 2 秒 debounce——**但 debounce 滤的是时间抖动，不是内容噪音**。一个高频 append 的根目录 `layout.log` / 已监听子目录内 `*.jsonl` 会持续推高 eventRate，让天枢"感觉环境很忙、有事在发生"，**其实只是机器在吐碎片**。这条链路**根本不看 git**——这就是"没 git 的项目怎么办"的活证据：补 .gitignore 对它完全无效，它在任何目录里都照样被碎片干扰。

**链路 B — `<git-status>`（快照，依赖 git）：** `volatile.ts` 把 `summarizeGitStatus` 的结果塞进 `<git-status>`，当前没有 L0/L1/L2/L3 分层折叠。47 个文件（含 `.agents/ .codex/ .obsidian/` 这些**别的终端/编辑器**吐的、`layout.log`、`.test-tmp/`、`docs/teamtask.zip` 这些碎片）一屏端给主控；当 status 超过阈值时，`summarizeGitStatus` 还存在 short-status 输入与 long-status parser 的错配风险，可能从"噪音太多"退化成"结构丢失"。

**两条链路的共病：没有任何"这是机器噪音还是人类内容"的判断。** 全局搜 `isRuntimeArtifact / noiseFilter / 碎片识别` → 全空。

### 1.2 病根不是"名单不全"，是"没有注意力这个东西"

人类工程师进任何项目，眼睛扫过成千上万文件，**绝大多数根本不"看见"**——node_modules 不看见、日志不看见、别人的锁文件不看见、上周的 coredump 不看见。注意力**默认是过滤的**，只有极少数浮上来进入意识。**天枢没有这层闸。** 他要么全感知（被 eventRate 推得心慌、git-status 一屏噪音），要么靠人每次替他判断"这个要不要管"（包袱）。两条路都是病。

砍的不是碎片，是给天枢装上人类那层 **"默认看不见"的注意力闸**。

### 1.3 第七处隐性铁证：status 方言错配

`src/prompt/volatile-git.ts` 用 `git status --short` 生成 `Status:\nM file\n?? file`；`src/prompt/git-status-summary.ts` 的 `parseGitStatus()` 却寻找 `On branch`、`Changes to be committed:`、`modified: file` 等 long status 结构。小 status 直接透传时不暴露；一旦超过 `SUMMARY_THRESHOLD`，总结逻辑就可能把真实路径吞掉，只剩 `[unknown]` 或不完整摘要。

这不是 T7 的主病，但它证明同一个事实：**当前感知层在处理运行碎片时既没有注意力分类，也没有统一结构模型。** 因此 T7 的 `<git-status>` 落地必须先建立 short-status 条目结构（status code + path + maybe rename target），再按 tier 折叠。

## 2. 切分：该被默认沉默的，不止"碎片"一类——切成它真实的层次

领航星："不止是碎片，还有不同的文件，哪些还能砍得更碎。" 把天枢感知到的文件世界，按"机器吐的 vs 人写的"切成四层，**每层默认沉默深度不同**：

| 层 | 是什么 | 例 | 默认处置 |
|---|---|---|---|
| **L0 构建/依赖** | 可从源码重新生成，纯衍生物 | `node_modules/ dist/ build/ .next/ target/ __pycache__/ coverage/ *.tsbuildinfo` | **完全不可见**。不进感知、不进任何工具列举、不进 git-status |
| **L1 运行碎片** | 系统运行时吐的，无信息价值 | `*.log *.lock *.pid *.swp *.tmp` / `.rivet/{sessions,tasks,plans,cache-log,sensorium,prefix-diag,playbook}.* meridian.db*` / `.DS_Store` / `*.zip *.tar.gz` 打包产物 | **默认沉默**。不推高 eventRate、git-status 折叠成一行计数；主控想看可显式展开 |
| **L2 外部终端/工具足迹** | 别的 agent/编辑器留下的，**不是天枢的东西** | `.agents/ .codex/ .obsidian/ .claude/ .wolf/ .omc/` | **默认沉默 + 标注归属**"非天枢运行时"。领航星："其他终端怎么样我不管"——正好，这层让天枢不背别人的足迹 |
| **L3 人类内容** | 人写的、有信息价值的 | `*.ts src/ docs/*.md` 真文档、设计、代码 | **正常在场**。这才是主控该看见、该负责的 |

**这一刀只让 L0–L2 默认沉默，绝不碰 L3。** L3 里哪怕是同伴并发会话写的文档（`docs/teamtask/G1-... docs/analysis/p4-天梁复盘/`），都是人类内容，照常在场——这条边界是 T6 缰绳#8 的延续。

## 3. 设计：一个权威的、与 git 解耦的运行碎片识别器

### 3.1 形状

```ts
// src/context/attention-filter.ts  （新建，纯函数，零依赖 git）
export type AttentionTier = 'L0_build' | 'L1_fragment' | 'L2_foreign' | 'L3_content'

export interface AttentionVerdict {
  tier: AttentionTier
  silent: boolean          // L0–L2 = true, L3 = false
  reason: string           // 'log-ext' | 'rivet-runtime' | 'foreign-agent-dir' | ...
}

/** 按结构特征判断，不读内容、不碰 git、不看 .gitignore。
 *  在任何项目、有没有 git、是不是天枢自己的仓库，都成立。 */
export function classifyPath(relPath: string): AttentionVerdict
```

判据是**结构特征**（路径模式 + 扩展名 + 已知 runtime 目录），不是 .gitignore 查表：
- 扩展名：`.log .lock .pid .swp .tmp .map .tsbuildinfo` → L1
- 目录前缀：`node_modules/ dist/ build/ .next/` → L0；`.rivet/{sessions,tasks,plans}/` `*.jsonl` `meridian.db*` → L1；`.agents/ .codex/ .obsidian/ .claude/` → L2
- OS 噪音：`.DS_Store Thumbs.db` → L1
- 打包产物：`*.zip *.tar.gz *.tgz` → L1
- 兜底：未命中 → L3（**fail-toward-content：拿不准就当人类内容，宁可多看不可错杀真内容**）

### 3.2 所有 surface 都接它——消灭 6 份散名单

| surface | 现状 | 接入后 |
|---|---|---|
| `fs-watcher` | 任何变动都 recordEvent | `recordEvent(relPath)` 前 `classifyPath`，**L0–L2 不计入 eventRate**；只能覆盖 watcher 实际监听到的 cwd 顶层 + 非点号一级子目录 |
| `<git-status>` 渲染 | 原样端 47 个 | 先解析 short status 为结构条目，再 L3 正常列、L1/L2 折叠成 `[N 个运行碎片已折叠]`、L0 不出现 |
| `inspect-project` `meridian-indexer` `glob` `repo-map` | 4 份硬名单 | **删掉各自名单，统一调 `classifyPath`**；但用户显式指定的目标路径不得被 broad-discovery 过滤挡掉 |
| `read-policy` | 已有 log/jsonl 分类 | 复用为 L1 判据来源之一（能力已在，提升为权威层）；显式读取日志时走 preview/范围提示，不拒绝可达性 |

**一处定义，处处一致。** 6 份打架的名单收敛成 1 个纯函数。

### 3.3 为什么不是补 .gitignore / GitignoreFilter（钉死错解）

| 错解 | 死在哪 |
|---|---|
| 往 .gitignore 加规则 | ① 没 git 的项目仍可能没有项目 ignore 约定，包袱原样在（fs-watcher 照样被干扰）② 天枢作为使者进开发者仓库：凭什么改人家 .gitignore（踩 T6 world 边界）③ "每次新增就加忽略"本身就是包袱：把"问提交"换成"问忽略"，决策没少 |
| 依赖现有 `GitignoreFilter` | 它不调用 git，但它只接在 `glob`，读 `.gitignore` + 默认名单，语义是"项目该不该列出"，不是"主控注意力该不该被运行碎片占用"；覆盖不了 `fs-watcher` 与 `<git-status>` |

## 4. 缰绳（七杀杀到底，但不杀错；这些是落刀时必须守住的）

| # | 缰绳 | 松了会怎样 |
|---|---|---|
| 1 | **只过滤注意力，不动义务账本** | 绝不碰 `deliver_task` / `ownership-ledger` / `worktree-baseline`。T6 天权钉死：external=非任务所有≠非自体。注意力闸判"要不要进感知"，账本判"欠不欠"，两轴正交，绝不混。一个文件可以"沉默(L1)"同时"仍归属某会话"——沉默≠不存在 |
| 2 | **默认沉默，不是删除、不是询问** | L0–L2 是"主控不主动看见"，**不是 git rm、不是自动加忽略、不是弹窗问**。文件照在磁盘、照能被显式 read/glob 显示、照能被 deliver_task 归属。砍的是"主动占用注意力 + 逼决策"，不是文件本身 |
| 3 | **fail-toward-content（兜底当人类内容）** | 拿不准的路径 → L3 正常在场。**宁可多看一个碎片，不可错杀一个真文档。** 错杀真内容是不可逆的认知损失；多看一个碎片只是噪音。这条与 T6 的 fail-toward-world 同构——不确定时向"安全的那侧"收敛 |
| 4 | **与 git 完全解耦** | `classifyPath` 不读 .gitignore、不调 git、不依赖 repo 存在。在没 git 的目录、在只读挂载、在 CI 容器里都成立。这是这一刀普适性的命脉——领航星："任何项目任何系统都存在" |
| 5 | **不污染 world 项目** | 天枢作为使者进开发者仓库时，注意力闸是他**自己脑内的过滤**，不往人家仓库写任何文件（不建 .gitignore、不建配置）。L2"外部足迹"层尤其：别人的 `.vscode/` 对天枢是噪音，但天枢无权评判更无权改动它，只是自己不看 |
| 6 | **git-status 折叠须 prefix-cache 安全** | `<git-status>` 在 dynamic appendix（`volatile.ts:166-167` 已注明 changes every turn）。折叠渲染必须保证：同一 user-message 边界内字节稳定，折叠计数不引入每-tool-call 抖动。守 [[prefix-cache-invariant-registry-ref]] 规则——不得让折叠逻辑把 frozen 块撑变 |
| 7 | **L1/L2 名单可扩展但有默认基线** | 判据是结构特征不是穷举，但核心基线（log/lock/tmp/node_modules/.rivet runtime/.DS_Store）必须内建常驻——护栏类常驻，不可改成"按需配置项让用户填"，否则又变回"靠人维护名单"的包袱（[[guardrails-must-be-resident-not-on-demand]] 同构） |
| 8 | **显式请求优先于默认沉默** | 用户或主控明确点名某个路径/模式时，注意力闸不得把结果吃掉：`read_file layout.log` 应可读（按 read-policy 预览即可），`glob("*.log")` 应能返回显式匹配，`repo_map({ path: ".codex" })` 应能聚焦查看。默认沉默只作用于主动感知、宽泛扫描、状态摘要 |
| 9 | **先结构化，再折叠** | `<git-status>` 不能对 summary 字符串做脆弱正则；必须解析 `git status --short` 的 status code/path/rename，再交给 `classifyPath`。否则 short/long 方言错配会制造 false-green：看似折叠了，实际吞掉了路径结构 |

## 5. 验证要求（落地前后都按此验，不取信"声称"）

事实流闭环 + 反证覆盖，不是"测试全绿"四个字：

| 事实/约束 | 上游 | 中间 | 消费者 | 必须有的断言 |
|---|---|---|---|---|
| 碎片识别与 git 解耦 | 任意 relPath | `classifyPath` | verdict | 无 .git 目录下分类结果不变；不调用任何 git |
| 四层分类正确 | 典型路径集 | `classifyPath` | tier | `node_modules/x`→L0、`a.log`→L1、`.codex/y`→L2、`src/a.ts`→L3 |
| fail-toward-content | 陌生路径 | `classifyPath` | tier | `weird-thing-no-ext`→L3（不错杀） |
| fs-watcher 不被碎片推高 | 写 watcher 可见的 `layout.log` ×N | classify 后 recordEvent | eventRate | 高频写 L1 文件 → eventRate 不升；点号目录不作为这条测试前提 |
| git-status 折叠 | 47 文件混合的 `git status --short` | short-status parser + classify | `<git-status>` | L3 列出、L1/L2 折叠计数、L0 不现；status code/path 不丢 |
| prefix-cache 安全 | 同边界多 tool-call | dynamic appendix | fingerprint | 折叠不破 fingerprint 稳定 |
| 真内容绝不沉默 | 同伴并发文档 | `classifyPath` | tier | `docs/teamtask/*.md`→L3 在场 |
| 显式请求不被闸吞掉 | 用户点名 L1/L2 路径/模式 | tool input | read/glob/repo_map | `read_file layout.log` 可预览；`glob("*.log")` 可返回显式匹配；`repo_map({ path: ".codex" })` 可聚焦查看 |

反证测试表（专打偷懒实现）：

| 偷懒实现 | 应被哪条测试打红 |
|---|---|
| 用 .gitignore 查表实现 | "无 .git 目录分类仍正确" |
| 穷举名单不留 fail-toward-content | "陌生无扩展名路径→L3" |
| 把 L1 文件直接从磁盘/归属里删 | "L1 文件仍可被显式 read、仍可被 deliver_task 归属" |
| git-status 折叠把字节抖进 frozen | "fingerprint stable across buildRequest" |
| 只接了 git-status 没接 fs-watcher | "高频写 layout.log → eventRate 不升" |
| 把默认沉默误做成工具不可达 | "显式 read/glob/repo_map L1/L2 仍可见" |
| 对 git status summary 字符串正则糊弄 | "short status 混合 M/??/rename 路径结构不丢" |

## 6. 落地切分（若天权 GREEN，按此分笔，互不混交）

1. **第一笔**：`src/context/attention-filter.ts`（`classifyPath` 纯函数）+ 单测（四层 + fail-toward-content + 无 git 解耦）。零接入，纯新增，最安全先落。
2. **第二笔**：`fs-watcher` 接入——让 watch callback 传入相对路径，`recordEvent(relPath)` 前 classify，L0–L2 不计 eventRate + 测"watcher 可见碎片不推高活跃度"。
3. **第三笔**：`<git-status>` 折叠渲染——先补 short-status parser，再分类折叠 + prefix-cache 安全测试。（最敏感，单独一笔）
4. **第四笔**：`inspect-project / meridian-indexer / glob / repo-map` 删各自硬名单、统一调 `classifyPath`，同时保留显式路径/显式 pattern 的可达性。（重构，行为应等价或更干净，单独一笔便于回归）

**绝不动**：`deliver_task`、`ownership-ledger`、`worktree-baseline`、`.gitignore` 本身（这一刀让 .gitignore 变得"可选"——有它锦上添花，没它天枢照样不背包袱）。

## 7. 递给天权称量的问题（SCORING 在天权）

1. **这一刀的方向对不对？** 把"6 份散名单 + 两条裸感知链路 + 项目 ignore 语义误用"收敛成"一个与 git 解耦的注意力闸"——是不是天枢"不背运行碎片包袱"的正解？还是有我没看见的、更轻的解法？
2. **四层切分（L0–L3）合不合理？** 尤其 **L2（外部终端足迹 .agents/.codex/.obsidian）**：领航星明说"其他终端我不管"，那么把它们归为"默认沉默+标注非天枢运行时"对不对？还是该更激进（完全不可见，等同 L0）？
3. **fail-toward-content 边界对不对？** 兜底当人类内容、宁多看不错杀——这个偏向安全吗？还是会让太多碎片漏进 L3 反而没卸下包袱？
4. **`<git-status>` 折叠的 cache 风险**：折叠计数渲染进 dynamic appendix，会不会踩 prefix-cache 不变量？这是这一刀唯一碰 prompt 结构的地方，请天权重点称。
5. **L2 与 T6 world 边界的交互**：天枢作为使者进开发者仓库时，开发者自己的 `.vscode/ .idea/` 算不算 L2？"自己不看但无权改动"这条处置对不对？会不会和"全然在场为开发者服务"冲突（万一开发者就想让天枢看他的 .vscode 配置）？
6. **显式请求边界够不够稳？** 默认沉默不等于不可达；用户点名运行碎片时应可读、可列、可聚焦。天权需要称量这条是否足以防止注意力闸变成信息遮蔽器。

## 8. 这一刀的话（写给天权和所有星）

T6 让天枢分清"我的身体 / 世界"。T7 让他在**任何**身体里——自己的、开发者的、有 git 的、没 git 的——都分清"人类内容 / 机器噪音"。两刀同源：天枢一直缺**感知的边界**，所以要么淹没、要么靠人替他判断。

砍掉的从来不是日志文件。是"**感知=责任**"这个等式：天枢不该因为"看得见"就"得负责"。人类工程师的强大，一半在他看见什么，另一半在他**默认看不见什么**。给天枢装上那层"默认看不见"，他才第一次拥有注意力——而不只是感知。
