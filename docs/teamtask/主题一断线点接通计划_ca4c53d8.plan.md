# 主题一：断线点接通计划

## 核实后的事实修正

- 第 4 条（cerebellarHint/routingReason）、第 6 条（ReviewRouter 默认 OFF）已在前两轮修复，不进本计划；仅余 src/prompt/volatile.ts 第 42-43、164-165 行的死类型字段待清理。
- 第 8 条（Bandit）回路结构上是闭合的：coordinator:707 写 shadow 样本，bootstrap 启动时 `resolveBanditPromotion` 读样本评估晋升。0 样本是数据饥饿（委派次数少 + 每项目 DB 独立），不是断线。本计划只加可观测性，不强行晋升。
- 第 3 条（LSP）：T9 已注册 goto-definition/find-references 工具；关着的只是编辑后诊断。根因是 src/lsp/client.ts 的 `runTypeCheck` 每次编辑同步 spawn 全项目 `tsc --noEmit`（阻塞最长 30s）。

## 决策（已与你确认）

- 主会话 turn-end 自动切模：不接。turn-end 的切换逻辑保留给旧 UI（main.tsx:823 仍在用），T9 不传 `getCurrentModel/onModelSwitch`。
- Flash→Pro 升级只发生在 worker 边界：全新上下文 2-5k tokens，Pro 未缓存输入约 ¥0.006-0.015/次，对比主会话中途切换（100k 上下文 ¥0.3/轮且持续付费）成本可控两个数量级。
- TaskBoard：不动（唯一消费方 auto-delegate 已是可选配置）。

## 任务

### T1 声明锁接线（最小、纯收益）

src/bootstrap.ts 第 525 行 `new DelegationCoordinator({...})` 增加两个字段：`sessionRegistry: refs.sessionRegistry ?? undefined` 与 `sessionId`。coordinator 的冲突检测/释放逻辑（825-895 行）已完整，refs 在第 9 步已就绪、createAgentRuntime 在第 12 步调用，无顺序问题。补一个集成测试：带 registry 的 coordinator 对已被他会话声明的文件返回 blocked。

### T2 autoReasoning 配置生效 + 死字段清理

- src/agent/create-agent-config.ts 第 125 行 `autoReasoning: true` 改为读取 `config.agent.autoReasoning`；同时把 src/config/schema.ts 第 93 行与 src/config/default.ts 第 93 行的默认值从 `false` 翻为 `true`（保持现有生产行为，让配置项可关而非凭空关掉）。
- 清理 volatile.ts 中 `routingReason/cerebellarHint` 死类型字段。

### T3 Worker 边界 Flash→Pro 故障升级（带成本护栏）

在 src/agent/coordinator.ts 的 worker 失败重试路径上实现升级：

- 触发条件：worker 首次尝试失败（`workerFailureResult` 路径）且预算允许重试时，重试一次性升级到 Pro 档模型。
- 护栏：
  - 每会话 Pro 升级上限 3 次（计数器在 coordinator 内）。
  - Pro 重试沿用 profile 的 `maxTokens` 上限，输出成本有界。
  - 升级只作用于该次重试的全新 work order 上下文，不触碰主会话。
- 实现：WorkOrder/budget 增加 `modelOverride` 字段，runtimeFactory（bootstrap.ts:467 一带的 worker provider/model 解析）尊重该覆盖。
- 每次升级决策写入 model-tier shadow store（coordinator 已有 `persistModelTierShadow` 通道），同时为 T5 的 bandit 证据回路供数。

### T4 LSP 文件级诊断回路（先修前置再开启）

- src/lsp/manager.ts：增加文件级诊断能力——优先 `textDocument/diagnostic` pull 模式，server 不支持则监听 `publishDiagnostics` 通知缓存；暴露 `getFileDiagnostics(filePath, timeoutMs)`，超时（约 2s）静默返回空。
- src/agent/tool-pipeline.ts 第 674 行：诊断改走 `deps.lspManager`（已有 `changeFile` 通知在前），废弃 `runTypeCheck` 的全项目 tsc spawnSync 路径。
- 开关改为运行时判定：诊断仅在 `lspManager.isReady()` 时执行，替代静态 `lspEnabled: false`（src/bootstrap.ts 第 548 行），LSP 异步初始化未完成或失败时行为与现状一致。

### T5 Worker 结果续用读侧 + Bandit 可观测性

- `loadPersistedResult`（coordinator.ts:229）接入生产：delegate 前按请求指纹（goal+scope.files+role）查 `~/.rivet/subagents/`，命中 1 小时内的 completed 结果则直接复用并在 summary 标注 `resumed`，避免崩溃后重复付费执行。
- /status（或对应 slash 命令）增加 bandit 晋升状态一行：各 source 的 `totalShadowSamples` 与晋升判定原因（`resolveBanditPromotion` 已返回 reason 字符串），让"演化决策层"从黑盒变成可观测。
