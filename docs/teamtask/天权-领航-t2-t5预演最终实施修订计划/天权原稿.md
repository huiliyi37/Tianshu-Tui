   ▍ 必须修正的 6 个点  
  
   1. `routing_shadow:{turn}` 会跨 session 覆盖  
  
    MeridianDb  的  p3_state  是：  
  
    ◇  kind   
    ◇  version   
    ◇  json   
    ◇ primary key =  (kind, version)   
  
   见  src/repo/meridian-db.ts:103  与  saveBanditState()   src/repo/meridian-db.ts:569 。  
  
   所以  routing_shadow:${turn}  不够。turn 每个 session 都会从小数开始，跨 session 会覆盖。  
  
   建议改成：  
  
  
   ┌── ts ──────────────────────────────────────────────────────────────────────────────────────────────────────────────────────────────────────────────────────────────────  
   │  routing_shadow:${sessionId}:${turn}:${timestamp}  
   └────────────────────────────────────────────────────────────────────────────────────────────────────────────────────────────────────────────────────────────────────────  
  
  
   或：  
  
  
   ┌── ts ──────────────────────────────────────────────────────────────────────────────────────────────────────────────────────────────────────────────────────────────────  
   │  routing_shadow:${objectiveHash}:${sessionId}:${turn}  
   └────────────────────────────────────────────────────────────────────────────────────────────────────────────────────────────────────────────────────────────────────────  
  
  
   P0 可以继续不加 DDL，但 key 必须天然 append-only。  
  
   ──────────────────────────────────────────────────────────────────────────────────────────────────────────────────────────────────────────────────────────────────────────  
  
   2. P0 不能注入真实 `onModelSwitch`  
  
   旧路由要 shadow，不要真切换。  
  
   当前危险点：  
  
    ◇  turn-end.ts:60-70 ：推荐模型不同且存在  onModelSwitch  就会调用。  
    ◇  tool-history-recorder.ts:61-63 ：trajectory health escalate 时会调用  onModelSwitch(proModel) 。  
  
   所以 P0 的实现应是：  
  
  
   ┌── ts ──────────────────────────────────────────────────────────────────────────────────────────────────────────────────────────────────────────────────────────────────  
   │  legacyRouterRecommendedModel = computeLegacyRecommendation(...)  
   │  actualModel = current configured model  
   │  // 不传 / 不调用 onModelSwitch  
   │  // 不让 turn-end / tool-history-recorder 的旧切换路径真实执行  
   └────────────────────────────────────────────────────────────────────────────────────────────────────────────────────────────────────────────────────────────────────────  
  
  
   验收门要写死：  
  
     │ 构造 legacy 推荐与 currentModel 不同，断言 `onModelSwitch` 调用次数为 0。  
  
   否则 P0 名义是 shadow，实际是行为变更。  
  
   ──────────────────────────────────────────────────────────────────────────────────────────────────────────────────────────────────────────────────────────────────────────  
  
   3. `TeamEpisodeRecorder` 当前拿不到可靠 `modelUsed`  
  
    DelegationCoordinator.delegateOrder()  返回了  selectedModel ：  
  
    ◇  src/agent/coordinator.ts:427-430   
  
   但  delegateBatch()  内部只把  run.results  push 到  allResults ：  
  
    ◇  src/agent/coordinator.ts:497-519   
  
   最终  CoordinatorRun  没有 per-worker 的  selectedModel  列表。也就是说， TeamEpisodeRecorder  现在无法可靠记录：  
  
  
   ┌── ts ──────────────────────────────────────────────────────────────────────────────────────────────────────────────────────────────────────────────────────────────────  
   │  modelUsed?: string[]  
   └────────────────────────────────────────────────────────────────────────────────────────────────────────────────────────────────────────────────────────────────────────  
  
  
   除非你改  CoordinatorRun  增加 per-order metadata。  
  
   P0 建议：  
  
    ◇ 先把  modelUsed  设为可选，不强求；  
    ◇ 或新增：  
  
  
   ┌── ts ──────────────────────────────────────────────────────────────────────────────────────────────────────────────────────────────────────────────────────────────────  
   │  interface CoordinatorRun {  
   │    workerModels?: Array<{ workOrderId: string; model: string }>  
   │  }  
   └────────────────────────────────────────────────────────────────────────────────────────────────────────────────────────────────────────────────────────────────────────  
  
  
   但这已经是 coordinator 数据面的变更，要单独测试。  
  
   ──────────────────────────────────────────────────────────────────────────────────────────────────────────────────────────────────────────────────────────────────────────  
  
   4. “TeamEpisode” 跨 wave 问题没解决  
  
   当前  runTeamSkeleton()  每次只派一个 wave：  
  
    ◇  src/agent/team-orchestrator.ts:231   
    ◇  src/agent/team-orchestrator.ts:275   
  
   多 wave 是靠用户/主控后续用  fromWave  再调用。  
  
   所以如果  TeamEpisodeRecorder.startEpisode()  /  closeEpisode()  放在单次  runTeamSkeleton()  内，它记录到的不是完整 episode，而是一个 wave fragment。  
  
   这里必须二选一：  
  
   安全版 P0：改名为 `TeamWaveTelemetryRecorder`  
  
   只记录单次 team_orchestrate 调用：  
  
  
   ┌── ts ──────────────────────────────────────────────────────────────────────────────────────────────────────────────────────────────────────────────────────────────────  
   │  TeamWaveTelemetry {  
   │    objectiveHash  
   │    fromWave  
   │    waveId  
   │    plannedTasks  
   │    results  
   │  }  
   └────────────────────────────────────────────────────────────────────────────────────────────────────────────────────────────────────────────────────────────────────────  
  
  
   完整版 P0：引入 `episodeId`  
  
   跨  fromWave  持续 upsert：  
  
  
   ┌── ts ──────────────────────────────────────────────────────────────────────────────────────────────────────────────────────────────────────────────────────────────────  
   │  team_episode:${episodeId}  
   └────────────────────────────────────────────────────────────────────────────────────────────────────────────────────────────────────────────────────────────────────────  
  
  
   每次 wave 完成 append，最后一波 close。  
  
   验收门：  
  
     │ 一个 2-wave plan，先 `fromWave=0` 再 `fromWave=1`，最终应是同一个 episode 两个 waves，不是两个孤立 episode。  
  
   如果不做这个门，后续 reward 会把“一个任务的两个阶段”误当成两个独立样本。  
  
   ──────────────────────────────────────────────────────────────────────────────────────────────────────────────────────────────────────────────────────────────────────────  
  
   5. `actualFiles` 不能等同 worker 自报  
  
   文档已经意识到这一点，但 P0 计划里还不够硬。  
  
   当前可见路径里  CoordinatorRun.results  包含  WorkerResult.changedFiles ，但需要确认它是否来自真实 worktree diff，不能默认信 worker 自报。  
  
   建议字段改成：  
  
  
   ┌── ts ──────────────────────────────────────────────────────────────────────────────────────────────────────────────────────────────────────────────────────────────────  
   │  reportedChangedFiles?: string[]  
   │  observedChangedFiles?: string[]  
   │  changedFilesSource: 'worker_result' | 'worktree_diff' | 'unknown'  
   └────────────────────────────────────────────────────────────────────────────────────────────────────────────────────────────────────────────────────────────────────────  
  
  
   P0 如果拿不到 worktree diff，就只能写：  
  
  
   ┌── ts ──────────────────────────────────────────────────────────────────────────────────────────────────────────────────────────────────────────────────────────────────  
   │  changedFilesSource: 'worker_result'  
   └────────────────────────────────────────────────────────────────────────────────────────────────────────────────────────────────────────────────────────────────────────  
  
  
   不要把它命名为  actualFiles 。  
  
   否则后续  TeamScopeHealth  会建立在不可靠观测上，形成 false-green。  
  
   ──────────────────────────────────────────────────────────────────────────────────────────────────────────────────────────────────────────────────────────────────────────  
  
   6. reward 公式必须归一化，并明确 false-green 权重  
  
   现在文档写：  
  
  
 ▍ Rivet  
  
   ┌── text ────────────────────────────────────────────────────────────────────────────────────────────────────────────────────────────────────────────────────────────────  
   │  reward = review_pass + verification_pass  
   │           - conflict_count - rework_count  
   │           - cost_over_budget - latency_surprisal  
   │           - false_green_penalty  
   └────────────────────────────────────────────────────────────────────────────────────────────────────────────────────────────────────────────────────────────────────────  
  
  
   方向对，但工程上要归一化，否则不同量纲混在一起。  
  
   建议写成：  
  
  
   ┌── ts ──────────────────────────────────────────────────────────────────────────────────────────────────────────────────────────────────────────────────────────────────  
   │  reward =  
   │    + 0.30 * reviewPass  
   │    + 0.30 * verificationPass  
   │    - 0.15 * normalizedConflict  
   │    - 0.15 * normalizedRework  
   │    - 0.10 * normalizedCostOverBudget  
   │    - 0.10 * normalizedLatencySurprisal  
   │    - 0.60 * falseGreen  
   └────────────────────────────────────────────────────────────────────────────────────────────────────────────────────────────────────────────────────────────────────────  
  
  
   关键不是具体数值，而是硬约束：  
  
  
   ┌── ts ──────────────────────────────────────────────────────────────────────────────────────────────────────────────────────────────────────────────────────────────────  
   │  falseGreenPenalty > maxCostPenalty + maxLatencyPenalty  
   └────────────────────────────────────────────────────────────────────────────────────────────────────────────────────────────────────────────────────────────────────────  
  
  
   也就是瑶光门：  
  
     │ 省钱永远不能覆盖 false-green 风险。  
  
   ──────────────────────────────────────────────────────────────────────────────────────────────────────────────────────────────────────────────────────────────────────────
