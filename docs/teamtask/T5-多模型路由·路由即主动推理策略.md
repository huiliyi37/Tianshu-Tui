## 0. 一句话

天枢路由弱，不是缺路由器——是**五个路由器全在休眠，断在注入点上**；更深的弱是**路由被当成独立子系统，没接进自由能引擎**。全领域在造独立学习路由器；天枢的边界是别人造不出的那一条：**选模型就是一次 EFE 驱动的策略选择**——成本进 G(π) 的 pragmatic 项，难度来自已经在跑的 Sensorium，学习落 MeridianDb。补强的最高杠杆是接线 + 把路由联合进具身自由能运行时，不是从零写 RouteLLM。

## 2. 外部前沿（2026 收敛点）

整个领域收敛到一句话：**估难度 → 路由到能过线的最便宜模型 → 从结果学**。

- **CASTER**（arxiv 2601.19793，2026-01）：双信号路由器=语义嵌入(1536d→128d)+结构元特征(6d：agent 角色 one-hot + 上下文长度 + 高风险关键词)，融合输出 `p(Strong|x)`，阈值 τ 分强/弱模型。三阶段自学：冷启动合成种子→教师 LLM 对抗轨迹→**负反馈重标记**（弱模型失败则强制标 Strong=1.0，弱模型成功推向 0.0 鼓励省钱）。on-policy 采集边界样本（random 探索会让强模型轻解易题、污染数据偏保守贵）。报告省 72.4% 成本、匹配强模型成功率。
- **cost-aware contrastive routing**（2508.12491）：prompt-specific 上下文感知的成本路由，避免昂贵的模型 profiling。
- **performance predictor**（2401.13979）：轻量模型不执行就估每个 LLM 的表现，再 cost-aware 解码选最优。
- **budget-controllable routing**（2502.20576）：预算与性能可控的多 LLM 路由。
- **query decomposition + historical matching**（2605.25558）：按分解子任务 + 历史匹配路由，避开"记忆陷阱"。

**关键观察**：这些全是**独立**的学习路由器——单独网络估难度、单独 cost 公式。这正是天枢可以超越的地方。

## 3. 联合洞察：路由即 EFE 策略——天枢独有的边界

> **选模型，就是一次 EFE 驱动的策略选择。** 便宜模型 = 低成本但高预期 surprise；强模型 = 高成本、低预期 surprise。这正是 `selectPolicy` 已经在算的 pragmatic（成本）vs epistemic（降不确定性）权衡。

CASTER 用独立模块做的每一件事，天枢都已有对应部件，只需接上：

| CASTER 用独立模块做的 | 天枢已有、只需接上的 | 行号 |
|---|---|---|
| 双信号网络估任务难度（语义+结构） | **Sensorium 就是双信号**：complexity=语义复杂度，pressure=结构压力。自由能引擎每回合在算"这有多难/多不确定"——不必造 CASTER 的网络 | `sensorium.ts` 6 维 |
| 难度→强/弱模型阈值映射 | **EFE/selectPolicy**：选模型是选策略，模型作为 policy 候选，成本进 G(π) pragmatic 项 | `policy-selection.ts:69` |
| 负反馈重标记自学 | **AdaptiveRouter passRate + MeridianDb**：落一套底座，surprise 驱动（失败=高 surprise→下次升级，正是 CASTER 第 9 条） | `adaptive-routing.ts:19` + `meridian-db.ts` |
| 多 agent 步级路由（team） | **coordinator.selectModelForTask 已活**：把星域 authority 从"只改 prompt"升级成"真分模型" | `coordinator.ts:137-157` |

**为什么这是天枢独有的边界**：CASTER 要冷启动训练一个网络去估难度；天枢的难度估计每回合已经在 Sensorium 里跑着。全领域造独立路由器，因为他们没有具身自由能运行时可以在其中路由。**选模型的决策和选工具是同一套机器（EFE），成本只是 G(π) 里的另一项。** 这是把路由联合进昨晚团队设计的 Embodied Free Energy Runtime，不是螺栓上一个 RouteLLM 克隆。

## 4. 联合架构

```
Sensorium(complexity/pressure/confidence)  ──┐  难度=epistemic 需求
prediction-error rate                        ├─→ EFE Kernel: G(π)
任务 token 预估 + 模型单价 ───────────────────┤      = epistemic + pragmatic(成本) + risk
ProviderHealth(hot/warm/cold)  ──────────────┘  健康=可用性约束
                                                      │
                  模型作为 policy 候选 {flash, pro, opus...}
                                                      ▼
                              Policy Arbiter（T4 天璇设计的 L0-L4）
                                  L1 shadow: 记录 EFE 推荐 vs 实际
                                  L2 assistive: 低风险自动选便宜模型
                                  L3 gated: 高置信下自动升级/降级
                                                      ▼
                              选定模型 → 执行 → 结果回写
                                                      │
                  surprise 高(失败) → MeridianDb 重标记 → 下次该任务类升级
                  surprise 低(便宜模型成功) → 强化省钱路径
```

**成本作为 G(π) 新项（真空白要建）**：
```ts
G(π_model) = -(epistemic·难度降低 - pragmatic·成本 - risk·失败代价)
// 便宜模型: 低 pragmatic 成本, 但高难度任务上 epistemic 降低少 + risk 高
// 强模型: 高 pragmatic 成本, 但 epistemic 降低多 + risk 低
// EFE 自动在"够用就省、不够就升"之间选 —— 不需要独立 τ 阈值
```

**team authority→模型 tier（真空白要建）**：
- 天权（审查/verifier）→ 强模型（审查不能省，false-green 代价最高）
- cheap 摘要/低风险 patch → flash
- 把 `default.ts` 全指 cheap-flash 的 routing 表，改为 authority 驱动的 tier 映射
- prompt 戏服 → 真多模型视角

## 6. 守缰绳

1. **不动自由能引擎核心**：路由做 `computeEFE` 的新消费者（加 pragmatic 成本项 + 模型作为 policy 候选），不改其既有 epistemic/pragmatic 语义。
2. **coordinator 是活前沿（30 commits 到 06-08）**：W4 改 routing 表要谨慎，不动其数据模型，只升级 authority→tier 映射。
3. **routing 旧资产是考古**：W0 激活 turn-end/Flash→Pro 时，确认它们的逻辑仍与当前 loop 兼容（冻结半月，消费端可能漂移）——实施前 grep 到行号，别凭本文推断。
4. **成本路由不能牺牲正确性**：审查/verifier 路径（天权）绝不为省钱降级——false-green 代价远高于模型差价。成本是 pragmatic 项，但 risk 项要压住"省错地方"。
5. **不破 prefix cache**：模型切换走 API 参数 / provider 重建，学习状态落 MeridianDb，不进 stable volatile。
6. **修正 memory**：Ice Mirror 不存在，删除该推断源。

### 8.1 W0 从「接线激活」收紧为「接线可观测，先 shadow，不自动 switch」

§5 的 W0 写「注入 config → 激活 turn-end 路由 + Flash→Pro 升级」。我建议改为：**接线让它可观测，先 shadow，不立刻让旧路由器自动切换**。

原因：旧路由资产是 5 月考古、冻结半月（§1.2 自证），直接激活 turn-end / Flash→Pro 自动切换，风险是「逻辑能跑，但语义漂移」——而你没有对照期察觉漂了多远，等发现时已经切错很多次。先 shadow 一个对照窗口，确认推荐 vs 实际的差距，再开自动切换。

落地为 `ModelRoutingShadowRecorder`：

```ts
interface ModelRoutingShadowEvent {
  turn: number
  objectiveHash: string
  currentModel: string
  efeRecommendedModel?: string        // EFE/policy-selection 推荐
  legacyRouterRecommendedModel?: string  // 旧 turn-end/Flash→Pro 推荐
  selectedByHumanOrConfig: string     // 实际生效的
  sensorium: { complexity: number; pressure: number; confidence: number; stability: number }
  reason: string
}
```

这一步让 W2 的成本项、W3 的自动降级，都有「推荐 vs 实际」真值表可对照——这是后面每一步可归因的地基。

### 8.2 reward 不要只用 success/fail，且 false-green 必须压住成本

W2/W3 的成本项落地时，reward 公式建议：

```
reward = + review_pass + verification_pass
         - conflict_count - rework_count
         - cost_over_budget - latency_surprisal
         - false_green_penalty
```

守瑶光的门，我用公式替她钉死：`false_green_penalty` 必须是压得住 `cost_over_budget` 的那一项。§6 守缰绳第 4 条「审查/verifier 路径绝不为省钱降级」由此从原则变成可计算约束——成本是 pragmatic 项，但 false-green 是 risk 项，**risk 永远先于 pragmatic**。天权配强模型这条不进 bandit、不受成本项影响，是硬规则。

### 8.3 顺序锚点：T5 是 T2-03 训练场的第一个高价值消费者

T5 与 T2-03 不是两条并行功能线。正确主线是：**先让 team 产生可学习的 episode（T2-03 的 `TeamEpisodeRecorder`），再让模型路由从这些 episode 里学会什么任务用谁、什么风险升档、什么场景可省**。所以 T5 的 W2 成本项、W3 自学，依赖 T2-03 先产出干净标签。下一份落地计划是二者合一的 `T5-01×T2-03-01·路由影子层与TeamEpisode训练底座.md`，不分开写。
