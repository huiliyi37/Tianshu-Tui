# T2-02·空转学习器接通活决策点 v2（天权修订版）

> 日期：2026-06-07
> 框架：能力最大化，不计成本（天枢标准——有用就复用，没用就丢着；成本不进判断）
> 考古来源：`docs/superpowers/analysis/2026-06-07-repo-intelligence-archaeology.md`
> 审查修订：采纳天权审查——四个 P3 组件确有空转，但不能一次性「接管」活路径；应分为 telemetry/shadow、受控建议、再到执行接管。尤其 PlanCache/JIT 不能自动执行未批准计划，Nightcrawler 必须先与 delegate-task 判重。
> 关联：[[meridian-db-is-cross-session-substrate]]、T2-01（同源——都是「把空转的学习能力接到活着的执行点」）

## 0. 一句话

P3 子系统（`p3-integration.ts`，8 组件门面）接进了 loop，但内部裂成两半：投机预读 + 错题本是活的，而 **LinUCB bandit、PlanCache、AgentJIT、Nightcrawler 四个完整造好的学习/复用组件主要空转**——它们都接通了「记录/构造」那一头，没接「咨询/复用」那一头。

本任务目标不是让它们立即接管主循环，而是把它们接到**活决策点的可观测旁路**：先 telemetry/shadow，确认语义正确，再变成建议，最后才允许局部执行。

---

## 1. 能力定位

四个空转组件各自代表 harness 的真实能力维度，但接线风险不同：

| 组件 | 代表能力 | 本该接到的活决策点 | 审查修订后的接线姿态 |
|---|---|---|---|
| **LinUCB bandit** | 在线 RL 选 reasoning effort / verbosity | `auto-reasoning` / `tool-execution` effort 决策 | 先 shadow 推荐 + 记录结果；不能直接替换规则 |
| **PlanCache** | 计划/工具序列记忆 | plan approval / task start / plan context | 先记录已批准或已成功执行的计划，不记录未批准草稿 |
| **AgentJIT** | 高频计划模板编译复用 | 经批准的重复性安全步骤 | 只能人工确认或白名单只读；不能自动执行 write/edit |
| **Nightcrawler** | 后台任务调度 | delegate / background research | 先判重；大概率是被 delegate/coordinator 覆盖的旧调度壳 |

它们不是「设计得奇怪所以没做完」，是「做完了但最后一根线没接」。但「接」不等于「立即接管」：这些组件一旦接错，会影响模型 effort、计划执行权限、后台并发与 prefix cache 结构，必须先按语义分层。

## 2. 证据（grep 锚点）

### 2.1 P3 门面接进 loop，execute 只服务投机预读

- `src/agent/loop.ts:278-292` `createP3Integration({ execute: ... })` —— 只传了投机预读用的 `execute`，且限 SAFE_TOOLS（`read_file`/`grep`/`glob`/`list_dir`）。
- `src/agent/p3-integration.ts:36/43/53` —— `backgroundExecute`、`jitExecute` 未传，fallback 到 `async () => ''` 或 `{ result: '', isError: false }`。

### 2.2 LinUCB bandit 完整造好、零咨询

- `src/agent/p3-integration.ts:46-50` 构造：6 维上下文、四臂（`flash`/`pro`/`concise`/`verbose`）。
- `src/agent/p3-integration.ts:120-127` `recommendAction` / `rewardAction` —— 生产零调用。
- 实际 effort 决策由固定启发式接管：`src/agent/auto-reasoning.ts:10-21` `selectReasoningEffort(input)` 看输入文本；`src/agent/tool-execution.ts` 再用错误率 intervention 调整。RL 学习器从不被问、从不被奖励。

审查补充：当前 bandit 的 arm 集合并不全是 reasoning effort：`flash/pro` 是模型 tier，`concise/verbose` 是输出风格，和 `ReasoningEffort = off/low/medium/high/max` 不同维度。不能把这四个 arm 直接拿来「接管 effort」。必须拆成独立 bandit 或重定义 arms。

### 2.3 PlanCache + AgentJIT 死链成立，但 plan_submit 不是 PlanCache 的天然记录点

- `src/agent/p3-integration.ts:94-100` `recordPlan` / `lookupPlan` —— 生产零调用。
- `src/agent/p3-integration.ts:130-134` `tryJIT` 依赖 `planCache.lookup` → cache 空时恒 null。
- `src/agent/agent-jit.ts:116-133` 的 `tryJIT(template)` 要 template `hitCount >= compileThreshold` 才编译执行。
- `src/tools/plan-submit.ts:93` 只是把计划 Markdown 写到 `.rivet/plans/{slug}.md`；它没有结构化 `PlanStep[]`。
- `src/plan/plan-store.ts` 管理 submitted/approved/rejected/executed 状态；批准后的计划会作为执行上下文，不等于可自动 replay 的工具步骤。

审查补充：把 `plan_submit` 成功直接写入 `PlanCache` 是错误接线。`plan_submit` 写的是设计文档草稿，尚未获用户批准，也没有结构化工具步骤。PlanCache 应记录**已批准计划骨架**或**已成功执行的工具序列**，而不是未批准 Markdown。

### 2.4 Nightcrawler 空转，但可能被 delegate/coordinator 取代

- `src/agent/p3-integration.ts:42-44` 构造时 `backgroundExecute` 未传 → 空执行器。
- `submitBackground` 生产零调用。
- `src/agent/nightcrawler.ts` 是进程内 queue + timeout + max concurrent 调度器。
- 当前项目已有 `delegate_task` / `delegate_batch` / `DelegationCoordinator` / `WorkerSession` 这条真实后台/worker 路径。

审查补充：Nightcrawler 不应直接接 delegate 执行器。它没有 worktree ownership、worker transcript、profile/tool 权限、B1 归属与 verification gate 语义；delegate/coordinator 已覆盖更完整的后台 agent 能力。Nightcrawler 更可能是「被取代的旧调度壳」或只适合包裹非 agent 的低风险后台任务。

## 3. 联合方案：四条线分别接，不做一刀切接管

### 接线 1 — LinUCB：从 shadow 推荐开始，重定义 action 空间

当前固定规则有两层：

1. `selectReasoningEffort(input, floor)`：按用户输入启发式选择 base effort。
2. `adjustReasoningEffort(effort, interventionLevel)`：按错误率/预测误差把 effort 往上调。

LinUCB 要接到这里，必须先明确 action 空间。推荐拆成两个独立 bandit：

| Bandit | Arms | 决策点 | 不做什么 |
|---|---|---|---|
| `reasoning_effort_bandit` | `off/low/medium/high/max` 或 `delta:-1/0/+1` | base effort 与 intervention 之间 | 不选模型 tier |
| `style_bandit` | `concise/verbose` 等 | 输出风格/verbosity hint | 不影响 API reasoning_effort |

`flash/pro` 不属于 effort；若要学习模型 tier，应接 provider routing / model switch，而不是 `auto-reasoning`。

实施顺序：

1. **Shadow**：构造上下文 `[taskComplexity, errorRate, turnDepth, fileCount, isRepeat, timeOfDay]`，调用 bandit 只记录推荐，不改变真实 effort。
2. **Reward 定义**：不要用「用户接受/拒绝」单一信号，因为 effort 通常没有显式接受。可用复合结果：工具成功率、是否触发 repair、是否进入 doom loop、是否被用户纠正、token 成本是否异常。
3. **受控建议**：当 bandit 与规则连续一致或历史置信足够时，允许 bandit 调整 ±1 档；`reasoningFloor` 仍然强制生效。
4. **持久化**：利用 `LinUCBBandit.serialize()/deserialize()`，落 MeridianDb KV；DB 不可用 no-op。

不要在 v1 直接让 bandit 替换现有启发式。现有规则是已承重路径，bandit 是学习补偿层。

### 接线 2 — PlanCache：记录「已执行成功的工具序列」，不是 `plan_submit` 草稿

PlanCache 当前类型是 `PlanStep { tool, target, args }[]`，它适合记录工具序列，不适合直接吞 Markdown 计划。正确来源优先级：

1. **首选：成功完成的任务轨迹**
   - 从 `TrajectoryRecorder` / tool history / TaskLedger 提取成功工具序列。
   - 过滤掉失败工具、审批被拒绝工具、危险工具、环境依赖过强工具。
   - 任务闭环成功后记录：`p3.recordPlan(taskDescription, steps)`。

2. **次选：已批准 plan 的结构化步骤**
   - 只有 `/plan-approve` 后才可考虑。
   - 需要从计划 Markdown 中解析明确工具步骤；无法结构化时只记录关键词，不生成可执行 steps。

3. **禁止：`plan_submit` 成功即记录**
   - 这是未批准草稿。
   - 没有结构化 `PlanStep[]`。
   - 直接记录会把未验证计划污染成「可复用经验」。

PlanCache 的 lookup 不应自动修改 prompt 大段内容。v1 只作为 tool-result nudge / execution context 的短建议，例如：「曾有相似已成功任务，建议检查这些文件/步骤」。大段计划注入需要另审 prefix cache 影响。

### 接线 3 — AgentJIT：只允许安全重放，不自动执行写操作

AgentJIT 的 `execute()` 会按模板逐步调用工具。一旦接到真实 `toolRegistry.execute`，它具备自动执行能力，风险高于普通 plan reuse。

必须加 gate：

| 工具类别 | JIT v1 行为 |
|---|---|
| `read_file` / `grep` / `glob` / `repo_graph` / `related_tests` | 可自动只读重放 |
| `run_tests` / `bash` | 需要命令 allowlist 或用户确认 |
| `edit_file` / `write_file` / `hash_edit` / `apply_patch` | 默认禁止自动执行，只能生成建议或待审批 step |
| `deliver_task` / git commit | 禁止 JIT 自动调用 |

JIT 的第一落点应是「生成可复用步骤建议」或「只读 warmup」，不是「直接执行整个重复任务」。只有当模板命中次数高、最近成功、所有步骤只读或已审批，才允许自动执行。

### 接线 4 — Nightcrawler：先判定，默认不接 agent delegate

Nightcrawler 与 delegate/coordinator 的能力重叠很大，但 Nightcrawler 少了关键工程语义：

- worker profile / tool permission；
- 独立 transcript / session 记录；
- worktree ownership；
- verification / delivery gate；
- coordinator progress 与 result aggregation；
- crash/timeout 的结构化 WorkerResult。

因此默认结论：**Nightcrawler 不接 delegate-task 作为第二套后台 agent**。两种可保留路径：

1. **封存**：判定被 delegate/coordinator 取代，保持不动，文档标明旧能力。
2. **降级为低风险 background job scheduler**：只跑非 agent 的后台任务，如 telemetry flush、indexing、repo analysis、cache warmup；不执行写工具，不创建 worker。

若未来要接 agent，必须直接复用 `DelegationCoordinator`，不要把 coordinator 包进 Nightcrawler 再包一层调度。

## 4. 持久化落点

T2-02 也应落 MeridianDb，但要分层：

| 状态 | 建议存储 |
|---|---|
| Bandit weights | `p3_state(kind='bandit:reasoning_effort', version, json)` 或专表 |
| PlanCache templates | `p3_state(kind='plan_cache', version, json)` 或 `plan_templates` 表 |
| AgentJIT compiled plans | v1 不持久化 compiled code，只持久化 template；compiled 可启动后再生成 |
| Nightcrawler queue | v1 不持久化，除非确认为低风险后台 job scheduler |

不要写入 `.rivet/knowledge`；这些是运行时学习状态，不是 canonical memory。

## 5. 影响面与边界

- **接线 1/2 是确定方向**，但第一阶段是 shadow/记录，不是接管。
- **接线 3 必须受权限 gate 限制**，不可自动重放写操作。
- **接线 4 需先判定**；当前倾向封存或降级为非 agent 后台任务。
- Effort 决策走 API 参数（B 臂，零 prefix-cache 代价）。
- Plan reuse 若进入 prompt，必须短、稀疏、事件触发；大段注入另开设计。
- 与 T2-01 同源：两个任务都是「把空转学习能力接到活执行点 + 落 MeridianDb 跨 session」。可并行，但共享 P3/MeridianDb 迁移，需避免 schema 冲突。

## 6. 推荐实施顺序

### P0：补观测，不改行为

- 增加 bandit shadow recommendation telemetry。
- 提取成功工具序列，dry-run 生成 PlanStep[]，但不写入可执行 cache。
- Nightcrawler 与 delegate/coordinator 做能力对照，给出封存/降级结论。

### P1：持久化运行时学习状态

- MeridianDb 增 `p3_state` KV 或专表。
- 保存/加载 bandit、PlanCache。
- DB unavailable no-op。

### P2：PlanCache 只记录已成功闭环的工具序列

- 任务闭环成功后记录 PlanCache。
- lookup 命中只输出短建议，不自动执行。
- 对文件变更调用 `invalidatePlanCache` 与 `jit.invalidateByPath`。

### P3：Bandit 受控影响 effort

- bandit 只允许 ±1 档调整。
- `reasoningFloor` 和 intervention escalation 仍优先。
- reward 信号来自任务结果与错误轨迹。

### P4：AgentJIT 只读重放

- 只读工具白名单自动执行。
- 写操作生成审批建议，不自动执行。
- 测试 false-positive 与 rollback path。

### P5：Nightcrawler 封存或降级

- 若封存：标注为被 delegate/coordinator 取代。
- 若降级：只服务 indexing/cache/telemetry 等非 agent 后台 job。

## 7. 验收

| 层 | 验收项 |
|---|---|
| LinUCB shadow | `recommendAction` 有真实调用，但 v1 不改变 effort；telemetry 可见规则选择 vs bandit 推荐 |
| Reward | `rewardAction` 由明确结果信号触发，不用空泛 accepted；doom/repair/成功率等信号可复核 |
| Action space | effort bandit 不混用 `flash/pro/concise/verbose`；模型 tier 与 style 另分通道 |
| PlanCache | 不记录未批准 `plan_submit` 草稿；只记录已成功闭环或已批准且结构化的计划 |
| JIT gate | 只读工具可自动重放；write/edit/bash/deliver_task 默认禁止或需审批 |
| Nightcrawler | 给出「封存/降级/接入 coordinator」之一的明确结论；不得产生第二套无 ownership 的 agent 执行器 |
| 持久化 | bandit/planCache 重启后从 MeridianDb 恢复；DB 缺失 no-op |
| Prefix cache | effort 走 API 参数；plan reuse 不做大段稳定 prompt 注入 |

## 8. 修订后的净判断

- T2-02 的「空转学习器」判断成立，但原计划把「接通」写得过于直接。
- LinUCB 不能直接接管 effort；先 shadow，再受控 ±1 档。
- PlanCache 不能从 `plan_submit` 草稿记录；必须从已批准/已成功执行的结构化步骤记录。
- AgentJIT 不能自动执行写工具；只读优先，写操作审批。
- Nightcrawler 大概率被 delegate/coordinator 覆盖；默认封存或降级为非 agent 后台 job。
