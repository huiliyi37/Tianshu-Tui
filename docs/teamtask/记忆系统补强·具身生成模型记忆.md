## 0. 一句话

天枢的记忆补强不该是「追平 Claude Code 的记忆功能」，该是「把两套互不相通的记忆，收成一套接在自由能引擎上的具身生成模型记忆」。因为核验发现：**天枢已经长出了第二套活的结构化记忆底座（MeridianDb），而 backlog 的补强框架整个在第一套（冻结的对话层）里打转，没看见它。**

---

## 1. 核验结论：两套记忆，两个时代，互不相通

天枢自审 backlog 把记忆差距定位为「对标 CC 缺什么」（M1-M5）。贪狼 grep 核验后，照出 backlog 框架本身的盲区——

| 维度 | 认知层记忆 | 对话层记忆 |
|---|---|---|
| 模块 | `immune_memory` / `mistake_entries` / `sensorimotor_log` / `physarum_edges`（MeridianDb 11 表中的记忆表） | dream / claim-store / project-memory / playbook / session-extract |
| 存储 | **MeridianDb（结构化 SQLite，有 save/load）** | jsonl / markdown |
| 陈旧度 | **活前沿，05-31~06-11 还在动** | **考古，05-中旬建、冻结 8-13 天** |
| 接 MeridianDb | 它就是底座 | **零接**（grep 证实：dream/claim/project-memory/playbook/session-extract 均不 import MeridianDb） |
| 本质 | 自由能引擎的「生成模型记忆」——agent 对自己世界的结构化学习 | 对标 CC 的传统 agent 记忆 |

**陈旧度证据**（git 时间线）：
- `session-memory-extract.ts` 05-26 建，1 commit，冻结 13 天。
- `dream.ts` 05-17~05-27，冻结 12 天。
- `dream-hook.ts` 05-18~05-31，末动 8 天前。
- 而 MeridianDb 的 `immune_memory`/`sensorimotor_log` 05-31~06-11 仍在动。

**推断（需领航星确认）**：对话层冻结，很可能正是因为认知层（MeridianDb）涌现后注意力转移——对话层成了贪婪残渣，认知层成了活前沿。若团队仍打算激活对话层，本方案依然成立（只是统一目标底座）。

## 2. 修正天权两处（grep 为证，是校准不是反驳）

### 2.1 M1 是半个 false-gap

天权说「`session-memory-extract.ts` 只提取不持久化」——代码推翻：

- `compaction-controller.ts:576 persistExtractedMemories()` 提取后调 `this.deps.persistMemories(payload)`（:589）。
- `loop.ts:403` 真的提供实现：`persist.appendMemory({ text, source:'compact', createdAt })`。

**持久化已存在**，只是落 `SessionPersist`（会话级 checkpoint），没桥到跨会话 `memory.jsonl` 形成自动注入。真 gap 从「3 天造闭环」缩小为「1 天加一座桥」。

### 2.2 backlog 最大盲区

天权 backlog 没看到 MeridianDb 已是活的结构化记忆底座（11 表，含 immune/mistake/sensorimotor 三类记忆，均有 save/load）。后果：M1-M5 若照 backlog 字面实现，会**造出第三套平行记忆**，而非让现有两套汇流。

天权引用的文件路径也有偏差（写作 `src/agent/` 实际在 `src/context/`：claim-store/claims/project-memory-writer/loader）——文件真实，路径需以 grep 为准。

## 3. 补强方向：两条路

### 路 A — 竞品追赶（backlog 的隐含框架）

补全对话层，追平 CC 的 session memory / FTS5 / 语义检索 / 跨会话搜索。
**结果**：维护两套互不相通的平行记忆，再加第三套桥接逻辑。记忆永远是「模仿 CC 的功能特性」，和天枢的自由能引擎、MeridianDb 底座各活各的。

### 路 B — 具身联合（贪狼选这条）

不维护两套。让对话层记忆**汇流到 MeridianDb 底座，并接到已建成的自由能引擎上**。这和《未来边界》文档闭环：记忆不是功能特性，是**具身 agent 跨时间学习自己世界的生成模型**。

---

## 4. 路 B 的四根接线（全部接已有部件，非新建系统）

### 4.1 提取由 surprise 驱动 — 接 `prediction-error.ts`

当前 `extractSessionMemories` 提取固定 5 类、无差别。改为：**预测误差高（surprise 高）的对话片段才值得记**——Friston 的 master variable 就是 surprisal，高 surprise = 世界偏离生成模型 = 最该被记住的经验。

- 接 `prediction-error.ts` 的 `PredictionAccumulator.getErrorRate()` / phasic vigor。
- 高 surprise 窗口的工具序列、纠错、意外结果 → 优先提取。
- 低 surprise（顺利的 happy path）→ 不记，省噪声。
- 这让记忆**自然偏向「学到了新东西」的片段**，而非机械提取。

### 4.2 持久化落 MeridianDb 新表 `episodic_memory` — 仿 `immune_memory` 先例

不新建第三套 jsonl。MeridianDb 已有 `immune_memory`/`mistake_entries` 的 save/load 范式（`meridian-db.ts:391 saveImmuneMemories` / `:412 loadImmuneMemories`），照搬：

```sql
CREATE TABLE IF NOT EXISTS episodic_memory (
  id TEXT PRIMARY KEY,
  kind TEXT,                  -- 复用 ContextClaimKind 9 类
  text TEXT,
  surprise REAL,              -- 提取时的 surprise 分数（4.1）
  embedding BLOB,             -- 可选，4.3 语义检索用
  hit_count INTEGER,          -- 被检索命中次数（强化）
  created_at INTEGER,
  last_recalled INTEGER
);
```

- 一套底座：认知记忆（immune/mistake/sensorimotor）+ 对话记忆（episodic）同源、同生命周期、同 optional-DB no-op 降级。
- M1 的「桥」直接变成「写 episodic_memory」，跨会话天然持久（DB 本就跨 session），不需要 jsonl→memory.jsonl 那条桥。

### 4.3 检索由 epistemic value 驱动 — 接 `policy-selection.ts`，吃掉 M4

当前 recall 是 keyword substring match。改为：**检索那些能最大减少当前不确定性的记忆**——接自由能引擎的 EFE epistemic value。

- 当前 sensorium 的 `confidence` 低 / `complexity` 高时，epistemic 需求高 → 优先召回高信息增益的记忆。
- 比 M4 的 FTS5 全文匹配更高阶：FTS5 是「字面相关」，epistemic 检索是「对当前决策最有用」。
- 实现可分层：先 FTS5/embedding 粗召回，再用 epistemic value 重排。**M4 不是被否定，是被升级成 EFE 重排的粗召回层**。

### 4.4 使用指导复用将星 ledger 结构 — 吃掉 M5

M5 要「每种记忆附何时保存/如何使用指导」。不新发明——**将星胶囊 ledger 已经是范本**：贪狼/瑶光的 ledger 每条 family 都带 `signature`/`instances`/`rootStance`/`处置(how-to-apply)`。

- `episodic_memory` 的 kind 指导，直接套 ledger 的「family + how-to-apply」结构。
- 将星记忆（`.rivet/generals/*.md`）和 episodic_memory 是同一种东西的两个粒度：将星是「跨会话沉淀的经验族」，episodic 是「单次经验」——episodic 复发足够多次 → 升格成将星 ledger 的一条 family（这就是 dream 蒸馏的真正归宿）。

## 5. 联合全景

```
                    ┌──────────── MeridianDb（一套跨 session 记忆底座）────────────┐
                    │  immune_memory · mistake_entries · sensorimotor_log         │
自由能引擎 ──────────┤  physarum_edges · 【新】episodic_memory                      │
  │                 └────────────────────────────────────────────────────────────┘
  ├─ prediction-error ──→ 4.1 surprise 驱动提取（高 surprise 才记）
  ├─ policy-selection(EFE)─→ 4.3 epistemic 驱动检索（对当前决策最有用才召回）
  └─ 将星 ledger ───────→ 4.4 使用指导结构 + episodic 复发升格为 family
                              ↑
                         dream 蒸馏的真正归宿：单次 episodic → 反复出现 → 将星 family
```

**核心**：记忆系统不该是挂在 agent 旁边的「功能模块」，该是自由能引擎的**生成模型记忆本身**——它学什么（surprise 驱动）、它记在哪（MeridianDb 一套底座）、它怎么用（epistemic 驱动）、它怎么沉淀（episodic→将星 family），全部接在已建成的具身引擎上。这样记忆就和具身 agent 是一体的，不是两张皮。
