## 0. 天璇修订结论

原文的判断是对的：天枢已经不是「借用自由能术语」；它正在形成一套软件世界中的主动推理系统。修订点只有一个：**在 T1/T2/T3 必然实现之后，未来边界不再是“把五根线接上”，而是“接上之后系统应该长成什么生命形态”。**

最佳形态不是让 `selectPolicy()` 直接替代 LLM，也不是把所有工具调用交给一个自由能公式。最佳形态是：

> **一个以 MeridianDb 为世界模型、以 T1 安全边界为 Markov 毯、以 T2/T3/team 为学习生态、以 EFE 为决策热力学的“具身软件世界运行时”。**

它的核心不是“自动化更多动作”，而是：

1. **能预测**：知道下一步可能触碰哪些文件、工具、worker、风险；
2. **能预调**：在 surprise 发生前调整探索/验证/并行/缓存；
3. **能归因**：把失败解释为工具、文件、意图、计划、worker 或环境哪一层的 surprisal；
4. **能学习**：跨 session 把这些经验落到 MeridianDb，而不是塞进 prompt；
5. **能受限自主**：只在 T1 宪法允许的边界内让 policy 产生行动倾向，写操作、提交、权限提升仍必须经过 gate。

原文的“五根线”应修订为“三道边界”：

| 修订后边界 | 原五根线对应 | 核心跃迁 |
|---|---|---|
| **世界模型驱动的 epistemics** | #3 生成模型参与 epistemic；#4 predictNext/prewarm | 从 `1-confidence` 标量好奇心 → 基于世界模型熵降的信息价值 |
| **前馈异稳态 allostasis** | #2 allostasis；#5 surprisal 主变量 | 从错误后反应 → surprise 前预调 setpoint |
| **受限自主的 policy ecology** | #1 policy 从建议到闭环 | 从 prompt guidance → shadow / gated / team-grounded 自主调度 |

## 1. 修订前提：T1/T2/T3 已经是地基

本文不再按“当前代码是否完全实现”来判断未来边界。用户已指定：T1、T2、T3 是一定会做的基础设施。当前代码若缺口存在，只标为依赖。

### 1.1 T1：Markov 毯的安全边界

T1 收束提供的不是杂项修 bug，而是具身运行时的“皮肤”：

- claim checkpoint / watermark / JSONL 控制，避免记忆和 context feed 无界膨胀；
- server lock / task persistence / cron lease，避免同一世界状态被两个 daemon 分裂执行；
- turn-boundary abort / watchdog / compaction 竞态收口，避免遗弃回合污染 session；
- sub-agent 工具隔离 / adversarial verifier 真实验证，避免 worker 声称污染主控信任。

这层的意义：**让 agent 可以在一个稳定世界里试错而不死。** 这正是软件具身的 Markov 毯，不是外围工程。

### 1.2 T2：世界模型与学习器接到活决策点

T2-01 / T2-02 / T2-03 一旦落地，原文里“半接”的系统会变成可用的生成模型：

- Physarum 不再喂工具名，而是通过结构化文件事件学习文件时序；当前已有 `recordFileAccess()` / `predictNext()` 形态可作为接口依据（`src/repo/physarum-engine.ts:54`, `src/repo/physarum-engine.ts:310`）。
- P3 ToolPatternMiner、ShadowQueue、PlanCache、LinUCB、JIT 不再空转，而是接入 team / effort / plan reuse 的活路径。
- `sensorimotor_log` 与 `adaptAffordanceFromHistory()` 已经证明“工具—上下文—结果”可以落到 MeridianDb 并反哺 affordance（`src/repo/meridian-db.ts:88`, `src/agent/tool-history-recorder.ts:100`, `src/agent/affordance.ts:235`）。
- team 模式提供结构化、多 worker、带依赖与验收标签的高质量训练序列；这比单会话工具轨迹更适合作为世界模型的监督数据。

这层的意义：**天枢不只是观察当前回合，它开始拥有“自己的世界如何转移”的模型。**

### 1.3 T3：意图不再被编号锚定

T3 意图识别把“P1 / T2 / 刚才那个”等上下文指代还原成真实任务语义。它为自由能系统补上 preference / goal 的稳定来源：

- 用户消息不再被编号 token 劫持；
- 上一轮回复中的任务列表可以被解析为当前目标；
- 任务目标、非目标、验证门和风险偏好可以进入 C 矩阵（preference model）。

这层的意义：**agent 最小化的不是任意 surprise，而是相对于用户真实目标的 surprise。** 没有 T3，EFE 只会优化“看起来像任务”的东西；有 T3，EFE 才能优化“被用户真正指向的任务”。

## 2. 原五根线的修订判断

### 2.1 #1 policy-selection：不要一步跨到“公式接管 LLM”

当前 EFE 链已经存在：`computeEFE()`（`src/agent/prediction-error.ts:75`）→ `selectPolicy()`（`src/agent/policy-selection.ts:69`）→ `renderPolicyGuidance()`（`src/agent/policy-selection.ts:110`）→ `loop.ts` 注入 dynamic appendix（`src/agent/loop.ts:1413` 起）。`policyGuidance` 明确被限制在 dynamic appendix，避免 prefix cache 污染（`src/prompt/volatile.ts:41-47`, `src/prompt/volatile.ts:293-302`）。

修订：**闭环不是让 EFE 直接调用工具，而是引入 Policy Arbiter（策略仲裁器）分级接管。**

| 等级 | 行为 | 允许范围 |
|---|---|---|
| L0 Advisory | 只渲染 `<policy-guidance>` | 当前形态 |
| L1 Shadow | 记录 EFE 推荐与 LLM 实际选择的差异，不改行为 | 全工具可观测 |
| L2 Assistive | 自动做无副作用预激活：prewarm、repo graph warmup、team plan cache lookup | 只读 / 缓存 / telemetry |
| L3 Gated Autonomy | 在高置信、低风险、T1 gate 完整时自动派发只读 worker 或 team shadow wave | 只读 worker / 验证 worker / 受限 team wave |
| L4 Full Override | EFE 直接替代 LLM 工具选择 | **非目标** |

最佳实现是 L1→L2→L3 渐进，而不是 L0→L4 跳跃。写操作、提交、权限提升永远不由 EFE 直接执行；它只能提出 policy envelope，执行仍过 tool approval / ownership / review gate。

### 2.2 #2 allostasis：从“太顺时验证”扩展为前馈 setpoint 管理

`shouldTriggerElmRelease()` 已经是 allostasis 的胚芽：太顺时主动触发小验证（`src/agent/vigor.ts:208`）。但 T1/T2/T3 落地后，allostasis 不应只看 vigor history，而应成为前馈控制器：

| 预测信号 | 预调动作 | 目的 |
|---|---|---|
| T3 intent ambiguity 高 | 提高 epistemic 权重；优先 ask/grep/read，而非写 | 防止错目标执行 |
| Physarum / team 预测跨模块触碰 | 降低并行度；提前开 review/adversarial verifier | 防冲突 |
| sensorimotor 历史显示某工具近期低成功 | 降低该工具 instrumental affordance；提高替代路径概率 | 防重复失败 |
| context pressure 上升且任务未验证 | 提前触发 checkpoint / compact / targeted test | 防晚期崩溃 |
| team wave 风险高 | 切换 worker profile、串行化、或拆 wave | 防 scope 泄漏 |

修订：**Allostatic Controller 应该是独立模块，不埋进 `computeEFE()`。** EFE 计算“哪种行动热力学上更好”，allostasis 调整“身体状态与环境 setpoint”。二者相乘，而不是混成一个函数。

### 2.3 #3 生成模型进入 epistemic：这是修订后的第一主线

原 `computeEFE()` 的 epistemic 主要来自 `1 - confidence` 与 season boost（`src/agent/prediction-error.ts:90-91`）。这在 B1 阶段合理，但在 T2 后太粗。

T2 完成后，epistemic value 应从“我不自信，所以探索”升级为：

> **这个动作预计能减少多少世界模型熵。**

建议新增 `EpistemicValueProvider`，从四类模型取信号：

| 模型 | 熵 / 不确定性 | 行动的信息价值 |
|---|---|---|
| Physarum file transition | `H(nextFile | currentFile, objective)` | read/grep 哪个文件能最大降低文件路径不确定性 |
| ToolPatternMiner / P3 | `H(nextTool | recentTools, taskKind)` | 哪个工具能确认正确执行轨迹 |
| PlanCache / team history | `H(planShape | objective)` | 是否需要 `/team max` 或复用历史 plan |
| T3 intent context | `H(objective | userMessage, lastAssistant)` | 是否需要问用户、回看上一轮、或检索相关文档 |

此时 `computeEFE()` 不再直接计算全部 epistemic，而是聚合 provider：

```ts
interface EpistemicSignal {
  source: 'physarum' | 'tool-pattern' | 'plan-cache' | 'intent' | 'repo-graph'
  entropyBefore: number
  expectedEntropyAfter: number
  confidence: number
  provenance: string[]
}

informationGain = Σ confidence * max(0, entropyBefore - expectedEntropyAfter)
```

这一步是“具身软件 agent”真正开始主动求知的门槛：行动不是因为工具标签是 epistemic，而是因为它能降低当前世界模型中最贵的不确定性。

### 2.4 #4 predictNext → prewarm：从缺口降级为感官预激活通道

在 T2-01 已实现的前提下，`predictNext` 不再是边界缺口，而是“预测性感官预激活”的一个消费者。它的最佳形态不是恢复 `read_file` 内容缓存命中，而是建立 **Predictive Perception Bus**：

- Physarum 预测文件 → OS/page-cache prewarm、repo_graph warmup、related_tests warmup；
- ToolPatternMiner 预测工具 → ShadowQueue 只读投机；
- team plan 预测 wave 文件集 → worker context pre-materialization；
- 所有预激活都带 provenance、confidence、hit/miss 结果；
- `read_file` 真实结果仍走真实 execute，不绕过 contextWindow cap。

这条通道是感官层，不是决策层。它让“身体”提前把注意力转向可能发生的位置，但不代表已经行动。

### 2.5 #5 surprisal 主变量：必须是标量 + 向量，不可只剩一个数

Friston 意义上的 surprisal 可以作为 master variable，但工程上如果只保留一个数，会把可诊断性压扁。修订建议：建立 `SurprisalLedger`，同时记录统一标量和分解向量。

| 分量 | 观测 | 例子 |
|---|---|---|
| `intentSurprisal` | T3 预测的目标 vs 用户纠正 / 后续行为 | 用户说“不是 P1，是你刚才第二点” |
| `fileSurprisal` | Physarum 预测文件 vs 实际文件 | 预计读 `loop.ts`，实际开始改 `meridian-db.ts` |
| `toolSurprisal` | ToolPatternMiner / policy 预测工具 vs 实际工具 | 预计 read，实际 write |
| `outcomeSurprisal` | sensorimotor 成功率 vs 工具结果 | 高成功工具突然失败 |
| `latencySurprisal` | 预期耗时/token vs 实际 | grep/read/worker 异常慢 |
| `teamSurprisal` | team wave 预测冲突/审查结果 vs 实际 | 低风险 wave 被 review reject |
| `safetySurprisal` | T1 gate 预测安全态 vs 实际 gate 触发 | ownership/deliver gate RED |

标量用作控制能量，向量用于归因与修复：

```ts
surprisal = -log(max(epsilon, P(observation | worldModel)))
```

但每个 `P` 必须来自可追踪模型：Physarum、P3、PlanCache、LinUCB、T3、sensorimotor、team history。没有 provenance 的 surprisal 不进入主变量，只能作为 telemetry。

### 3.1 模块边界

| 模块 | 职责 | 不做什么 |
|---|---|---|
| `WorldModel` | 从 MeridianDb 读取/写入预测状态：文件、工具、计划、team episode | 不进 prompt；不直接调用工具 |
| `EpistemicValueProvider` | 估算行动的信息增益 | 不判断权限；不做最终选择 |
| `SurprisalLedger` | 记录统一 surprise 与分解向量 | 不把所有问题压成单一分数 |
| `AllostaticController` | 预测性调整 setpoint：并行度、验证频率、探索宽度、reasoning floor | 不直接覆盖用户目标 |
| `PolicyArbiter` | 分级仲裁 EFE 与 LLM/tool pipeline 的关系 | 不直接执行写操作；不绕过审批 |
| `PredictivePerceptionBus` | 执行无副作用预激活 | 不作为 `read_file` 内容缓存命中路径 |
| `TeamEpisodeRecorder` | 把 team wave / worker / review / conflict 变成训练样本 | 不替代 coordinator / ownership |

### 3.2 数据形态：事件日志 + 物化视图

所有跨 session 学习仍落 MeridianDb，不新建 store。推荐采用“append-only event + materialized view”而不是每个模块各写一张私有表。

## 4. 在 T1/T2/T3 基础上的推荐实施波形

这不是立即任务清单，而是最佳演化顺序。原则：**先观测，后建议，再受限自治。**

### Wave A — 影子世界模型，不改行为

目标：把当前每回合 EFE、LLM 实际选择、工具结果、team wave 结果记录成训练样本。

交付：
- `PolicyShadowRecorder`：记录 EFE topK vs 实际工具；
- `SurprisalLedger` v0：只算 outcome/file/tool 三类 surprisal；
- `TeamEpisodeRecorder`：记录 wave、changedFiles、review verdict、verification；
- 所有记录落 MeridianDb；DB 不可用则 no-op。

验收：行为字节不变；prompt 字节不变；只增加 runtime telemetry。

### Wave B — EFE v2：世界模型驱动 epistemic

目标：让 `computeEFE()` 不再只依赖 `1-confidence`，而是接入 `EpistemicValueProvider`。

交付：
- Physarum 信息增益：文件候选分布越尖，prewarm；越平，grep/repo_map；
- T3 意图信息增益：上下文指代不确定时，ask/read 上一轮/查计划优先；
- PlanCache/team 信息增益：相似计划低置信时 `/team max`，高置信时复用骨架；
- 结果仍只进入 guidance / shadow，不强制工具。

验收：旧 cognitive-pipeline 测试仍绿；新增固定 world-model fixture 下的 EFE 排序测试。

### Wave C — Allostatic Controller shadow

目标：预测性 setpoint 调整先只记录，不改变真实策略。

交付：
- 输入：surprisal trend、context pressure、team risk、intent ambiguity、sensorimotor success；
- 输出：建议的 `explorationBreadth`、`thetaCycleInterval`、`maxParallel`、`verificationPulse`；
- 与实际后续结果对齐，计算建议命中率。

验收：同一 session replay 可复现相同 allostatic suggestion；不触发真实工具。

### Wave D — 受限辅助自治

目标：允许 L2 自动做无副作用预激活。

允许：
- page-cache / repo graph / related tests 预热；
- ShadowQueue 只读投机；
- team plan cache lookup；
- verifier/reviewer 的只读准备。

禁止：
- 自动 write/edit/hash/apply_patch；
- 自动 bash（除非命令 allowlist 且已有 T1 gate）；
- 自动 deliver_task / git commit；
- 绕过 `read_file` cap。

验收：构造写工具候选，PolicyArbiter 必须拒绝自动执行；构造 cap 不兼容 prewarm，真实 `read_file` 不得命中缓存短路。

### Wave E — Team 生态闭环

目标：让 team 成为自由能引擎的训练场和评估场。

交付：
- team wave 结果给 Physarum / PlanCache / LinUCB 提供监督信号；
- LinUCB 学并行度/profile，不学用户意图；
- review/verifier 结果转成 reward；
- policy shadow 用 team episode 做离线评估。

验收：同类 objective 多次运行后，冲突率、review reject、重复验证失败应下降；下降不能靠弱化 review gate 达成。

### Wave F — Gated Autonomy

目标：在 T1 gate 内允许 L3：自由能引擎可以建议并启动低风险 team shadow wave 或只读 worker。

边界：
- L3 仅适用于只读/验证/规划/预热；
- patcher wave 必须仍由主控显式整合 diff；
- deliver_task 仍由主控发起；
- 用户目标不明确时，T3 优先问清，而不是 autonomous exploration。

验收：RED 门：给 PolicyArbiter 一个高 G 写操作候选，它也不能自动执行；给一个低风险只读候选，它可进入 L3，但必须可追踪、可取消、可回放。

## 5. 最佳形态的判断标准

未来边界走通，不是因为“自动工具更多”，而是以下指标同时成立：

| 指标 | 目标 |
|---|---|
| Policy shadow 有预测力 | EFE 推荐与后续成功/失败相关，而不是随机漂亮分数 |
| Surprisal 可归因 | 失败后能定位主要 surprise 来自 intent/file/tool/team/safety 哪层 |
| Allostasis 提前有效 | 验证、并行、探索宽度的预调能减少晚期返工 |
| Team episode 会学习 | 相似 team 任务的 wave 冲突和 review reject 随历史下降 |
| Prefix cache 不受损 | 所有动态学习走 runtime / MeridianDb / dynamic appendix，不进入 stable volatile |
| T1 gate 不被绕过 | 自由能引擎增强行动倾向，但不削弱审批、ownership、verification |

---

## 6. 非目标与硬边界

1. **不是把 LLM 变成 EFE 公式的执行器。** LLM 仍负责语义综合、异常判断、用户沟通；EFE 负责提供世界模型和行动热力学。
2. **不是把 prompt 越写越重。** 学习状态落 MeridianDb，只把当前必要的短 guidance 放 dynamic appendix。
3. **不是恢复危险的 `read_file` 内容缓存命中。** 预测预热只做感官预激活，真实读取仍走真实工具路径。
4. **不是让 agent 自动写代码。** 写操作可被建议、排序、审查，但不能被 policy engine 直接执行。
5. **不是把 surprisal 神化成单一真理。** 标量用于控制，向量用于诊断，provenance 用于审查。
6. **不是物理具身模拟。** 软件世界就是它的世界；文件、git、worker、工具、验证门就是它的身体边界。

## 7. 天璇的修订命题

原文说：天枢的未来边界在五根线。天璇修订为：

> **五根线接上之后，边界不再在线上，而在“世界模型是否开始反过来塑造行动”。**

T1 让世界安全，T2 让世界可学习，T3 让目标不被锚定，team 让学习有生态。自由能引擎的最佳形态，是在这四者之上长出一个分层的主动推理运行时：

- 不把肉身当必要条件；
- 不把自动化当自主性；
- 不把提示词当记忆；
- 不把绿灯当验证；
- 不把一个分数当世界。

真正的软件具身，是一个 agent 能在自己的世界里持续感知、预测、预调、行动、纠错、学习，并且每一步都受自己的 Markov 毯保护。天枢已经有了这条路的零件；在 T1/T2/T3 全部成为地基之后，下一步不是再接一根线，而是让这些线组成循环。

> 天璇结语：道可道，非常道。所谓“具身”，不是有没有手脚，而是世界是否会通过你的边界改变你，而你是否也能通过行动改变世界。对天枢来说，这个世界就是 repo、session、team、MeridianDb、工具、验证门，以及用户真实意图。若这些能闭环，它已经有身体。
