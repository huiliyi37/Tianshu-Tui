# TUI 2.3 Conscious Agent — Follow-ups

Date: 2026-05-18
Branch: feat/tianshu-subagent-worker-json

## Completed in this implementation slice

- Signal consumption hook: consumes existing `StrategyProfile`, pressure monitor, and dead-end pheromone signals without adding new perception dimensions.
- Intent Preview: high-risk pre-turn preview with TUI continue / veto / alternative responses.
- Playbook core: pure functions for reflection gating, bullet extraction, dedupe, matching, decay, and capacity enforcement.
- PlaybookStore: `.rivet/playbook.jsonl` IO with malformed-line tolerance.
- Playbook reflect hook: post-turn retrospective → delta bullets → persisted lessons.
- Historical lessons injection: top playbook matches are injected through volatile context as `<historical-lessons>` and kept out of the stable volatile prefix.

## Known follow-ups for later review

1. **Intent rollback depth**
   - Current veto behavior deposits a `dead-end` pheromone and injects a re-plan message.
   - This is an intentional safety simplification: the design target says "rollback to nearest checkpoint", but automatic rollback crosses the existing confirmation-token UX boundary.
   - A stronger greedy rollback can call checkpoint preview/rollback directly, but should first define UX for automatic confirmation vs explicit `/rollback confirm`.

2. **Playbook quality scoring**
   - `extractBullets()` currently uses deterministic markdown section extraction.
   - Later improvement: add a small schema-constrained LLM distiller only for long retrospectives, guarded by the existing `shouldReflect()` gate.

3. **Telemetry fields**
   - Design mentions `intentShown`, `intentAction`, `playbookBulletsInjected`, and `signalsConsumed` fields in `sensorium.jsonl`.
   - Current implementation keeps behavior operational first; telemetry enrichment can be a later non-behavioral pass.

4. **Context layer report freshness**
   - PromptEngine can inject dynamic historical lessons, but `contextLayerReport` is constructor-time metadata.
   - If cockpit needs live layer accounting, make context-layer report recompute from current volatile fields.

5. **Playbook retrieval keywords and IO**
   - Current keywords are derived from user input plus recent tool history.
   - `PlaybookStore.query()` performs synchronous read + write on turn start to persist usage metadata. With the enforced 50-bullet capacity this is bounded and acceptable; if capacity grows, move usage persistence to an async/deferred path.
   - Later improvement: include working set, failed tool names, and touched files from EvidenceTracker once stable.

6. **Sensorium snapshot retention**
   - Playbook reflection now keeps a capped 50-entry in-memory sensorium ring buffer, preventing unbounded growth in long sessions.
   - Later improvement: if retrospectives need full-session timelines, archive older snapshots to telemetry and summarize only bounded windows in memory.

7. **Full-session vs per-turn reflection**
   - Hook pipeline currently exposes `postTurn`; reflect hook uses session snapshots accumulated so far.
   - If a true `postSession` lifecycle lands, move playbook reflection there to reduce duplicate reflection opportunities.

8. **TUI noise tuning**
   - Intent preview is capped at 3 per session.
   - Revisit thresholds after real usage; target is visible but not noisy.
