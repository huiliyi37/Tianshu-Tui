# 审查实战复盘：team 四模块对抗式审查（2026-06-07）

> 性质：实战案例记录（事实层），非方案。
> 触发：team mode V1 已交付（45 测试绿、tsc 0 error、天府审查修过 H1/H2/M2/M3），收到"进度总览"声明后做独立深度审查。
> 价值：这是"姿态视角在场才能发现细节隐患"的活样本，作为 squadron 方案加「姿态轴」的实证依据。
> 下游：`2026-06-07-review-squadron-stance-axis-proposal.md`（用本案例反推的优化提案）。

---

## 0. 一句话结论

team 四模块的**编排主干是稳的（B+）**，但**四个真 bug 全部挤在"解析人写的 markdown"这道输入边界上（解析层 C+）**。它们在 45 个绿测试 + 一轮天府审查后**依然存活**——只有当一个**带对抗姿态的审查视角真的在场**、主动喂畸形输入时才暴露。这正是"team 认知 > 单主控认知"的实证：救活的每个时刻，都是临时切换了姿态。

---

## 1. 四个真 bug —— 各由什么"姿态/动作"挖出

| # | 缺陷 | 锚点 | 由什么姿态发现 | 默认主控为何看不到 |
|---|------|------|---------------|-------------------|
| ① | 反引号包多路径被吞成一个伪文件名，静默破坏文件冲突串行（两个该串行的写任务并行） | `team-plan.ts:extractFiles` | **马超**：主动喂 `` `src/a.ts, src/b.ts` `` 畸形输入 | 只为想象中的"一路径一反引号"写代码 |
| ② | 循环依赖静默产出任意顺序，配个笼统 "circular or unresolvable" | `team-grouping.ts` forced 分支 | **天权**：质疑"循环依赖真被处理了吗" | 标了 high risk 就以为"已安全降级" |
| ③ | 悬空依赖（拼错的 id）被当"已满足"，任务无依赖抢跑 | `team-grouping.ts:159-160` | **天权 + 马超**：拼错一个 dep id 看会怎样 | `!taskMap.has(dep)` 兜底=容错偏好，咽下歧义 |
| ④ | verification 关键词无词边界，散文"测试整个流程"被当成命令 | `team-plan.ts:extractVerification` | **马超**：喂一句含"测试"的散文 | 中文关键词便利写法，没想词边界 |

**关键观察**：四个里三个靠"喂畸形/对抗输入"出来。默认主控**不会**这么做——它测它"为之而造"的输入，不测"能击穿它"的输入。

---

## 2. 五条主控盲区（stance 默认值导致，非知识缺口）

1. **盲区全长在输入边界，不在主干。** 注意力被"功能正确性"占满，畸形输入被挤出视野。（呼应 squadron 设计 §0 根因）
2. **错误形态是"静默吸收"而非崩溃。** 代码被写成绝不大声失败（悬空当满足、循环 force 过）——容错偏好把歧义咽下去，错误隐形、累积。
3. **把"上游声称"当事实往下传（最毒）。** 本会话多次把"框架落地/有设计文档"读成"已验证/可用"，需被反复纠正。错前提复利污染下游每个判断。
4. **连自己派的审查 agent 也不能照单全收。** 对抗 agent 误报"死循环 HIGH"（`visited` 集合根本不会死循环）——主控须对自己的审查者也做对抗验证。
5. **绿灯 ≠ 对，且绿得最稳处恰是最弱处。** 45 绿 + 0 error 与四个真 bug 并存；绿测试覆盖的是实现者想象的 happy path，在最该警惕处制造最强虚假信心。

---

## 3. 结论：盲区是姿态默认值，换强模型救不了

默认主控姿态 = "造它 / 让它跑通 / 继续往前 / 信绿灯"。**这一个姿态，无论模型多强，都会结构性产出**：输入边界脆弱、静默吞错、锚定旧声称、绿即完成。

它只能被**另一种姿态在场**救：
- **马超**（专找能破坏的）→ 喂畸形输入 → 抓到 ①③④
- **天权**（有权质疑）→ 拒绝"绿=完成""文档=已验证" → 抓到 ②③、纠正盲区 3/5
- **天府**（fail-closed 守护）→ 会把解析器写成遇歧义大声失败，而非咽下

修复时刻意**不改容错策略，只让失败可见**（forced wave 指名道姓、悬空 dep 升 risk + 警告）——因为问题不是"太脆"，是"太顺从地咽下歧义"。

**这就是为什么专精姿态视角值得做成常驻可召唤的在场**：不能指望主控偶尔自己想起来切换姿态。本案例中，扮演"缺席视角"的是人类协作者（反复"你又陷进去了""如果前提不成立呢"）——目标是把这个角色沉淀进系统。

## 4. 复发实证：盲区会跨会话、跨提交原样复发（2026-06-07 第二轮）

§1-3 的盲区不是一次性的。同日审查**另一会话**新交付的 V2 max-mode 合并层（`team-perspectives.ts`，提交 `f364a02` 前），挖出两个新缺陷——它们与 §1 的 ①④ 是**同一族**：

| 新# | 缺陷 | 与旧缺陷同族关系 | 实证 |
|-----|------|----------------|------|
| 1 | 天府风险无 taskId 时落到 `''.includes(taskId ?? '')`，**空字符串永真**，关联到第一个无关的天璇替代，凭空造出 "conflict on unknown" | 同 ④：**缺字段时比较退化为永真**（④ 无词边界，此处空串 includes） | ✅ 构造输入复现 |
| 2 | 依赖集比较用 `join(',')`，`[a,b]` vs `[b,a]`（同一依赖集）被判为顺序冲突 | 同 ①：**字符串化比较吞掉结构语义** | ✅ 构造输入复现 |

**两轮共性**：测试全绿（35→37）、tsc 0 error，缺陷全部藏在"模型真实输出会走、但测试用例都绕开"的路径——天府风险常不带 taskId，规划器常乱序声明依赖。绿覆盖的仍是实现者想象的 happy path。

**这证明 §3 的论断不是修辞**：盲区是**姿态默认值**，所以它跨会话、跨人、跨提交**原样复发**。不同模型实例写出与上一轮**结构同型**的缺陷，正因共享同一默认姿态。换更强模型不会让这一族消失——只有"另一种姿态常驻在场"会。

修复同样遵守 §3 原则——**不改容错倾向，只补正确的匹配语义**：taskId 缺失时跳过关联（而非永真），依赖按集合比较（而非字符串）。两个原有冲突检测测试仍绿 → 削掉的是误报，不是检测能力。加两个 RED→GREEN 回归测试钉住。

**这一节本身是反例的反例**：能发现"盲区会复发"，正因为这一轮有"拒绝信绿灯、坚持复现才算数"的姿态在场。下一节把这个姿态命名、沉淀为天枢的一颗新星。
