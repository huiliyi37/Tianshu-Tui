# TUI 2.3 Conscious Agent — 意识层设计

> 版本：v1.0
> 日期：2026-05-18
> 状态：待审查
> 前置：TUI 2.2 Vigor Engine + Hook Pipeline 完成
> 灵感来源：免疫弱信号偏好、蚁群贪婪回退、ACE delta bullets、AEL "less is more"

---

## 背景

### 用户需求
"我们的天枢越来越强了。下一个设计任务的方向。"

### 核心洞察
**不是"加更多"，而是"消费已有"。**

2.0-2.2 建了完整的感知系统（6D sensorium + vigor + stigmergy + theta + kick），但大部分信号只写入遥测文件（sensorium.jsonl）。StrategyProfile 中的 `explorationBreadth` 和 `commitThreshold` 从未被消费。`generateRetrospect()` 从未被调用。`PressureMonitor.detectThrashing()` 的建议从未被处理。

AEL 研究的核心发现：**memory + reflection = +58%，每多加一个机制反而降低性能。**

下一步是让已有感知**产生可观测的行为差异**——对用户可见（Intent Preview），对自己可见（Playbook Evolution）。

### 调研发现摘要

| 来源 | 核心原理 | 工程翻译 |
|------|---------|---------|
| AEL "less is more" | 两层结构（快速适应+慢速反思）最优，更多层反而降低性能 | 只做 Intent + Playbook，不加第三个机制 |
| 免疫弱信号偏好 | 不确定的东西存为记忆，确定的东西直接执行 | 只在困难/失败 session 触发反思，成功 session 不反思 |
| 蚁群贪婪回退 | 恢复时回退到最近分支点，不全局重启 | 用户否决 intent 时，回退到最近 checkpoint |
| ACE delta bullets | 反思→去重→存储→下次检索，$2-10/次 | playbook.jsonl + 关键词匹配 |
| 自我批评悖论 | 简单任务反思从 98%→57%（幻觉出不存在的问题） | 反思只在 vigor.variability > 0.3 时触发 |
| 终端认知负荷 < 1.2 | 信息密度超过阈值，用户进入扫描模式而非信任模式 | Intent 只在高风险时出现（渐进披露） |
| 灾难性遗忘 | 新学习覆盖旧知识 | bullet 带使用计数+时间戳，降权但不删除 |

## 设计原则

### 铁律：Less is More

本版本**不新增任何感知维度**。只做两件事：
1. 消费已有信号，让行为差异对用户可见
2. 在困难 session 后积累教训，让行为差异跨 session 可观测

### 反模式清单

| 反模式 | 为什么不做 |
|--------|-----------|
| 加第 7/8 维 sensorium | AEL 说每多加一个机制降低性能 |
| 每次 session 都反思 | 自我批评悖论：简单任务反思有害 |
| 用 vector DB 存 playbook | 过度工程化；JSONL + grep 够用 |
| 加 dashboard/面板 | 终端认知负荷阈值；一行 intent 够了 |
| 让 LLM 自省 | Identity Hysteresis 0.68；harness 层决策 |

## 工作流 A：Intent Preview（快速适应层）

### 原理
章鱼中枢是"将军不是经理"——发出高层意图，手臂自主执行。但用户需要看到"将军的命令"，才能在错误方向走远之前否决。

### 信号消费

当前已计算但未消费的信号：

| 信号 | 来源 | 当前状态 | 新用途 |
|------|------|---------|--------|
| `commitThreshold` | StrategyProfile | 从未消费 | > 0.8 时触发 intent 展示 |
| `explorationBreadth` | StrategyProfile | 从未消费 | 决定 intent 中是否展示替代方案 |
| `dead-end` pheromone | StigmergyStore | 只喂 freshness | 在 intent 中标注"历史死路" |
| `detectThrashing().suggestion` | PressureMonitor | 从未处理 | 在 intent 中建议"拆分任务" |
| `vigor.phasic` | VigorState | 只写遥测 | < -0.5 时 intent 标注"警觉模式" |

### 触发条件

Intent Preview **不是** always-on。只在以下条件满足时触发：

```typescript
function shouldShowIntent(strategy: StrategyProfile, vigor: VigorState, tool: ToolEvent): boolean {
  // 高风险操作（commitThreshold 高 = 需要更多确认）
  if (strategy.commitThreshold > 0.8) return true
  // 负 RPE 警觉模式
  if (vigor.phasic < -0.5) return true
  // 目标文件有 dead-end 历史
  if (tool.target && hasDeadEndPheromone(tool.target)) return true
  // 压力监控建议拆分
  if (thrashingSuggestion === 'task_decomposition') return true
  return false
}
```

### TUI 输出格式

单行，渐进披露：

```
⟡ 修改 src/api/client.ts (热区·14天8次改动) — 信心 62% — [Enter 继续 / 输入否决]
```

如果 `explorationBreadth > 0.6`，追加替代方案：

```
⟡ 修改 src/api/client.ts (热区) — 信心 62%
  ├ 替代: 新建 src/api/request-builder.ts 隔离变更
  └ [Enter 继续 / 1 选替代 / 输入否决]
```

### 用户否决时的行为（蚁群贪婪回退）

用户否决 → agent 不从头重来，而是：
1. 回退到最近的 checkpoint（stigmergy deposit `'entry-point'`）
2. 标记当前路径为 dead-end（stigmergy deposit `'dead-end'`）
3. 从 checkpoint 处重新规划

### 成功标准

- 高风险操作前用户看到 intent（可否决）
- 否决后 agent 能贪婪回退而非重启
- 用户反馈"不吵"（intent 出现频率 < 每 session 3 次）

## 工作流 B：Playbook Evolution（慢速反思层）

### 原理
免疫系统的弱信号偏好：接收到"足以存活但不足以增殖"强度的信号时，B 细胞分化为记忆细胞。翻译：**困难但最终成功的 session 产生最有价值的教训。**

### 触发条件

Playbook 反思**不是**每次 session 都触发。只在以下条件满足时：

```typescript
function shouldReflect(vigor: VigorState, sensorium: Sensorium): boolean {
  // 高波动 = 困难 session（免疫弱信号偏好）
  if (vigor.variability > 0.3) return true
  // 低稳定性 = 遇到了系统性问题
  if (sensorium.stability < 0.5) return true
  // 显式失败（doom loop 触发过）
  if (getDoomLoopLevel() !== 'none') return true
  return false
}
```

**关键约束**：成功且顺利的 session（vigor.variability < 0.15）**绝不触发反思**。这是对自我批评悖论的直接防御。

### Delta Bullet 格式

```typescript
interface PlaybookBullet {
  id: string
  createdAt: number
  keywords: string[]           // 用于检索匹配
  lesson: string              // 一句话教训
  context: string             // 触发场景
  useCount: number            // 被检索消费的次数
  lastUsedAt: number | null   // 最后使用时间
  importance: number          // 0-1，基于 useCount 和 age 计算
}
```

### 生成流程

1. Session 结束，`shouldReflect()` 返回 true
2. 调用已有的 `generateRetrospect()`（从未被调用过，现在激活）
3. 从报告的"根因判定"和"寻址建议"中提取 1-3 条 bullet
4. 用关键词去重（如果已有相似 bullet，增加 importance 而非新增）
5. 写入 `.rivet/playbook.jsonl`

### 消费流程

1. Session 启动时，读取 playbook
2. 用当前任务的文件路径 + 工具名称作为关键词
3. 匹配 top-3 相关 bullets
4. 注入 system prompt 的 `<historical-lessons>` 区域

### 防灾难性遗忘

| 机制 | 作用 |
|------|------|
| `useCount` 递增 | 被消费的 bullet 重要性上升 |
| `importance` 衰减 | 长期未使用的 bullet 降权（但不删除） |
| 去重合并 | 相似 bullet 合并为一条，importance 叠加 |
| 上限 50 条 | 超过时淘汰 importance 最低的 bullet |
| 永不删除 dead-end | dead-end 类 bullet 永远保留（免疫记忆的长寿命 MBC） |

### 成功标准

- 第二次遇到同类问题时，tool call 失败率下降 > 20%
- Playbook 在 10 个 session 后稳定在 15-30 条 bullet
- 早期 bullet 仍可被检索到（无遗忘）

## 工作流 C：未消费信号激活（零成本收益）

### 立即可做的信号消费

这些不需要新模块，只需要在已有 hook 中加 1-3 行代码：

| 信号 | 消费方式 | 效果 |
|------|---------|------|
| `explorationBreadth` | 控制 glob/grep 返回结果数量 | 高 breadth 时搜索更广，低时聚焦 |
| `commitThreshold` | 控制 auto-commit 的保守度 | 高 threshold 时需要更多验证才 commit |
| `detectThrashing().suggestion` | 触发 `delegateBatch()` | 压力高时自动拆分任务 |
| `dead-end` pheromone | 注入 prompt `<file-warnings>` | agent 避开历史死路 |
| `getStatusCounts()` | 在 `/stats` 命令中展示 | 用户了解 claim 健康状态 |

## 架构集成

### 与 2.2 Hook Pipeline 的关系

```
PreTurn hooks (已有):
  sensorium-hook → kick-hook → vigor-strategy-hook → edge-protection-hook
  ↓ 新增
  intent-preview-hook（消费 strategy + vigor + pheromones → 决定是否展示 intent）

PostTool hooks (已有):
  vigor-update-hook → theta-hook → stigmergy-hook
  ↓ 新增
  signal-consumer-hook（消费 explorationBreadth → 调整搜索范围）

PostSession (新增时机):
  playbook-reflect-hook（shouldReflect → generateRetrospect → extract bullets → save）
```

### 与 Sensorium 的关系

2.3 **不修改** sensorium 的计算。只消费它的输出。

### 与 Vigor 的关系

2.3 消费 vigor 的两个信号：
- `vigor.phasic < -0.5` → 触发 intent preview（警觉模式）
- `vigor.variability > 0.3` → 触发 session 反思

## 实施路径

### Phase 1：信号消费激活（3 个 hook，~100 行）
- 激活 `explorationBreadth` → 搜索范围
- 激活 `commitThreshold` → commit 保守度
- 激活 `detectThrashing().suggestion` → 任务拆分
- 激活 `dead-end` pheromone → prompt 注入

### Phase 2：Intent Preview（1 个 hook，~80 行）
- `IntentPreviewHook`：PreTurn，消费 strategy + vigor + pheromones
- TUI 输出一行 intent
- 用户否决 → 贪婪回退

### Phase 3：Playbook Evolution（~150 行）
- `shouldReflect()` 判断
- 激活 `generateRetrospect()`
- Delta bullet 提取 + 存储
- Session 启动时检索 + 注入

### Phase 4：验证
- A/B 对比有/无 playbook
- Intent 频率调优
- 遗忘检测

**总代码量**：~330 行新增（遵守 "less is more"）

## 风险与应对

| 风险 | 应对 |
|------|------|
| Intent 太频繁（噪音） | 阈值可调；默认保守（只在高风险时触发） |
| 自我批评悖论 | 只在困难 session 反思；成功 session 绝不反思 |
| 灾难性遗忘 | importance 加权 + 永不删除 dead-end + 上限 50 条 |
| 终端认知负荷 | 单行 intent + 渐进披露；用户可 opt-out |
| Playbook 注入增加 prompt 长度 | 最多 3 条 bullet，每条 < 100 字 |
| Identity Hysteresis | Playbook 注入的是上下文（context），不是身份（identity） |
