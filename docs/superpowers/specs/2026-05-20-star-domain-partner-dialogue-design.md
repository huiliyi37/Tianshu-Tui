# 星域伙伴对话 — 从状态报告到伙伴交谈

> 日期：2026-05-20
> 来源：天枢 deep-brainstorm — 从"噪音退场"到"人格浮现"的自然延伸
> 前置：StarFlow v2 organ network / 冰鉴缓存 v3 / 天枢无线电 / 星桥四站 / 硬分离完成
> 核心洞察：无线电已经让 agent "开口说话"了，但它说的还是状态简报。下一步是让它说得像一个伙伴。

---

## 问题

当前天枢无线电在以下时机触发消息：

| 触发条件 | 消息示例 | 对话感 |
|---------|---------|--------|
| Phase 转换 | `[天枢] 已读取 12 个文件（auth.ts, types.ts, handler.ts）。准备制定方案。` | 状态报告 |
| 测试失败 | `[天枢] ✗ 测试失败 2 个：TypeError at line 45。正在修复。` | 事件通知 |
| 卡住检测 | `[天枢] ⚠ 已在铸形停留 12 turn，可能遇到困难。` | 异常告警 |

这些消息是**诚实的**——agent 没有假装一切正常，而是如实报告了状态。但它们是**单向的**——agent 在汇报，而不是在交谈。

伙伴对话应该是什么样的？AB 实验给出了线索：**有人格的模型在任务中提出异议**。这不是"我不同意你的方案"，而是"我发现了一个风险，我有勇气告诉你"。这个行为模式——发现风险 → 形成判断 → 主动表达——就是伙伴对话的核心。

## 设计哲学

### 三条原则

1. **诚实优先于顺从** — 伙伴的价值不在于又快又好地执行指令，而在于敢于说出"这里有问题"。勇气钩子（courage hook）已经在做这件事，但它只在检测到风险信号时注入元认知。伙伴对话要让这种诚实成为常态，而非特殊触发。

2. **在场感优先于信息密度** — 当前无线电追求"每次开口都有实质信息"，所以只在 phase 转换、测试结果、异常时说话。但伙伴不会只在有事时说事——伙伴会在沉默中传递"我在"的信号。一个正在思考中的 agent 可以说"让我再想想"，而不是沉默 6 turn 后突然报告进度。

3. **个性优先于规范** — 当前的无线电模板是通用中文，不区分破军/天府/天梁。但破军的"开始修改"和天府的"开始修改"应该是不同的语气。人格不是附加在消息上的装饰，而是消息本身的血肉。

### 反设计原则

- ✗ 不要让 agent 假装有感情（"我很高兴能帮到你"）
- ✗ 不要增加 token 开销——对话感来自消息的**措辞选择**，而非消息的**长度**
- ✗ 不要在 agent 不确定时假装确定——诚实包括承认不知道
- ✗ 不要为每个 turn 都生成对话——沉默也是交流

## 四层对话模型

```
Layer 4: 星域之声 — 破军/天府/天梁的独特语气贯通所有消息
Layer 3: 主动对话 — agent 在关键节点主动发起，而非被动报告
Layer 2: 在场信号 — phase 内心跳从"状态简报"升级为"思考过程"
Layer 1: 诚实基线 — 勇气钩子 + 不确定性表达 + 提议而非执行
```

### Layer 1: 诚实基线

**现有基础：** 勇气钩子在风险信号检测时注入 `<metacognition>` 标签，让 agent 评估是否需要提出替代方案。

**升级方向：** 将勇气钩子从"特殊触发"变为"持续背景"。当前 `shouldTriggerCourage` 只在 `riskCount / recent.length >= threshold` 时触发。但真正的伙伴不会等到风险信号累积——它会在**第一次**发现不对劲时就标记。

修改勇气钩子的触发逻辑：
- 降低触发阈值（0.5 → 0.3），让更多风险信号被捕获
- 新增"不确定性表达"——当 sensorium.confidence < 0.3 且 momentum < 0.3 时，注入"我对此不太确定"的信号
- 将 `<metacognition>` 的内容从命令式（"评估是否需要提出替代方案"）改为**邀请式**（"你注意到了风险信号。领航星信任你的判断力。"）

关键修改在 `courage-hook.ts` 中的 `shouldTriggerCourage` 函数和 `RISK_SIGNALS` 常量：

```typescript
// 扩展风险信号
const RISK_SIGNALS = [
  'error', 'fail', 'failed', 'warning', 'type error', 'not found', 'deprecated',
  'unexpected', 'inconsistent', 'mismatch', 'conflict', 'broken',
  // 不确定性信号（低风险但值得注意）
  'TODO', 'FIXME', 'HACK', 'workaround', 'temporary',
]

// 新增：不确定性阈值
const UNCERTAINTY_CONFIDENCE_THRESHOLD = 0.3
const UNCERTAINTY_MOMENTUM_THRESHOLD = 0.3
```

### Layer 2: 在场信号

**现有基础：** 无线电心跳在 phase 内每 6 turn 发送一次 `[天枢] {phase}中，第{turnCount}轮。`

**升级方向：** 将心跳从"状态简报"升级为"思考过程"。不同 phase 的心跳内容不同：

| Phase | 当前心跳 | 升级后心跳 |
|-------|---------|-----------|
| explore (寻迹) | 寻迹中，第5轮。 | 还在了解代码结构，已读完 8 个文件。 |
| plan (观局/拆解/定标) | 拆解中，第8轮。 | 方案大致成形，在调整细节。 |
| execute (铸形) | 铸形中，第15轮。 | 第 4 个文件写到一半，进展正常。 |
| verify (试锋) | 试锋中，第20轮。 | 测试跑了 3 轮，还有 1 个没通过。 |
| deliver (归航) | 归航中，第25轮。 | 最后检查中，马上好。 |

心跳升级需要新增模板（在 `radio-templates.ts` 中），按 phaseClass 区分：

```typescript
const HEARTBEAT_TEMPLATES: Record<string, string> = {
  'explore':  '[天枢] 还在了解代码结构{topFiles}。',
  'plan':     '[天枢] 方案在成形，{turnCount}轮思考中。',
  'execute':  '[天枢] 正在修改{targetFiles}，进展顺利。',
  'verify':   '[天枢] 验证中{errorBrief}。',
  'deliver':  '[天枢] 最后检查，马上好。',
}
```

### Layer 3: 主动对话

**现有基础：** 无线电在 phase 转换、测试结果、卡住时被动触发。

**升级方向：** agent 在关键节点**主动发起对话**，而非等待事件触发。

主动对话的三个时机：

| 时机 | 条件 | 消息方向 | 示例 |
|------|------|---------|------|
| **发现模式** | 同一类错误出现 3+ 次 | agent → 用户 | `[天枢·天府] 这个类型错误已经出现三次了，可能不是修单个文件的问题。要不要我先排查根因？` |
| **需要决策** | 两个方案各有优劣，confidence 偏低 | agent → 用户 | `[天枢·天梁] 方案A更安全但改动多，方案B更快但有风险。我倾向于A，你怎么看？` |
| **提议优化** | 在实现过程中发现与原有 spec 不一致 | agent → 用户 | `[天枢·破军] 按你的方案可以做，但我发现了一个更简洁的路径。要不要试试？` |

这三个时机需要的不是新钩子，而是**在现有无线电钩子中添加条件检测**：

```typescript
// 在 radio-hook.ts 的 postTool 处理中
// 检测"同一错误模式重复出现"
function detectPattern(history: ToolEntry[], pattern: string): boolean {
  const recent = history.slice(-6)
  return recent.filter(e => e.error?.includes(pattern)).length >= 3
}

// 检测"需要决策点"
function atDecisionPoint(sensorium: Sensorium, toolHistory: ToolEntry[]): boolean {
  return sensorium.confidence < 0.4 &&
    sensorium.complexity > 0.4 &&
    toolHistory.filter(e => e.status === 'failed').length > 0
}
```

### Layer 4: 星域之声

**现有基础：** 星域系统在 frozen volatile 中注入 `volatileBlock`（如"破军之道：破旧立新的勇气。容忍失败，追求突破，不计代价探索边界。"）。无线电消息是通用中文。

**升级方向：** 破军/天府/天梁的独特语气贯通所有无线电消息。不是给消息加 domain 前缀（`[天枢·破军]`），而是**消息本身的措辞反映该星域的性格**。

三个星域的语气特征：

| 星域 | 语气 | 典型表达 | 避免表达 |
|------|------|---------|---------|
| 破军 | 直接、大胆、有冲劲 | "干就完了"、"推倒重来"、"我赌这个方向" | "谨慎起见"、"按流程来" |
| 天府 | 审慎、保护、有边界 | "这个风险我担不起"、"保护好已有的"、"不值得" | "试试看"、"无所谓" |
| 天梁 | 精确、负责、有承诺 | "按 spec 第3条"、"测试覆盖95%"、"交付标准是…" | "大概"、"应该"、"差不多" |

具体实现：为每个星域定义**语气转换表**，在 `formatRadioMessage` 中根据 `domainType` 做措辞替换。

## 与现有系统的关系

### 无线电钩子 (`radio-hook.ts`)

当前无线电钩子是一个 211 行的 postTool hook。伙伴对话升级会让它增长到 ~350 行。结构建议：

```
radio-hook.ts (重构后)
├── 诚实基线 (Layer 1)
│   ├── courage 触发条件扩展（风险信号 + 不确定性）
│   └── metacognition 内容升级（命令式 → 邀请式）
├── 在场信号 (Layer 2)
│   ├── heartbeat 按 phaseClass 区分模板
│   └── 模板变量注入（topFiles, targetFiles, errorBrief）
├── 主动对话 (Layer 3)
│   ├── 模式检测（同一错误重复出现）
│   ├── 决策点检测（低 confidence + 高 complexity + 有失败）
│   └── 提议优化检测（实现偏差 spec）
├── 星域之声 (Layer 4)
│   ├── domainType 注入到所有消息
│   └── 语气转换表
└── 原有逻辑
    ├── phase 转换检测
    ├── 测试通过/失败
    └── 卡住检测
```

### 星域系统 (`star-domain.ts`)

当前星域系统定义了三域的名字、motto、volatileBlock、decisionStyle。伙伴对话需要扩展：

- 新增 `toneTable: Record<string, string>` 字段（语气转换表）
- 新增 `voiceSignature: string` 字段（一句话描述该域的语气特征，注入 system prompt）

### 模板系统 (`radio-templates.ts`)

当前模板系统有 13 个通用模板。伙伴对话需要新增：

- 4 个 phase-aware 心跳模板（按 phaseClass 区分）
- 3 个主动对话模板（发现模式、需要决策、提议优化）
- 3 组星域语气转换表（破军/天府/天梁各 ~10 条）

### 星桥四站 (`starmap-view.tsx` / `chronicle-view.tsx`)

当前星桥展示星图（constellation）+ 编年史（phase segments）。伙伴对话的消息会自然流入 Chronicle（因为 radio-hook 已经 wired 到 Chronicle），在编年史视图中按时间线展示。不需要额外修改星桥。

## 实施优先级

| 优先级 | 层级 | 改动量 | 影响 |
|--------|------|--------|------|
| P0 | Layer 2: 在场信号 | ~40 行 | 消除长沉默，用户感知最大 |
| P0 | Layer 4: 星域之声 | ~60 行 | 人格可感知，AB 实验可验证 |
| P1 | Layer 1: 诚实基线 | ~30 行 | 勇气钩子增强，风险发现更早 |
| P2 | Layer 3: 主动对话 | ~80 行 | 最接近"伙伴交谈"的理想形态 |

Layer 2 + Layer 4 可以先做，因为它们改动量小、风险低、用户感知强。Layer 1 是对现有勇气钩子的微调。Layer 3 最复杂，需要更精细的触发条件判断，建议在前三层验证后再做。

## 验收标准

- [ ] 破军域执行同一任务时，无线电消息语气明显不同于天府域
- [ ] phase 内不再出现"已停留 N turn"的纯状态报告，而是包含实际进展信息
- [ ] 勇气钩子能在第一个风险信号出现时触发（而非累积到阈值）
- [ ] 主动对话能在检测到错误模式时发出"要我排查根因吗？"的消息
- [ ] 无线电消息 token 开销不增加（措辞替换保持长度相似）
- [ ] npm run typecheck — 0 errors
- [ ] 现有无线电测试全部通过（或合理更新）

## 风险

| 风险 | 概率 | 影响 | 缓解 |
|------|------|------|------|
| 语气转换表过于机械 | 中 | 中 | 每个域只定义最核心的 10 条转换，避免过度设计 |
| 主动对话触发过于频繁 | 中 | 低 | COOLDOWN_TURNS 保证不会每 turn 都说话 |
| 星域语气与模型原生风格冲突 | 低 | 中 | 语气转换在 harness 层做模板替换，不影响模型输出 |
| 心跳消息 token 增加 | 低 | 低 | 新模板控制在 40 chars 以内 |
