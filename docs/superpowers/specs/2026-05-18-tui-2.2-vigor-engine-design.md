> 日期：2026-05-18
> 状态：待审查
> 前置：StarFlow v2 闭环接线 + TUI 2.1 自适应运行时
> 灵感来源：多巴胺 RPE (Schultz 1997)、心脏窦房结 HRV、托卡马克等离子体约束、椋鸟群飞临界态

---

## 背景

### 用户需求
"架构的承载，性能、稳定性、架构工作流的流畅性，甚至我想要的是他们可以自激励的情绪"

### 当前状态
StarFlow v2 有 6 维 sensorium（momentum/pressure/confidence/complexity/freshness/stability）+ 策略计算。但系统缺乏：
- **动力感**：连续成功不会加速，意外失败不会警觉
- **流畅性**：组件各自独立接线，阶段转换生硬
- **韧性指标**：无法区分"健康的波动"和"病态的僵化"
- **优雅降级**：崩溃时是硬中断而非软着陆

### 调研交叉发现

| 来源 | 核心原理 | 工程翻译 |
|------|---------|---------|
| 多巴胺 RPE | 动机 = 预测误差，不是奖赏本身 | vigor 由"比预期好/差"驱动，不是由"成功/失败"驱动 |
| 心脏 HRV | 复杂性 = 健康，规律性 = 病态 | 监控 vigor 的变异性，过于稳定是预警 |
| 托卡马克 | 边缘先崩溃；受控不稳定 > 完美稳定 | 保护最新 context；允许小故障释放压力 |
| 椋鸟 | 临界态 = 灵敏 + 稳定；6-7 邻居够了 | 组件只需感知最相关的邻居，不需全局信息 |

## 核心设计：Vigor Engine

### 概念模型

```
                    ┌─────────────────────────────┐
                    │  Vigor Engine (第 7 维)       │
                    │                             │
  tool result ──→  │  RPE = actual - predicted   │ ──→ vigor (0-1)
                    │  tonic = EMA(success_rate)  │       │
  sensorium ───→   │  phasic = instant RPE       │       │
                    │  curiosity = info_gap       │       ↓
                    └─────────────────────────────┘  行为调节
                                                      │
                    ┌─────────────────────────────────┼──────────┐
                    │                                 │          │
                    ↓                                 ↓          ↓
              reasoningEffort                   thetaInterval   commitThreshold
              (高vigor→low)                    (高vigor→长)    (高vigor→低)
```

### 三层信号

| 层 | 名称 | 时间尺度 | 计算方式 | 功能 |
|---|------|---------|---------|------|
| 1 | **Tonic Vigor** | 分钟级 | 最近 10 次 tool call 成功率的 EMA | 设定基线活力——"环境有多友好" |
| 2 | **Phasic RPE** | 即时 | `actual_outcome - predicted_outcome` | 瞬时调节——"这次比预期好/差多少" |
| 3 | **Curiosity Drive** | turn 级 | `complexity > 0.5 && confidence < 0.4` | 信息缺口驱动探索——"我不理解但想理解" |

### Vigor 计算

```typescript
interface VigorState {
  tonic: number           // 0-1, 基线活力
  phasic: number          // -1 to +1, 瞬时 RPE
  curiosity: number       // 0-1, 信息缺口强度
  vigor: number           // 0-1, 综合活力输出
  variability: number     // 0-1, vigor 的变异性（HRV 类比）
}

function computeVigor(prev: VigorState, toolSuccess: boolean, sensorium: Sensorium): VigorState {
  // Tonic: EMA of success rate
  const tonicAlpha = 0.15
  const newTonic = tonicAlpha * (toolSuccess ? 1 : 0) + (1 - tonicAlpha) * prev.tonic

  // Phasic: RPE = actual - predicted
  const predicted = prev.tonic  // prediction = current baseline
  const actual = toolSuccess ? 1 : 0
  const newPhasic = actual - predicted  // positive = better than expected

  // Curiosity: information gap
  const newCuriosity = (sensorium.complexity > 0.5 && sensorium.confidence < 0.4)
    ? Math.min(1, sensorium.complexity - sensorium.confidence)
    : 0

  // Vigor: tonic + phasic boost + curiosity boost, clamped
  const rawVigor = newTonic + 0.3 * newPhasic + 0.2 * newCuriosity
  const newVigor = Math.max(0, Math.min(1, rawVigor))

  // Variability: rolling std of last 10 vigor values (HRV analog)
  // High variability = healthy; low variability = rigid/pathological
  const newVariability = computeRollingStd(prev, newVigor)

  return { tonic: newTonic, phasic: newPhasic, curiosity: newCuriosity, vigor: newVigor, variability: newVariability }
}
```

### Vigor → 行为映射

| Vigor 状态 | 行为效果 | 生物学类比 |
|-----------|---------|-----------|
| vigor > 0.7 | reasoningEffort → 'low'，theta interval 延长，commitThreshold 降低 | 高多巴胺 → 快速行动，少犹豫 |
| vigor 0.3-0.7 | 正常模式，由 sensorium 其他维度决定 | 基线状态 |
| vigor < 0.3 | reasoningEffort → 'high'，theta interval 缩短，commitThreshold 升高 | 低多巴胺 → 谨慎，多验证 |
| phasic < -0.5 | 触发策略回退（类似负 RPE 的"警觉"） | 意外失败 → 停下来重新评估 |
| curiosity > 0.6 | 增加 explorationBreadth，主动读取相关文件 | 好奇心驱动探索 |
| variability < 0.1 | **病态预警**：行为过于规律，可能即将僵化 | HRV 过低 = 心脏病前兆 |

## 吸收特征 B：HRV 健康监控

### 原理
心脏的 HRV（心率变异性）是健康指标。过于规律的心率是病态信号。同理，agent 行为的变异性是韧性指标。

### 实现

```typescript
function detectRigidity(vigorHistory: number[], windowSize = 10): boolean {
  if (vigorHistory.length < windowSize) return false
  const recent = vigorHistory.slice(-windowSize)
  const std = computeStd(recent)
  return std < 0.05  // vigor 几乎不变 = 僵化预警
}
```

**触发动作**：当 rigidity 检测为 true 时：
1. 在 sensorium.jsonl 中标记 `rigidity_warning: true`
2. 下一次 dissipative kick 的阈值降低（更容易触发突破）
3. 注入轻微随机性到 theta interval（±1 的抖动）

### 生物学对应
- 健康心脏：HRV 呈 1/f 粉红噪声分形
- 病态心脏：HRV 趋向白噪声或纯周期
- Agent 健康：vigor 有结构化波动（跟随任务节奏）
- Agent 病态：vigor 恒定不变（系统失去响应性）

## 吸收特征 C：边缘保护 + 软着陆

### 边缘保护原则（Greenwald 启发）

**核心洞察**：系统崩溃由最薄弱的边缘层决定，不是总容量。

**实现**：当 pressure > 0.7 时，保护策略从"均匀压缩"切换为"边缘优先"：
- 最近 3 轮对话的 context 不压缩（边缘保护）
- 更早的 context 激进压缩（核心可以承受）
- 用户原始请求永远不压缩（类似 q=1 面的保护）

### 软着陆（MGI 启发）

**核心洞察**：崩溃不可避免时，控制崩溃方式比试图阻止更安全。

**实现**：当 pressure > 0.9 时，触发"软着陆序列"：
1. 将当前任务状态写入 `.rivet/checkpoint.json`
2. 将关键 context 摘要写入 stigmergy（deposit signal: 'session-handoff'）
3. 通知用户："上下文即将饱和，建议开启新 session。关键状态已保存。"
4. 如果用户继续，执行激进压缩但保留 checkpoint 引用

### ELM 微释放（受控不稳定）

**核心洞察**：小故障是健康的压力释放。消除所有波动反而导致更大灾难。

**实现**：不再试图让每次 tool call 都成功。当 vigor > 0.8 持续 5+ turns 时：
- 这是"过于顺利"的信号
- 系统可能在积累隐性技术债
- 主动触发一次 theta check（即使 interval 未到）
- 如果发现问题 → 正常处理（ELM 释放了压力）
- 如果没问题 → 确认系统确实健康

## 组件协调：椋鸟规则

### 当前问题
sensorium、theta、stigmergy、kick、star-event 各自独立接线到 loop.ts。缺乏"流畅感"。

### 解决方案：拓扑邻居而非全局广播

每个组件只需感知 **最相关的 2-3 个邻居**（椋鸟的 6-7 邻居原则缩放到 5 个组件）：

```
sensorium ←→ vigor（互相影响）
vigor ←→ strategy（vigor 调制策略输出）
theta ←→ vigor（vigor 影响 interval；theta 结果影响 phasic RPE）
stigmergy ←→ sensorium（pheromones 影响 freshness）
kick ←→ vigor（低 vigor 降低 kick 阈值）
```

**不需要的连接**（避免过度耦合）：
- theta 不直接影响 stigmergy
- kick 不直接影响 theta
- star-event 是只读观察者，不反向影响任何组件

### 时变领导

不同阶段，不同组件"领导"：
- **Planning 阶段**：sensorium 领导（感知驱动）
- **Implementing 阶段**：vigor 领导（活力驱动速度）
- **Testing 阶段**：theta 领导（节律驱动验证频率）
- **Stuck 阶段**：kick 领导（突破驱动重构）

## 风险与应对

| 风险 | 应对 |
|------|------|
| vigor 振荡（tonic 在阈值附近反复切换策略） | EMA 的 α=0.15 足够平滑；且 vigor→strategy 映射有宽带（0.3-0.7 不变） |
| 习惯化过度（连续成功后 RPE=0，vigor 停滞） | curiosity 维度独立于 RPE，在高 complexity 时仍能驱动探索 |
| rigidity 误报（短 session 天然 vigor 稳定） | 最少 10 个数据点才启动检测 |
| 边缘保护与现有 compact 冲突 | 边缘保护是 compact 的模式切换，不是替代 |
