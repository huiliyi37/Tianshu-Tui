# 清醒认知闭环 — 缓存安全设计

> 2026-07-11。源起 incident 20b9714e（瑶光执行计划被"90 轮未收敛"轰炸 + 上下文压力幻觉 + 催收敛致脑补）。
> 目标：模型在**清醒认知闭环**下获得有效信息、无压力完成任务；
> 硬约束：**前缀缓存是天枢最强差异化指标**（用户实测：某开发场景 1.5 亿 token 消耗 ≈ 5 元），
> 一切认知信号改动必须字节级缓存安全。

## 0. 背景修正与已落地部分

- **实证归属修正**：`docs/CVM运行时对Agent模型的实证影响.md` 里的 A/B 测试，对照变量是
  **星域信念宪法**（有/无信念注入跑同一 deepseek-v4-flash），不是 CVM 整体。CVM 是那次实验的
  运行底座。引用时须区分："信念宪法提升异议/行动意愿"是 A/B 直接结论；"CVM 有效"是间接推论。
- **W1/W2 已由并发会话落地**（commit `9eb7bb20`）：
  - W1 阶段相对轮数（`loop.ts` `phaseStartTurn`）、progressBeacons（todo 完成增量抑制 L2+、
    activePlan 阈值放宽 1.5x）、msgKey 跳过"（第 N 次…"前缀。
  - W2 efficacy 负反馈环（`advisory-bus.ts`）：同 key 会话内 delivered≥3 且 adopted=0 → 冷却
    翻倍；delivered≥6 仍零采纳 → 会话内静默；constitutional / priority≥0.8 豁免；改道卡同步抑制。
  - **W2 的判据选型正确**：incident 数据里 convergence 是 delivered≈32 / adopted=0 / **ignored=0**
    ——adopted 与 ignored 同时为零说明多数变体无 expect 谓词、从未被核销判定，`ignoredStreak`
    恒 0，习惯化静音在机制上永远够不着。只有"delivered 且零采纳"这条环拦得住无谓词 key。
  - 遗留：`loop.test.ts` throttles 测试待更新（commit message 自述）。

本设计覆盖剩余 W3/W4/W5 + 新增 W6，并给出全局缓存安全分级。

## 1. 缓存安全分级（所有改动的第一审查轴）

| 通道 | 机制 | 字节行为 | 缓存代价 |
|------|------|---------|---------|
| A：appendixDelta 块 | cognitive-mirror / tool-context 等附录 | 字节恒定入场付一次，稳态零重发；语义变化才字节变化 | ≈0（档位跳变时一次增量） |
| B：system-reminder 尾部追加 | advisory / 改道卡 / 注入消息 | 只在消息尾部追加，不重写历史 | 不碎前缀；但**永久驻留**——每条都是终身 token 房租 |
| C：磁盘 / 遥测 | sensorium.jsonl、meta、efficacy 台账 | 零 prompt 字节 | 0 |
| 禁区 | 重写 frozenBase / volatileBlock、user 边界前插入、工具定义热改 | 前缀整段 miss | 单次最高 ~19 万 token 重建（见 2026-07-06 frozen 快照事故） |

设计纪律：
1. 高频信号走 A（量化到桶，桶变才重发）；一次性提醒走 B（且受 W2 负反馈环约束）；
   诊断数据走 C。
2. 工具集变更（新增工具定义）= 前缀一次性 miss，只允许**跟版本发布上车**（版本升级本来就换
   prompt），绝不热更。
3. static prompt 不为本设计改动一字。纪律文案放进 advisory 副本（通道 B、有生命周期）而非
   常驻 prompt。

## 2. W3 — 诊断型活动识别 + 收敛文案分流

**根因**（incident 复盘）：`turn-orchestrator.ts:976` 的"本轮已进行 12+ 次 API 调用，请收敛当前
动作并输出结论，不要继续发散" + convergence 改道卡，在证据不足时把模型推向"编个结论交差"。
三次脑补结论（compact 去重幻觉、cache-log 不存在、上下文压力紧张）都发生在催收敛之后。

**改动**：
- 新增纯函数 `classifyActivityMode(recentToolHistory, evidenceState): 'diagnostic' | 'build'`：
  近 N 轮（N=8）只读工具占比 ≥0.8 且 `filesModified=0` → diagnostic。放在
  `convergence-detector.ts` 旁，供 loop 与 turn-orchestrator 共用。
- 诊断态下两处文案分流：
  - turn-orchestrator 催收敛 → "已进行 12+ 次调用。**先用工具核实你将要写进结论的关键断言**
    （ls/grep/read 实际文件），核实完再收束。没有工具证据的推断必须标注'未核实'。"
  - convergence 改道卡（非无工具僵局变体）→ 同方向措辞，并挂
    `expect: { kind: 'verify_attempted', withinTurns: 3 }` ——诊断态"采纳"的行为签名就是
    去跑验证类工具，让这些变体进入核销闭环（配合 W2 环，采纳则续命、无效则静默）。
- **缓存标注**：通道 B，纯文案替换，字节量级不变；expect 是 readback 内部状态，零 prompt 字节。

**验证**：`convergence-detector.test.ts` 增 classifyActivityMode 边界（只读比 0.79/0.80、
filesModified 0/1）；`turn-orchestrator` 测试断言诊断态文案含"核实"不含"输出结论"。
**瑶光反证**：诊断中途小改一个文件（filesModified=1）会退回 build 文案——可接受，改动即应验证；
不为此加复杂窗口逻辑。

## 3. W4 — 镜面常驻上下文硬数据

**根因**：pressure 是 routing-only（`cognitive-ledger.ts:97-100`），模型看不到窗口占用，
"上下文压力紧张"全靠脑补（实际 34%·1M，离 70% 告警线很远）。

**改动**：
- `CognitiveLedgerInput` 增 `ctxRatio?: number`（来源 `pressureResult.ratio`，
  turn-step-producer 已在手）与 `ctxWindowLabel?: string`（'1M'/'128K'，会话内恒定）。
- `buildCognitiveMirror` 增字段：`ctx="30%·1M"`。**ratio 量化到 10% 桶**（0/10/20…90%），
  桶变才字节变——与 mirror 现有 low/mid/high 档位纪律一致（2026-07-06 appendix 字节稳定评审
  口径：量化在渲染层做，不加语义哈希）。
- 不再显示更多维度。pressure 复合值继续 routing-only——给模型的是**可引用的硬数字**，
  不是又一个需要解读的软信号。
- **缓存标注**：通道 A。会话早期 ctx 从 0%→30% 会跨 3 个桶 ≈ 3 次小增量重发；稳态长会话
  每 10% 才一次。可接受。

**验证**：cognitive-ledger 测试断言 34%→`ctx="30%·1M"`、同桶两次调用输出字节相等（`===` 级），
跨桶才变化。
**瑶光反证**：桶粒度 10% 会让模型在 69% 时仍读到 60%——但 context-pressure-hook 在 70% 有
独立告警（通道 B），镜面桶只需支撑"离告警线远近"的定性判断，不承担精确预算。

## 4. W5 — session_vitals 工具 + sensorium 默认轻量快照

**根因**：模型断言自身状态时无处取数（incident 里 cache-log 路径都找错）；sensorium 快照默认
关（`RIVET_DEBUG_TELEMETRY`），事后复盘无数据——发现 3（节流估算）至今无法证实。

**改动**：
- **sensorium 轻量快照默认开**（通道 C）：每个 turn 边界向会话目录 `sensorium.jsonl` 追加一行
  compact JSON：`{turn, sensorium 六维(2位小数), cvmOverheadRatio, throttled, advisories:{rendered,dropped,adopted}}`。
  单行 <200B，百轮会话 <20KB，IO 可忽略。`RIVET_DEBUG_TELEMETRY=1` 仍控制完整快照（含
  recall-summary 等大对象），新增 `RIVET_TELEMETRY_LITE=0` 可关轻量行。
- **`session_vitals` 工具**：只读，返回当前会话摘要——ctx 占用（精确值+窗口）、cache 命中率
  近 5 轮均值（cache-log 尾读）、sensorium 当前值+quality 标注、advisory 台账 top5
  （delivered/adopted/静默中）、guardianActivity 计数。模型在写"系统状态"类结论前有处取证。
  - **缓存标注**：新工具定义 = 前缀一次性 miss → **跟版本发布上车**（纪律 §1.2）。
    工具输出走 tool_result（通道 B 等价，尾部追加），单次 <1KB。
- static prompt 不加"断言前必须调 session_vitals"条款（违反 §1.3）；改为诊断态收敛文案（W3）
  内提一句"会话自身状态可用 session_vitals 取证"——文案随 W3 通道 B 生命周期走。

**验证**：轻量快照行 schema 测试 + 百轮体积上限断言；session_vitals 在无 cache-log 的新会话
返回 quality 标注而非编造数字（空虚真值纪律，对齐 P1b）。
**瑶光反证**：工具存在≠模型会用。不强推：W3 文案给入口，efficacy 台账天然记录"提了
session_vitals 后模型是否调用"（expect: tool_appears），两周后看采纳率再决定是否加压。

## 5. W6 — CVM 节流记账修正 + 阴阳对称（新增，发现 3）

**根因**（本次深读确认，双重缺陷）：
1. **记账高估 ~10x**：`turn-step-producer.ts:564` 每轮把 `projectionStable+ephemeral+toolCtx`
   全长计入 `recordCvmInjection`。但 appendixDelta 语义下字节恒定块**稳态零重发**，实际边际
   成本只有变化字节 + 缓存读折价。累加器又**单调不衰减**（`resetCvmOverhead` 零调用方，
   compact 后也不重置——被压缩掉的注入仍在计费）。137 轮会话按估算累计 7-14 万 token
   "名义开销"，对 1M 窗口 7-14%，越过 5% 阈值甚至 8% 硬顶。
2. **节流方向反了（阴阳失衡）**：`shouldThrottleCvm` 触发时熄灭的是**镜面/季节/vigor/toolContext**
   （通道 A，稳态近零成本的自我感知层），而 advisory/改道卡（通道 B，每条真金白银驻留）
   **照发不误**。长会话后段模型恰在最需要自察时失去镜子、同时被守护层轰炸——incident 三次
   脑补全在会话后段，与此吻合（待 W5 快照数据证实）。

**改动**：
- **增量计费**：producer 记住上轮 projection/toolCtx 字符串，`recordCvmInjection` 只计
  `变化字节数/4`（首轮全额）。与 appendixDelta"入场付一次"语义对齐。
- **compact 重置**：`compact-boundary-coordinator` 完成历史重写后调 `resetCvmOverhead()`
  ——被压缩掉的注入不再计费（它们已不在上下文里）。
- **节流次序反转**：`shouldThrottleCvm`（5%）先降级通道 B——非 constitutional advisory
  进入 2 倍冷却（复用 W2 efficacy 环的冷却设施）；镜面保留。`isCvmThrottlingCeiling`（8%）
  才熄 toolContext；镜面**任何档位不熄**（<50 token/轮 名义、稳态近零实际，是模型唯一的
  自我感知窗口）。
- **缓存标注**：全部为运行时记账逻辑（B 臂），零 prompt 字节变化。节流反转反而**减少**
  通道 B 驻留 token。

**验证**：pressure-monitor 测试——同字节两轮只计费一次；compact 后 ratio 归零；节流态断言
mirror 仍在 ledger、advisory 冷却翻倍。回归：现有 throttle 相关测试改断言方向。
**瑶光反证**：增量计费会让 overhead ratio 大幅下降，5%/8% 阈值可能从此永不触发——这是
**预期效果**而非失灵（原阈值校准的就是虚高记账）。保留阈值不动，两周后看 W5 快照里
`cvmOverheadRatio` 分布再决定是否收紧到 2%/4%。

## 7. 实施记录（2026-07-11）

W3/W4/W5/W6 全部落地（W1/W2 已由 `9eb7bb20` 先行）。`npm test` 全绿 + `tsc --noEmit` 干净。
与设计的偏差（均为实现期决策，方向不变）：

1. **W3 谓词选型**：诊断态改道卡挂的是 `tool_appears`（read_file/grep/glob/list_dir/bash,
   withinTurns 2），不是设计里写的 `verify_attempted`——后者的工具家族是
   run_tests/typecheck/lsp（构建验证），而诊断态的"核实"动作恰恰是认知型工具。
   行为签名对齐语义："无工具直接脑补结论"判 ignored，"先取证再收束"判 adopted。
2. **W6 通道 B 降级**：实现为 advisory-bus 内的隔渲染周期投递（`setOverheadThrottled`，
   等效冷却翻倍），未复用 W2 efficacy 冷却 map——后者按 key 记账，节流是全局态，
   混用会互相污染台账。豁免口径与 efficacy 环一致（constitutional/immediate/priority≥0.8）。
3. **W6 计费基线的 compact 作废**：producer 端用 `lastCompactTurn` 变化侦测 compact，
   作废增量计费基线（compact 后 appendix 全量重发，重发字节要重新入账），与
   `resetCvmOverhead()` 归零配对，否则重建成本被漏计。
4. **W4 字段形状**：`ctxWindow` 传原始 token 数（渲染层格式化为 1M/200K），
   不是设计里的预格式化 label——量化/格式化统一收在渲染层（2026-07-06 评审口径）。
5. **W5 工具层级**：session_vitals 注册在 EXTENDED 层（bootstrap interactive 装配），
   不进 kernel default-registry——kernel budget ≤26 是硬约束。主控与 TUI 均可用，
   worker 子会话无 runtime 挂接时工具返回显式"不可用"而非报错。

## 8. 成功判据（两周观察窗）

- convergence 类 advisory 会话内送达次数 p95 ≤ 6（incident 基线 32）。
- 模型输出中"上下文/窗口"相关断言 100% 可溯源到 mirror ctx 字段或 session_vitals 输出
  （抽样人工核）。
- 缓存命中率不下降（cache-log hitRate 周均值对比）；appendix 重发字节量不升。
- W5 快照回答：长会话 `cvmOverheadRatio` 修正后分布、throttle 触发率、镜面存活率。
