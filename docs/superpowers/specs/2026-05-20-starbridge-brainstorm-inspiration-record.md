# 深度头脑风暴灵感资产 — 2026-05-20 终端 Agent 可观测性

> 本文档记录完整的创意探索过程，作为 Rivet 项目的核心设计资产。
> 灵感可能在当前方案中未被使用，但在未来的迭代中可能被激活。

---

## Session 概况

- **议题**：面向未来的终端引擎——agent 自主执行时，用户如何感知状态？
- **约束**：不局限于"右侧面板"，需要跨越性灵感
- **Scout 配置**：3 技术 + 2 跨域 + 1 反证 = 6 个 scout
- **三轮结果**：4 个方案 → 1 灭绝 2 降级 → 星桥四站位 + 氛围增强

### Scout 3：终端技术边界

| 技术 | 能力 | 限制 | 对设计的影响 |
|------|------|------|------------|
| Ink 6 flexbox | 完整 flexbox，百分比宽高，响应式 | 无 position:fixed，z-index 脆弱 | 分栏可行，固定元素需手动 |
| Braille patterns | 8x 分辨率，成熟库（drawille） | 需要等宽字体支持完整 Unicode | 星座图 + sparklines 可行 |
| Sixel/Kitty images | WezTerm 支持全部三协议 | 终端兼容性参差，需检测 | 远期增强，非核心依赖 |
| BEL 字符 | 跨平台声音通知 | 用户可能关了声音 | 作为可选 Layer 0 信号 |
| 24bit 色 | 大多数现代终端支持 | 某些 SSH/tmux 配置不支持 | 氛围色温 graceful degradation |

### 反证 Scout：被杀死的假设

| 假设 | 反证 | 我们的回应 |
|------|------|-----------|
| "开发者在终端用外周视觉" | 终端是密集文本，外周视觉不适用 | 改用色温（整个视觉场变化）而非小元素 |
| "环境 UI 有稳定的中间态" | 要么被忽略要么分散注意力 | 按需切换（模式 2/3）而非始终显示 |
| "7 颗星可以外周区分" | 太多了，会模糊 | 星图是全屏模式（聚焦阅读）不是外周 |
| "开发者想要美学环境" | 很多人只要 text+diff | 默认模式 1 不变，美学是按需进入 |
| "终端感知 = 物理空间感知" | 屏幕是平面，无深度视差 | 不模拟物理空间，而是用注意力层级 |

## 核心设计洞察（可跨项目复用）

### 洞察 1：五层注意力金字塔

```
Layer 0 氛围: 不需要看就知道（声音、色温）
Layer 1 心跳: 扫一眼（持续可见的紧凑状态条）
Layer 2 全景: 按需进入的丰富视图
Layer 3 叙事: 结构化历史回顾
Layer 4 诊断: 深度分析工具
```

这不是 Rivet 特有的——任何需要人类监督自主系统的场景都可以用这个分层。

### 洞察 2：灯塔守望者模型

守望者不盯着仪表。他通过光的节奏、雾笛的声音、海浪的感觉来感知状态。只有异常才需要聚焦阅读。

映射到软件 UI：默认是环境（色温+声音），异常才弹出文字。反过来（默认文字，异常高亮）是行业惯例——但惯例是错的。

### 洞察 3：NASA 站位制

不要给用户一个包含所有信息的 dashboard。给他们一个只有一个维度的视图，和快速切换到其他维度的能力。

这解决了 "信息太多" 和 "信息太少" 的矛盾：不是调整信息量，而是让用户选择看哪个维度。

### 洞察 4：编年史 vs 实时流

实时流（scrolling text）的本质问题不是 "太快"——是 **信息没有被结构化**。50 个 tool calls 的 raw 输出是无结构的。但如果把它们分成 3-5 个 phase 段落，每个段落有标题、摘要、修改文件——这就是编年史。

编年史不是 "事后总结"。它是对同一信息的**结构化重组**。

### 洞察 5：终端是一种乐器，不是一块屏幕

终端可以发声音（BEL）、可以变色（ANSI escape）、可以渲染图案（Braille）。把它当纯文本输出设备是对它的低估。

最好的终端 UI 应该像乐器——用声音的节奏、色彩的温度、图案的变化来传达信息，而不只是排列文字。

## 未采用但值得保留的灵感碎片

### "Factorio 传送带" — 工具链可视化

Tool calls 渲染为流动的彩色 token：蓝色（read）、绿色（edit）、红色（bash）。在传送带上流过 plan→fetch→write→verify 阶段。瓶颈（连续失败）表现为堆积。

**为什么未采用**：终端渲染动态流动太复杂。但概念可以简化为传说视图中的 "工具流" 图标序列。

### "Civ VI 城市卡片" — 多 Agent 协作视图

每个 sub-agent 是一个命名卡片，显示任务、进度、风险。适用于 delegation coordinator 的多 worker 场景。

**为什么未采用**：当前焦点是单 agent 可观测性。但 Rivet 已有 sub-agent 编排系统——多 agent 视图是下一个自然方向。

### "EVE 舰队 pip" — Turn 序列色带

30-50 个 turn 渲染为一行水平色带，每个 turn 一个 pip：绿色=成功、黄色=thinking、红色=失败。在传说视图的顶部显示整个 session 的 "心电图"。

**为什么未采用**：增加了视觉复杂度。但作为传说视图的 header bar 非常优雅——Phase 2 候选。

### "易经六爻" — Agent 状态的诗意命名

Sensorium 6 维→6 爻→64 卦。每个卦有名字和卦辞。例如：高 momentum + 高 confidence + 低 complexity = ☰ 乾·刚健。这不是功能，是 **品牌**——让每个 session 有自己的 "卦象"。

**为什么未采用**：学习成本太高。但作为 `.rivet/chronicles/` 的 metadata 很有趣——"本次 session 卦象：雷火丰"。
