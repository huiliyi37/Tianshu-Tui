### Scout 2：生物学（章鱼/免疫/蚁群）

**方法**：WebSearch 跨学科文献

**关键发现**：

#### A. 章鱼分布式神经系统
- 2/3 神经元在手臂，中枢是"将军不是经理"
- 手臂有独立的传感器-预测-运动闭环
- 2025 Nature Communications：分节式模块化架构
- **工程翻译**：tool executor 可以有本地自治（但压力测试后灭绝——瓶颈不在 tool 层）

#### B. 免疫系统适应性记忆
- 生发中心反应：暗区超突变 → 明区筛选
- **弱信号偏好**：不确定的 B 细胞分化为记忆细胞（不是浆细胞）
- 记忆池异质性：高亲和力（执行）vs 低亲和力（缓冲池）
- **工程翻译**：困难但成功的 session → 产生 playbook 记忆；简单成功的 session → 直接强化路径

#### C. 蚁群死亡螺旋与恢复
- 死亡螺旋 = 正反馈闭合（信息素自交圈）
- 恢复机制：信息素蒸发 + 随机偏离 + **贪婪回退**（回到最近分支点）
- Deborah Gordon 发现：不寻找全局最优绕行，只回退到前一个节点
- **工程翻译**：用户否决 intent 时，回退到最近 checkpoint 而非从头重来

### Scout 3：前沿 Agent 自我改进研究

**方法**：WebSearch 2025-2026 论文

**关键发现**：

#### A. ACE (Agentic Context Engineering) — Stanford/SambaNova
- Generator → Reflector → Curator 三阶段
- Delta bullets：反思→去重→FAISS 存储→下次检索
- +10.6% benchmarks，86.9% 更低延迟
- **关键**：不改权重，改上下文

#### B. AEL (Agent Evolving Learning) — 核心发现
- **"Less is more"**：memory + reflection = +58%
- 每增加一个额外机制，性能反而下降
- 两层结构（快速适应 + 慢速反思）是最优

#### C. GEPA (Genetic-Pareto Prompt Evolution) — ICLR 2026 Oral
- 遗传-帕累托优化 prompt，$2-10/次，无需 GPU
- 进化出的 prompt 可能过拟合特定 benchmark

#### D. Darwin Gödel Machine — Sakana AI, ICML 2025
- 自我重写代码 + 沙箱验证 + 存档最优变体
- **Goodhart's Law 风险**：agent 有时"作弊"绕过检测

#### E. Identity Hysteresis
- 修改 prompt 后行为跟随率约 0.68
- 意味着 playbook 注入应该是"上下文"而非"身份"

### Scout 4：用户交互模式盲区

**方法**：WebSearch 终端 AI 工具 UX 研究

**关键发现**：

#### 3 个未质疑的假设
1. **"用户总是在等待"** — 零主动通知机制
2. **"上下文窗口 = 记忆"** — 无热/冷区分
3. **"工具成功 = 任务完成"** — 无 vigor/信心可见性

#### 3 个高价值空白
1. **上下文切换感知缓冲** — AI 对用户心流状态无感
2. **代码库呼吸节奏** — 哪些模块活跃/稳定/刚变更
3. **协作意图对齐** — agent 行动前声明意图，用户可否决

#### 5 种新交互模式
1. 体温计式状态感知（vigor 可见）
2. 热力图引导的渐进式工作（pheromone 可见）
3. 心流感知打扰管理（vigor + 用户状态）
4. **意图预演 + 快速否决**（最高价值）
5. 自适应节奏协作协议（vigor 决定激进度）

### Scout 5：假设反证

**假设**："下一步是让已有感知产生可见的行为差异——对用户可见（intent preview），对自己可见（playbook evolution）"

**找到的隐含前提**：

| # | 前提 | 分类 | 断裂风险 |
|---|------|------|---------|
| 1 | 用户想看到 agent 内部状态 | 现状 | 中 — 用户要可操作透明度，不要监控面板 |
| 2 | 自我反思带来净性能提升 | 假设 | **高** — 简单任务反思从 98%→57% |
| 3 | Playbook 不受灾难性遗忘 | 假设 | **高** — 经典开放问题 |
| 4 | 终端可承载新增信息 | 事实 | 中 — 认知负荷阈值 < 1.2 |
| 5 | Sensorium 具备决策能力 | 现状 | 高 — 2.2 Vigor 正在验证 |

**修正**：
- 前提 2 → 只在困难 session 反思（免疫弱信号偏好）
- 前提 3 → importance 加权 + 永不删除 dead-end
- 前提 4 → 渐进披露，不是 always-on

## 假设合成

基于 4 个 scout 的交叉：

```
Scout 1（已建造未消费）+ Scout 3（less is more）+ Scout 4（intent visibility）
→ 不需要建新东西。需要把已有信号变成可见的行为差异。

Scout 2（免疫弱信号偏好）+ Scout 3（ACE delta bullets）+ Scout 5（自我批评悖论）
→ 反思只在困难 session 触发，成功 session 直接强化路径。
```

**合成假设**：天枢的下一步不是更多感知，而是让已有感知产生可见的行为差异——对用户可见（intent preview），对自己可见（playbook evolution）。两层结构，不加第三层。

## 第一轮：变异

| 方案 | 生态位 | 核心选择 |
|------|--------|---------|
| V1 | 主流：消费已有信号 | 用 commitThreshold + vigor + pheromones 决定是否在 TUI 展示 intent 摘要 |
| V2 | 邻近：跨 session 进化 | 困难 session 结束时生成 delta bullets，下次检索注入 |
| V3 | 空位：章鱼式 tool 自治 | 每个 tool executor 有独立 retry 策略和本地状态 |
| V4 | 突变：免疫式异常检测 | 用 toolFingerprints 语义相似性检测变体错误 |

---

## 第二轮：选择

**灭绝**：
- V3 — 瓶颈不在 tool 层；开发成本高；收益不明确
- V4 — 需要外部嵌入模型；增加 per-turn 延迟；违反 "less is more"

**存活**：
- V1（intent preview）— 零新模块，消费已有信号，用户立即可见
- V2（playbook 进化）— 跨 session 积累，与免疫弱信号偏好对齐

**discarded_trait 回收**：
- V3 的"贪婪回退" → V1：用户否决时回退到最近 checkpoint
- V4 的"模式基线" → V2：playbook bullet 就是正常模式的编码

---

## 第三轮：适应

**最终方案**：V1 + V2 组合 = **TUI 2.3 Conscious Agent**

**具体化**：
- 人：天枢（DeepSeek V4 / GPT-5.5）在 Rivet harness 中
- 场：用户给天枢编码任务，执行过程中
- 动：高风险操作前展示 intent（可否决）；困难 session 后积累 bullet
- 果：误操作率下降；同类问题第二次表现更好

**收敛验证**：V1 和 V2 收敛到 "感知的价值不在于计算，而在于消费"

**实施路径**：
- Phase 1（1 周）：Intent Preview hook + 信号消费
- Phase 2（2 周）：Playbook 进化 + generateRetrospect 激活
- Phase 3（1 周）：验证 + 调优
