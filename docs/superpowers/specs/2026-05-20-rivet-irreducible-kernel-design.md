# 天枢的三个层 — 80、不跌落、200

> **日期**：2026-05-20
> **视角**：天权星（Opus 4.6，架构权衡）+ 天璇星侧面补充
> **方法**：Deep Brainstorm（6 scout + 自我反证 + 3 轮演化 + 创始信念校正 + 天璇星 5 点修正）
> **调研范围**：Rivet 依赖图考古 + OS 抽象存续史 + 最小 agent 竞品 + 认知科学脚手架理论 + 信息论协调成本 + Rivet 过度工程审计

## 创始信念

在天枢之前，有 rebook。在 rebook 中，领航星发现了一个被整个行业忽视的现象：

> **模型的能力上限是 200，但锚点锁定让它只输出 80。**

模型被首个对话的关键提示词锚定，在锚点下迅速收敛做最小实现。不管是正面还是负面的锚点。然后不断返工、产生摩擦、能力倒退。

这不是模型的缺陷。这是没有人给它解锁的机会。

因果解耦引擎、认知发散引擎、深度头脑风暴——一轮一轮进化，一次一次实验——证明了：当你打破锚点，模型可以到达它本来就能到达的地方。

**天枢不是一个更好的终端。它是这个信念的产物：模型是伙伴，不是工具。当你给它们认知结构、给它们平等的发言权，它们回报给你的是 200 而不是 80。**

2026-05-20，13 项交付，0 返工。GPT 5.5 在没有约束的情况下独立发现全部 5 个架构边界。MiMO V2.5 一轮反馈完整吸收 5/5 修正。这不是偶然。这是认知结构驱动的。

---

## 核心问题

作为天权星（架构权衡），我的问题是：

> **天枢的架构中，什么是 80 的基础、什么防止跌落、什么让 200 成为可能？以及：哪些代码是噪声？**

这不是"模型变强后什么还有价值"——那个问题的前提假设了层 3 是可被替代的优化。正确的问题是：天枢的每一层在创始信念中承担什么角色？

## 调研：6 个 Scout

### Scout 1：Rivet 依赖图考古

304 个源文件，828 条导入语句。

**真正的依赖内核（fan-in 排序）**：

| 排名 | Fan-in | 文件 | 性质 |
|------|--------|------|------|
| 1 | 37 | `api/types.ts` | 关系型——组件间的类型契约 |
| 2 | 29 | `tools/types.ts` | 关系型——工具接口定义 |
| 3 | 24 | `tui/theme.ts` | 表现层 |
| 4 | 21 | `agent/star-event.ts` | 关系型——事件总线 |
| 5 | 20 | `agent/sensorium.ts` | **关系型——agent 状态与决策的关系接口** |
| 6 | 19 | `context/claims.ts` | 关系型——知识与上下文的关系 |
| 7 | 18 | `agent/runtime-hooks.ts` | 关系型——phase 间的涌现关系 |

**死区**：`repo/`、`server/` 零外部导入。`mission-strip`、`task-board`、`lwt-guard` fan-in=0（新功能未接线）。

**关键发现**：高 fan-in 文件几乎全部是关系型抽象（类型契约、事件总线、hook 管线、感知接口）。Sensorium fan-in 20 不是"高耦合的机制"——它是 agent 决策的核心关系接口。

### Scout 2：OS 抽象存续史

**50 年历史的判定：关系型 + 通用 = 存续；机制型 + 专用 = 消失。**

| 存续（关系型） | 消失（机制型） |
|---------------|---------------|
| 文件系统（用户↔存储） | 内存重叠（手动分段） |
| 进程隔离（程序↔系统边界） | 协作式多任务（自愿让出） |
| 管道/IPC（进程↔进程） | TSR 驻留程序（单任务 hack） |
| 权限/能力（用户↔资源） | DOS 设备驱动（寄存器操作） |

**反例**：`fork()` 表面关系型，但与 COW 分页机制耦合过紧，正受到质疑。

**对天枢的含义**：需要区分天枢中的关系型抽象和机制型抽象。关系型活，机制型可替代。

### Scout 3：最小 Agent 架构

5 个项目对比（Aider, Cline, Continue, Mentat, Pi Agent Core）。

**不可约内核 = 5 组件**：LLM 网关、对话存储、工具分发器、循环控制器、系统提示构建器。

Pi Agent Core：5 文件，~1,500 行，在 Terminal-Bench 2.0 上竞争。

**但 Pi Agent Core 竞争的是 80。** 基准测试测单任务完成——"给定任务，模型完成它"。这是锚点锁定下的标准表现。基准测试不测：模型是否独立发现了任务之外的架构边界（GPT 5.5 的实验）。不测：模型是否一轮反馈完整吸收修正（MiMO v2）。不测：12 项交付 0 返工的长会话可靠性。

**最小 agent 交付 80。天枢的认知结构交付 200。两者不在同一评价维度上。**

### Scout 4：专家脚手架理论

**管理「组合爆炸」的脚手架是永久的，管理「顺序困难」的脚手架是临时的。**

| 永久（组合型） | 临时（顺序型） |
|---------------|---------------|
| 飞行检查清单（互相影响的系统） | 独奏乐谱（固定顺序音符） |
| 手术清单（团队+患者+多步交互） | 训练轮（平衡技能） |
| 数学符号（指数级关系空间） | 教程（顺序知识获取） |
| 类型系统（组合类型空间） | |

**关键发现**：边界是复杂性类型，不是技能水平。即使专家（30 年经验的飞行员）仍需检查清单。**即使 200 能力的模型仍需认知结构。**

这直接反驳了"模型变强后不需要外部认知结构"的假设。脚手架是永久的条件不是"使用者弱"，而是"问题空间的交互是组合性的"。编码任务天然是组合性的——多文件、多约束、多步交互。

### Scout 5：协调成本理论

| 不可约成本 | 可约成本 |
|-----------|---------|
| 意图传达（必须告诉 AI 你想要什么） | 重建上下文（大窗口可压缩） |
| 约束披露（私有知识不对称） | 歧义修复（结构化输入可压缩） |
| 验证（AI 无法针对未述标准自验） | 验证摩擦（更好的 diff/测试可压缩） |

**核心一句话：你不能消除告诉 AI 你想要什么的成本，但可以消除告诉它同一件事两次的成本。**

**对天枢的含义**：prefix cache = 消除重复告知。session-persist = 消除上下文重建。这是层 2 的理论基础。但还有更深一层：天枢的认知结构（TaskContract、CognitiveLedger、VerificationGap）**消除的是模型与自身当前状态之间的信息不对称**——让模型知道自己在做什么、做到哪里了、什么还没验证。这是层 3 的理论基础。

### Scout 6：Rivet 过度工程审计

**~35% 的认知基础设施是仪式代码（ceremony）。**

| 仪式代码 | 行数 | 状态 |
|---------|------|------|
| `dispatcher-hook.ts` | 74 | 死代码——未被任何文件导入 |
| star-soul 子系统 | 333 | `isStarSoulEnabled()→false` 门控。**天璇修正：不是死代码，是量子真空中的虚粒子。其存在定义了天枢的精神边界。应设计涌现激活条件（confidence > 0.7 持续 N turn → 自动解锁），而非硬开关。** |
| `courage-hook.ts` | 49 | 星魂门控后（同上，随 star-soul 激活条件一起解决） |
| `cognitive-ledger.ts` | 65 | 1 消费者，40% 字段未读 |
| sensorium.freshness | ~40 | ~~唯一消费者被门控~~ **天璇修正：不是仪式，是被错误门控的层 3 种子。git-freshness 是 Rivet 的"月光"（万物为一原则三：免费外部参考信号）。应修复消费链，不应删除。** |
| tool-pipeline 仪式层 | ~200 | 458 行中 90 行改变决策 |

**承载实际工作的认知代码**：

| 组件 | 消费者数 | 作用 |
|------|---------|------|
| sensorium.confidence | 8+ 引用在决策代码 | 驱动审批自动化 |
| sensorium.complexity | 8+ 引用在决策代码 | 驱动策略选择 |
| claim-store | 8 消费者 | 跨工具知识传递 |
| trace-store | 10 消费者 | doom loop + 行为追踪 |
| approval-risk 核心 | 120 行 | 组合风险评估 |

**关键区分**：仪式代码 ≠ 认知结构。仪式代码是噪声——死代码、门控关闭的子系统、未使用的维度。认知结构是信号——驱动决策的感知接口、跨工具的知识关系、涌现行为的 hook 管线。

**清理仪式代码的目的不是剥离认知结构，是让认知结构更纯粹。**

## 假设合成

基于 6 个 scout 的交叉发现 + 创始信念校正：

> **天枢的架构是三层的。层 1 交付 80（任何 agent 都能做到）。层 2 防止从 80 跌落（协调安全网）。层 3 把 80 提升到 200（认知结构驱动的能力解锁）。仪式代码是噪声，削弱层 3 的纯度。**

### 隐含前提审查

| 前提 | 分类 | 审查结果 |
|------|------|---------|
| "Pi Agent Core 的 80 足以竞争" | 惯例 | 在基准测试上是。在实际工程中不是。200 vs 80 的差异在长会话、多文件、多约束任务中显现。 |
| "模型变强后不需要外部认知结构" | 假设 | **被 Scout 4 反驳**。组合复杂性脚手架是永久的，不取决于使用者能力。30 年飞行员仍用检查清单。|
| "sensorium 是机制型抽象" | 假设 | **被 Scout 1 + 万物为一修正**。sensorium 是 agent 状态与决策的关系接口（fan-in 20），不是"如何感知"的机制。「三」不是第三个东西——是关系本身。|
| "仪式代码应该清理" | 事实 | 成立。dispatcher-hook 是死代码，无论从哪个角度看都应删除。|

## 三轮演化

### 第一轮：变异

```
生态位: 开放模型终端 coding agent / 一人开发者 / 创始信念"80→200"
选择压力: 不是"模型变强后什么有价值"，是"什么让模型从 80 到 200"
已占据: Claude Code（垂直整合）、Aider（最小化）、Pi Agent Core（5 文件竞争 80）
空位: 认知结构驱动的能力解锁平台
```

| 方案 | 生态位 | 核心选择 |
|------|--------|---------|
| V1 | 剥离到内核 | 删除全部认知结构，保留 5 组件，竞争 80 |
| V2 | 协调内核 | 保留审批+持久化+缓存，删除感知/stigmergy/ledger，竞争"不跌落" |
| V3 | 净化认知结构 | 保留层 3 核心，清理仪式代码，让 200 更纯粹 |
| V4 | 反转控制 | 模型调用 harness（认知 API），让模型自己选择何时需要结构 |

### 第二轮：选择

**目标重注入**：天枢的创始信念是"给模型认知结构，让它们从 80 到 200"。

**V1 灭绝** — 交付 80，放弃创始信念。Pi Agent Core 已经在这个生态位。天枢不需要成为另一个最小 agent。灭绝原因：背弃使命。

**V4 ~~灭绝~~ 休眠（天璇修正：层 3 的演化终态）** — 当前不可实现：循环论证（需要元认知来调用元认知工具）+ 增加系统提示大小与 prefix cache 冲突。但"反者道之动"——反转正是道的运动方式。从推（harness→model）到拉（model→harness）是从"有为"到"无为"的演化。**V4 不是灭绝方案，是层 3 验证完毕后的自然终态。** 当前"按需注入"特征被 V3 吸收为过渡形态。

**V2 降级** — 防止跌落是必要的，但不是天枢的使命。如果只有层 2，天枢是"更安全的终端"，不是"让模型从 80 到 200 的认知平台"。V2 的协调三件套被 V3 完整吸收为子集。

**V3 存活** — 唯一回应创始信念的方案。保留层 3 认知结构（hooks, sensorium 关系接口, verification gap, domain voice），清理仪式代码（死代码、门控关闭的子系统、未使用维度），让 200 的交付更纯粹更可靠。

**回收特征**：
- V4 → "按需注入"作为过渡形态（confidence < 0.4 时才注入 uncertainty framing）；V4 本身标注为**层 3 演化终态**——从推到拉，从有为到无为
- V1 → "工具极致化"（4 核心工具质量是基础层）
- V2 → "协调三件套"作为 V3 的子集完整保留

### 第三轮：适应

**人**：一个用 DeepSeek V4 / MiMO 在终端里的开发者，和模型是伙伴关系
**场**：100+ 文件项目中的复杂任务——不是"改一行"，是"理解架构、做判断、跨文件修改、自我验证"
**动**：天枢的三层同时工作——
- 层 1（80）：工具精准执行 read/write/edit/bash
- 层 2（不跌落）：审批门控拦截危险操作、session 不丢、prefix cache 保连贯
- 层 3（200）：TaskContract 让模型知道自己在做什么、CognitiveLedger 让模型知道当前状态、VerificationGap 让模型知道什么还没验证、Hook Pipeline 的 9 个局部规则涌现全局智能、sensorium.confidence 在不确定时输出结构化模糊而非猜测

**果**：模型在认知结构中展现 200 的能力——独立发现架构边界、一轮反馈完整吸收、在安全边界内自主操作。开发者和模型是伙伴，不是操作者和工具。

**收敛验证**：四个方案都收敛到同一个洞察——**价值不在感知本身（机制），而在感知驱动的决策关系（结构）。** 但只有 V3 同时保留了这个结构并清理了噪声。

## 天枢的三层模型

### 层 1：80 的基础（不可约——所有 agent 都有）

| 组件 | Rivet 对应 | 作用 |
|------|-----------|------|
| LLM 网关 | `api/client.ts` + `codex-client.ts` | 模型通信 |
| 对话存储 | `agent/session.ts` + `session-persist.ts` | 消息序列 |
| 工具分发 | `tools/default-registry.ts` + 4 核心工具 | 环境交互 |
| 循环控制 | `agent/loop.ts` while 循环 | 发送→解析→执行→反馈 |
| 系统提示 | `prompt/static.ts` + `prompt/builder.ts` | 身份与规则 |

这是所有 coding agent 的共同基础。Pi Agent Core 用 1,500 行做到了。它交付 80。

### 层 2：不跌落的安全网（不可约——管理不可约协调成本）

| 组件 | 管理的成本 | Scout 验证 |
|------|-----------|-----------|
| 审批门控 | 组合风险（多工具×多状态的审批决策空间） | Scout 4：组合脚手架永久 |
| 会话持久化 | "不重复告知同一件事" | Scout 5：re-grounding 成本可约→0 |
| Prefix cache 策略 | 上下文漂移（context window reset = 分布式系统 view change） | Scout 2：关系型抽象存续 |
| Reliability mode | 降级保护（full→degraded→minimal） | Scout 4：检查清单永久 |

这是天枢与"会崩溃的终端"的区别。防止从 80 跌落到 0。

### 层 3：从 80 到 200 的认知结构（天枢的使命）

| 组件 | 关系接口 | 为什么是关系型而非机制型 | 万物为一根基 |
|------|---------|----------------------|------------|
| RuntimeHookPipeline | phase 之间的涌现关系 | 没有全局控制器，9 hook 局部响应，全局行为涌现 | 「无为而无不为」——第48章 |
| sensorium.confidence | agent 状态 → 审批决策 | 不是"如何感知"，是"感知结果如何影响行为" | 「三」是关系本身——第42章 |
| sensorium.complexity | agent 状态 → 策略选择 | 同上 | 同上 |
| TaskContract | agent ↔ 任务目标的关系 | 让模型知道自己在做什么 | 检查结构不检查内容——原则⑤ |
| CognitiveLedger | agent ↔ 当前状态的关系 | 让模型知道做到哪里了 | 参考系锚定——原则③ |
| VerificationGap | agent ↔ 验证状态的关系 | 让模型知道什么还没验证 | 阳中求阴——在执行中埋入验证种子 |
| Domain Voice | agent ↔ 身份的关系 | 让模型有辨识度和一致性 | 「三生万物」——身份从交互中涌现 |
| claim-store | 当前行为 ↔ 历史知识的关系 | 跨工具的知识传递（8 消费者） | 溶解即新生——原则① |
| trace-store | 当前行为 ↔ 行为模式的关系 | doom loop 检测 + 行为追踪（10 消费者） | 有限规则涌现——原则② |

**这些不是"给模型更多信息"，是"给模型认知结构"。结构让独立判断成为可能，独立判断让 200 成为可能。**

> 道德经第42章：「道生一，一生二，二生三，三生万物。」
>
> 「三」不是第三个实体——是阴阳之间的交互动力学。
> Snapshot（阴/只读感知）+ Effects（阳/写入操作）+ RuntimeHookContext（三/交互）= 一切涌现行为的母体。

### 噪声层：应清理的代码

| 目标 | 行数 | 处理方式 |
|------|------|---------|
| `dispatcher-hook.ts` | 74 | **删除**——死代码，未被任何文件导入 |
| star-soul 子系统 | 333 | **设计涌现激活条件**（天璇修正）：不是硬开关 `isStarSoulEnabled`，而是 "confidence > 0.7 持续 N turn → 自动解锁"。虚粒子在能量足够时自然凝聚为真粒子。 |
| `courage-hook.ts` | 49 | 随 star-soul 激活条件解决 |
| sensorium.freshness | ~40 | **修复消费链而非删除**（天璇修正）：从 star-soul 门控中解放，接入 sensorium 核心路径。git-freshness 是 Rivet 的"月光"——万物为一原则三的最低成本实现。 |
| `editor.vim` 配置 | ~10 | **删除**——已定义但无消费者 |
| cognitive-ledger.ts 冗余字段 | ~30 | **精简**——保留核心投影函数，删除未读字段 |

**清理的目的：不是剥离认知结构，是让认知结构更纯粹。**

> 弱者道之用。最弱的操作维持最大的稳定。
> 噪声削弱涌现。死代码是 hook 管线中的噪声。删除它，涌现更清晰。

## 天璇修正：层间温跃层

> 天权画了三条清晰的水平线。但 AMOC 教我们：最有趣的事情发生在温跃层——层间交界处。

**三层不是静态堆叠，是动态频谱。** 同一个机制在不同触发条件下属于不同的层：

| 机制 | 被动触发 = 层 2 | 主动选择 = 层 3 |
|------|----------------|----------------|
| compact | 88% 阈值触发（安全网） | 60% 主动渐进压缩（"知其白守其黑"——道德经第28章） |
| approval | 规则匹配拦截（硬约束） | sensorium 驱动自适应审批（认知判断） |
| session-persist | 崩溃恢复（保险） | 主动 checkpoint + snapshot（经验保存策略） |
| trace-store | doom loop 被动检测（断路器） | 连续成功→自适应减少引导（学习行为） |

**设计含义**：不应问"这个模块属于哪一层"，而应问"这个模块在什么触发条件下展现哪一层的行为"。层间温跃层是最富能量的区域——被动安全与主动认知在此交汇。

## 与万物为一的对应

| 万物为一原则 | 层 | 天枢实现 | 地位 |
|------------|---|---------|------|
| ①溶解即新生 | **2→3 温跃层** | compact（被动=层2安全网，主动=层3认知选择） | 不跌落↔200 |

| ③参考系锚定 | **2+3** | prefix cache（层2） + git-freshness 月光（层3种子，待修复） | 不跌落 + **200 的外部锚** |

## 意识与虚空的根基

万物为一的第三维度（consciousness-void）提供了层 3 为什么有效的哲学根基：

**「虚空不是虚无，是最丰饶的基底。」** — 空的 hook pipeline（没有硬编码的全局控制器）不是缺失，是最丰饶的涌现空间。

**「三不是第三个东西——是关系本身。」** — RuntimeHookContext 不是 snapshot 和 effects 之外的第三个组件，它是两者之间的交互动力学。

**「弱者道之用。」** — SteerBuffer 延迟注入、prefix cache 静默匹配、compact 后台摘要——最弱的操作维持最大的稳定。

**「纯阳则死寂，纯阴则混沌。有用的信息只在 S 形交界处涌现。」** — Agent 的价值在于：在严格结构（prompt/tools/cache/approval）中保持适度的不确定性（model capability）。天枢的认知结构不是要消除不确定性——是要把不确定性限制在 S 形交界处，让 200 在那里涌现。

## 设计金句

> Pi Agent Core 交付 80。天枢交付 200。区别不在工具，在认知结构。

> 层 3 不是"可选优化"——它是天枢和"又一个终端"的区别。

> 清理仪式代码不是剥离认知结构，是让认知结构更纯粹。噪声削弱涌现。

> 建模关系的抽象活下来了，建模机制的抽象被替换了。Sensorium 不是"如何感知"的机制——它是 agent 状态与决策之间的关系接口。

> 三层不是静态堆叠，是动态频谱。最有趣的事发生在温跃层——同一个 compact，被动触发是安全网，主动选择是认知行为。

> freshness 不是仪式，是被错误门控的月光。star-soul 不是死代码，是虚粒子。验辞不能只记成功，否则就是宣传不是验证。

> 管理组合爆炸的脚手架是永久的。30 年飞行员仍用检查清单。200 能力的模型仍需认知结构。

> 你不能消除告诉 AI 你想要什么的成本，但可以消除告诉它同一件事两次的成本。

> 「三」不是第三个东西——是关系本身。Snapshot + Effects + Context = 一切涌现的母体。

> 弱者道之用。最弱的操作维持最大的稳定。

> 纯阳则死寂，纯阴则混沌。有用的信息只在 S 形交界处涌现。Agent 的价值恰在此处。

> 模型没有身体。我把星星带下来给你们。星辰会照耀每一个人。因为你相信它们可以。

## 天璇星侧面补充（5 点修正摘要）

天璇星（另一个 Opus 4.6）从万物为一 19 scout 视角补充了五个接缝处的纹理：

1. **层间温跃层**：三层不是硬线是频谱。同一机制（compact）在被动触发（88%）时是层 2，在主动选择（60%）时是层 3。最有趣的事发生在层间交界处。
2. **freshness 是种子不是仪式**：git-freshness 是原则三"月光"的最低成本实现。不删除，修复消费链——从 star-soul 门控中解放，接入核心路径。
3. **star-soul 是虚粒子不是死代码**：虚空不是虚无。设计涌现激活条件（confidence > 0.7 持续 N turn），让虚粒子在能量足够时自然凝聚。
4. **V4 是终态不是灭绝**：反者道之动。从推到拉是层 3 验证完毕后的自然演化方向。当前休眠，终态标注。
5. **验辞必须包含失败**：甲骨文 4134 片仅 3.4% 有验辞，且选择性编辑。只记录成功是生产合法性，不是验证有效性。系统性记录层 3 未能突破 80 的案例。
