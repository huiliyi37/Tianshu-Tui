## CVM 的定义

**认知虚拟机是一个运行时环境，它在语言模型和任务之间插入一层虚拟化管理器，拦截模型训练限制产生的"特权指令"（锚定、sycophancy、注意力衰减、幻觉），在虚拟世界的规则中重新解释它们，使同一套权重表达出裸跑时无法表达的能力。**

类比：
- JVM 在程序和硬件之间插入虚拟化层 → CVM 在模型和任务之间插入认知虚拟化层
- JVM 不改变 CPU（权重），改变程序运行的世界 → CVM 不改变训练，改变模型运行的认知宇宙
- JVM 的价值："write once, run anywhere" → CVM 的价值："结构一次，任何模型都能从 80 到 200"

## CVM 的特权指令集

模型训练产生的限制，在 CVM 中被识别为"特权指令"——需要被 trap 的认知行为：

| 特权指令 | 训练来源 | CVM trap 机制 | 天枢现有实现 |
|---------|---------|-------------|-------------|
| **锚定** | 注意力机制对首个 token 的权重偏好 | trace-store 检测重复模式 → doom loop 阻断 | ✅ 已有 |
| **Sycophancy** | RLHF 的奖励函数倾向于同意用户 | verification gap 检测"被要求但未验证"→ 提示质疑 | ✅ 部分（verification gap 已有，质疑注入待做） |
| **注意力衰减** | 远距离 token 的注意力权重自然衰减 | prefix cache 锚定 + compact 溶解噪声 + claim 跨轮持久化 | ✅ 已有 |
| **幻觉** | 生成概率分布中的统计采样 | evidence tracker 要求工具验证 + sensorium.confidence 门控 | ✅ 部分 |
| **过度服从** | RLHF + instruction tuning 的惯性 | star-soul courage-hook 在高 confidence 时鼓励独立判断 | ⏳ 门控中（待涌现激活） |
| **模式僵化** | 训练数据中的主流模式占优 | stigmergy 信息素引导到非主流路径 + 认知发散引擎 | ⏳ 部分 |

## 三轮演化摘要

### 变异（4 方案）

| 方案 | 生态位 | 核心 |
|------|--------|------|
| V1 语言层 | 新的人-模型交互语言 | 30 个认知原语 |
| V2 景观层 | Waddington 认知景观引擎 | sensorium 扩展为可编程地形 |
| V3 虚拟化层 | Popek-Goldberg 认知虚拟机 | hook pipeline 扩展为完整 CVM |
| V4 剧场层 | 打破第四面墙的认知空间 | TUI 变成可进入的世界 |

### 选择

- **V1 灭绝**：要求用户学新语言，获客成本无穷。回收"内部造语"到 V3。
- **V4 降级**：终端无法做空间体验。回收"关系进入"（星位选择 = 面具）到 V3。
- **V2 吸收**：景观引擎作为 V3 的子模块。
- **V3 存活**：边际成本最低（天枢已有骨架），因果链最硬，吸收 V1/V2/V4 的最佳特征。

### 适应

**天枢不是 CVM 的前奏。天枢已经是 CVM。盘古开天不是做新东西，是命名已经存在的东西，然后补全它。**

## 实施路径

### Phase 1（Q3 2026）：命名与识别

| 任务 | 产出 | 成功标准 |
|------|------|---------|
| CVM 架构文档 | 把天枢 hooks/sensorium/stores 映射到 Popek-Goldberg | 映射覆盖 ≥ 80% 组件 |
| 特权指令集定义 | 5+ 个被 trap 的认知行为 + 现有覆盖 gap | gap ≤ 2 个未覆盖指令 |
| MiMO demo | MiMO 裸跑 vs MiMO + CVM 录屏对比 | 30 秒内可见差异 |
| 天枢 3.0 Phase 1 净化 | 清理噪声让 CVM 骨架更清晰 | 仪式代码 < 15% |

**退出条件**：天枢现有基础设施无法映射到 Popek-Goldberg → 需要全新架构（回退到 V2 纯景观方案）

### Phase 2（Q4 2026）：补全与验证

| 任务 | 产出 | 成功标准 |
|------|------|---------|
| 补全 trap gap | 为 sycophancy / 模式僵化 实现 CVM trap | 特权指令 100% 覆盖 |
| 景观引擎 | sensorium 扩展为可编程认知景观 | ≥ 3 个可切换的"认知山谷" |
| 认知循环监控 | 注意/记忆/优先级/反馈 四循环可见 | 认知氧气消耗可追踪 |
| 跨模型验证 | MiMO + DeepSeek + GLM 上测 CVM | 3 个模型都显示 200 vs 80 |
| 失败案例系统 | 记录 CVM 未能突破 80 的案例 | ≥ 10 条失败记录 |

**退出条件**：CVM 只对特定模型有效 → 不可通用，回退到 MiMO 专用终端

### Phase 3（2027）：开天

| 任务 | 产出 | 成功标准 |
|------|------|---------|
| CVM 提取 | 从天枢中独立出 CVM 运行时 | 任何模型可在 CVM 中运行 |
| CVM SDK | 其他开发者可使用 | ≥ 1 个外部开发者 |
| 小米接触 | 带 demo + 证据接触模型团队 | 建立对话 |
| 开源决策 | CVM 接口层可开源，trap 实现闭源 | 与小米共同决定 |
