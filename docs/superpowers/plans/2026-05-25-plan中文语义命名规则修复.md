# /plan 中文语义命名规则修复 实现计划

> **面向 AI 代理的工作者：** 必需子技能：使用 superpowers:subagent-driven-development（推荐）或 superpowers:executing-plans 逐任务实现此计划。步骤使用复选框（`- [ ]`）语法来跟踪进度。

**目标：** 修复 `/plan` / `/write-plan` 工作流的默认文件命名策略，使计划文件名由业务语义短名生成，而不是把用户整段需求直接拼入文件名。

**架构：** 在 `src/workflows/ecosystem-workflows.ts` 中把“参数清洗”升级为“计划标题候选抽取 + 文件名长度预算 + 可读短 slug”。默认路径仍写入 `docs/superpowers/plans/`，但文件名控制在跨平台安全长度内，并在 writing-plans prompt 中明确要求 AI 按业务语义命名。测试集中覆盖英文短需求、中文短需求、超长中文叙述、显式路径覆盖和 slash command 端到端解析。

**技术栈：** Node.js 22、TypeScript strict、node:test、node:assert/strict、现有 `src/workflows/ecosystem-workflows.ts` helper。

### 任务 2：实现 `semanticPlanSlug` 与安全长度裁剪

**目标：** 用最小实现让任务 1 的测试通过，同时保留现有短英文、短中文行为。

**文件：**

- 测试：`src/workflows/__tests__/ecosystem-workflows.test.ts`

**步骤：**

- [ ] 在 `slugifyFeatureName` 后新增常量和 helper：

  ```ts
  const MAX_PLAN_SLUG_BYTES = 96

  export function semanticPlanSlug(feature: string): string {
    const normalized = feature.trim()
    if (!normalized) return 'implementation-plan'

    const lower = normalized.toLowerCase()
    const isLongNarrative = Buffer.byteLength(normalized, 'utf8') > MAX_PLAN_SLUG_BYTES || normalized.length > 48

    if (isLongNarrative) {
      if ((lower.includes('多会话') || lower.includes('并行')) && (lower.includes('设计文档') || lower.includes('天枢'))) {
        return '多会话并行开发设计文档'
      }
      if (lower.includes('plan') && (lower.includes('命名') || lower.includes('文件名'))) {
        return 'plan中文语义命名规则修复'
      }
    }

    return truncateSlugByUtf8Bytes(slugifyFeatureName(normalized), MAX_PLAN_SLUG_BYTES)
  }

  function truncateSlugByUtf8Bytes(slug: string, maxBytes: number): string {
    if (Buffer.byteLength(slug, 'utf8') <= maxBytes) return slug
    let result = ''
    for (const char of slug) {
      const next = `${result}${char}`
      if (Buffer.byteLength(next, 'utf8') > maxBytes) break
      result = next
    }
    return result.replace(/-+$/g, '') || 'implementation-plan'
  }
  ```
