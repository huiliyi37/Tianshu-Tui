## 五、风险回滚协议

## 六、关键设计决策记录

| # | 决策 | 理由 | 替代方案（被否） |
|---|------|------|-----------------|
| D1 | router.ts 不依赖 React | 可纯单元测试；未来可复用于非 Ink 前端 | 用 useReducer 内联（耦合 React） |
| D2 | overlay 层互斥 | 避免 Z 轴冲突；同时只有一个深度面板有意义 | 允许多 overlay 叠加（复杂度爆炸） |
| D3 | GlanceBar 只 1 行 | 80×24 终端下垂直空间极度稀缺 | 2 行（信息更多但挤压 chat） |
| D4 | 数字键 2/3 回收而非重映射 | 减少认知负担；palette hotkey 是更好的发现路径 | 重映射到其他功能（增加记忆负担） |
| D5 | 死表面删除而非隐藏 | 零消费者 = 维护成本 > 0 收益；git 历史可恢复 | 保留但标记 deprecated（代码腐烂） |
| D6 | GlanceBus 独立于 SurfaceRouter | 关注点分离：router 管导航，bus 管数据 | 合并到 router（职责混乱） |
| D7 | alert 不抢焦点 | dark cockpit 原则：信息自己跳出来，但不打断当前操作 | 自动弹出 cockpit（打断流） |

## 九、执行建议

**推荐执行方式**：subagent-driven-development
- Phase 1 任务 1.1-1.3 可并行派 3 个 worker
- Phase 1 任务 1.4 必须串行（依赖前三个）
- Phase 2 任务 2.1-2.2 可并行
- Phase 3 可整体派一个 worker

**每个 worker 的退出检查**：
1. `npx tsc --noEmit` 通过
2. `node --import tsx --test <涉及的测试文件>` 通过
3. 不引入新的 `console.log`
4. 不触碰 `src/prompt/` 或 `src/agent/session*.ts`
