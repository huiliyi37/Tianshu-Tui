# TUI 2.4 — Structural Maturity 实施计划

> 日期：2026-05-19
> 前置：TUI 2.3 Conscious Agent 完成 (d5eee13)
> 执行者：天枢（DeepSeek V4 / Rivet）
> 预估：8-10 小时（4 个 Phase）
> 铁律：不加新感知维度，不加新 UI 能力。只做让系统能安全继续演化的基础设施。

---

## 核心目标

从"有意识的 agent"到"能安全持续演化的 agent"。

三件事：
1. **Session Lifecycle** — 统一 session-end 行为，消除散落的 cleanup 逻辑
2. **AgentLoop 瘦身** — 提取内部 controller，让 loop.ts 回到 orchestration 职责
3. **Consciousness Telemetry** — 统一事件账本，让所有意识行为可追溯

---

## 当前问题诊断

| 问题 | 严重度 | 来源 |
|------|--------|------|
| `loop.ts` 1031 行，每次加能力都碰它 | 高 | GPT 复盘 + 2.2c retro |
| Dream 和 Playbook 是两套独立 session-end 提取，无统一生命周期 | 中 | followups #6 |

| `persistDream` 在 `main.tsx` useEffect 中，不在 hook pipeline | 低 | code review |

## 执行顺序

```
Phase 1 (postSession) → Phase 2 (loop 瘦身) → Phase 4 (test hygiene) → Phase 3 (telemetry)
```

理由：
- Phase 1 先做：Phase 2 提取时需要知道 session 边界在哪
- Phase 2 是最大风险（重构），放在 Phase 1 稳定后
- Phase 4 穿插在 Phase 2 之后：确保重构没引入回归，修复 baseline
- Phase 3 最后做：依赖 Phase 1 的 postSession 和 Phase 2 的 controller 分层

## Phase 1：Session Lifecycle

**目标**：让 session 结束成为一等生命周期事件，统一所有 session-end 行为。

### 约束

- `postSession` 必须 best-effort（不阻塞 TUI 退出）
- 保持 `postTurn` 语义不变（中间 turn 仍可触发 vigor/stigmergy）
- Dream 和 Playbook 共享 session 数据但独立执行
- hook 失败不影响其他 hook（已有 `onError` 机制）

### Task 1.4：迁移 persistDream 到 postSession hook

**新文件**：`src/agent/hooks/dream-hook.ts`

```ts
export interface DreamHookDeps {
  cwd: string
  sessionId: string
  getEvidenceState: () => EvidenceState
  getDecisions: () => string[]
  getTrajectory: () => TrajectoryEntry[]
}

export function createDreamHook(deps: DreamHookDeps): PostSessionRuntimeHook {
  return {
    phase: 'postSession',
    name: 'dream-distill',
    run() {
      const evidenceState = deps.getEvidenceState()
      const hasPassedTests = evidenceState.verifications.some(v => v.status === 'passed')
      const hasEnoughFiles = evidenceState.filesModified.size >= 3
      if (!hasPassedTests && !hasEnoughFiles) return
      persistDream(deps.cwd, {
        filesModified: [...evidenceState.filesModified],
        filesRead: [...evidenceState.filesRead],
        verifications: evidenceState.verifications,
        decisions: deps.getDecisions(),
        trajectoryEntries: deps.getTrajectory(),
        sessionId: deps.sessionId,
      })
    },
  }
}
```

**文件**：`src/main.tsx` — 删除 useEffect 中的 `persistDream` 调用，改为在 `createDefaultRuntimeHooks` 中注册 dream hook。

**验收**：Dream distillation 行为不变，但从 React 生命周期移入 hook pipeline。

## Phase 2：AgentLoop 瘦身

**目标**：把 loop.ts 从 1031 行降到 ~650 行，不改变外部行为。

### 约束

- 纯提取，不改外部接口（AgentConfig、AgentCallbacks 不变）
- 每个 controller 是 plain class，不是 hook（内部分层，不是可插拔扩展）
- 每次提取后 `npm run typecheck && npm test` 必须通过
- loop.ts 保留 orchestration 职责：turn 循环、tool dispatch、callback routing
- 提取顺序：从最独立的开始，逐步收紧

## Phase 3：Consciousness Telemetry

**目标**：统一事件账本，让所有意识行为可追溯、可复盘。

### 约束

- 不影响 prefix cache
- Writer 是 best-effort（和 telemetry-writer 同模式）
- 事件格式向前兼容（新字段 optional）
- 不替代 sensorium.jsonl，而是补充意识层事件

### Task 3.1：定义 ConsciousnessEvent schema

**新文件**：`src/agent/consciousness-events.ts`

```ts
export interface ConsciousnessEvent {
  ts: number
  turn: number
  kind: 'signal-consumed' | 'intent-shown' | 'intent-action' | 'playbook-injected' | 'playbook-stored' | 'reflection-triggered'
  detail: Record<string, unknown>
}

export interface SignalConsumedDetail {
  signals: string[]  // e.g. ['commitThreshold', 'deadEndPheromone']
  actions: string[]  // e.g. ['injectUserMessage', 'emitPhaseChange']
}

export interface IntentShownDetail {
  summary: string
  confidence: number
  warnings: string[]
}

export interface IntentActionDetail {
  action: 'continue' | 'veto' | 'alternative'
  depositedDeadEnd?: string
}

export interface PlaybookInjectedDetail {
  bulletCount: number
  keywords: string[]
}

export interface PlaybookStoredDetail {
  bulletCount: number
  lessons: string[]
}
```

## 明确排除（不做）

| 提议 | 为什么不做 |
|------|-----------|
| Intent veto rollback UX | 等真实用户反馈，当前 re-plan 够用 |
| Playbook LLM distiller | deterministic extraction 够用，加 LLM 增加延迟和成本 |
| app.tsx 瘦身 | 和 loop.ts 同时重构风险太大，留给 2.5 |
| Plugin ecosystem | 没有外部用户前做生态是空市场 |
| 新感知维度 | 铁律继续 |
| Provider routing 升级 | Physarum tracker 已够用，等多 provider 场景验证 |
