## 核心目标

从"有感知但不自知"到"有感知且自知且可被观测"。

两件事：
1. **Intent Preview** — 高风险操作前展示意图，用户可否决
2. **Playbook Evolution** — 困难 session 后积累教训，跨 session 学习

---

## Phase 2：Intent Preview

**目标**：高风险操作前展示单行意图，用户可否决。

### P2.1 — intent-preview-hook.ts

```
文件：src/agent/hooks/intent-preview-hook.ts（新建）
注册：createDefaultRuntimeHooks 中追加
阶段：preTurn（在 perception 和 kick 之后）
```

核心逻辑：

```typescript
export function shouldShowIntent(
  strategy: StrategyProfile,
  vigor: VigorState,
  pheromones: Pheromone[],
  thrashingSuggestion: string | null,
): boolean {
  if (strategy.commitThreshold > 0.8) return true
  if (vigor.phasic < -0.5) return true
  if (pheromones.some(p => p.kind === 'dead-end')) return true
  if (thrashingSuggestion === 'task_decomposition') return true
  return false
}
```

## Phase 3：Playbook Evolution

**目标**：困难 session 后积累教训，下次 session 自动检索注入。

### P3.1 — playbook.ts（纯核心）

```

```

```typescript
interface PlaybookBullet {
  id: string
  createdAt: number
  keywords: string[]
  lesson: string
  context: string
  useCount: number
  lastUsedAt: number | null
  importance: number
}

// 纯函数

function decayImportance(playbook: PlaybookBullet[], now: number): PlaybookBullet[]
function enforceCapacity(playbook: PlaybookBullet[], max?: number): PlaybookBullet[]
```

### P3.3 — playbook-reflect-hook.ts

```
文件：src/agent/hooks/playbook-reflect-hook.ts（新建）
注册：createDefaultRuntimeHooks
阶段：postTurn（session 最后一个 turn 结束时）
```

触发条件：

```typescript
function shouldReflect(vigor: VigorState, sensorium: Sensorium, doomLevel: string): boolean {
  if (vigor.variability > 0.3) return true      // 困难 session
  if (sensorium.stability < 0.5) return true    // 系统性问题
  if (doomLevel !== 'none') return true          // doom loop 触发过
  return false
}
// 关键：vigor.variability < 0.15 时绝不反思（自我批评悖论防御）
```

流程：
1. `shouldReflect()` → true
2. 调用 `generateRetrospect()`（C5 已激活）
3. `extractBullets(report)` → 1-3 条 bullet
4. `deduplicateBullets()` → 合并相似
5. `playbook.addBullets()` → 写入 .rivet/playbook.jsonl

### P3.5 — 防灾难性遗忘

| 机制 | 实现位置 |
|------|---------|
| `useCount` 递增 | `PlaybookStore.recordUsage()` |
| `importance` 衰减 | `decayImportance()` — 每次 load 时执行 |
| 去重合并 | `deduplicateBullets()` — 关键词 Jaccard > 0.6 合并 |
| 上限 50 条 | `enforceCapacity()` — 淘汰 importance 最低 |
| dead-end 永不删除 | `enforceCapacity()` 中 skip kind === 'dead-end' |

**测试**：
- `shouldReflect` 在 variability < 0.15 时返回 false
- `shouldReflect` 在 variability > 0.3 时返回 true
- `extractBullets` 从 retrospect 报告中提取 1-3 条
- `deduplicateBullets` 合并相似 bullet（importance 叠加）
- `matchBullets` 按关键词匹配 top-3
- `enforceCapacity` 保留 dead-end，淘汰低 importance
- 端到端：模拟困难 session → 反思 → 存储 → 下次检索

**commit**：`feat(2.3): playbook evolution — cross-session learning from difficult sessions`

## 执行顺序与依赖

```
Phase 1 (信号消费)
  └── P1.1-P1.3: signal-consumer-hook.ts
       ↓
Phase 2 (Intent Preview)
  ├── P2.1: intent-preview-hook.ts (依赖 P1 的 shouldShowIntent 逻辑)
  ├── P2.2: AgentCallbacks 扩展
  ├── P2.3: TUI 渲染
  └── P2.4: 否决回退
       ↓
Phase 3 (Playbook)
  ├── P3.1: playbook.ts 纯核心 (独立，可与 P2 并行)
  ├── P3.2: playbook-store.ts
  ├── P3.3: playbook-reflect-hook.ts (依赖 P3.1 + P3.2)
  ├── P3.4: volatile.ts 注入 (依赖 P3.2)
```

**建议执行路径**：P1 → P3.1 → P2 → P3.2-P3.5

理由：P3.1 是纯函数，可以在 P2 的 TUI 交互设计之前先写好测试。P2 涉及 async callback 和 TUI 渲染，复杂度最高，放中间让前后都有稳定基础。

## 风险提醒

| 风险 | 应对 |
|------|------|
| Intent 阻塞 agent loop | onIntentPreview 设 5s 超时，超时自动 continue |
| extractBullets 从 retrospect 提取不准 | 用正则匹配"根因"和"建议"section，不用 LLM |
| Playbook 注入增加 prompt 长度 | 最多 3 条 × 100 字 = 300 字，可忽略 |
| postTurn 时机不对（session 可能被 abort） | 在 AgentLoop.cleanup() 中也触发反思检查 |
| VolatileContext 字段膨胀 | playbookLessons 是可选字段，不影响现有 |

## 给天枢的执行建议

1. **先读设计文档**：`docs/superpowers/specs/2026-05-18-tui-2.3-conscious-agent-design.md`
2. **遵循规约**：`pure core → hook wrapper → runtime registration → telemetry → behavior`
3. **P3.1 先行**：playbook.ts 是纯函数，最适合 TDD，先写测试再实现
4. **P2 最复杂**：涉及 async callback + TUI 交互 + checkpoint rollback，需要仔细设计
5. **不要过度设计**：extractBullets 用正则，不用 LLM；matchBullets 用关键词 Jaccard，不用 embedding
6. **停止条件**：核心闭环 + 测试通过 + 遥测可观测 → 停止。不要加额外机制。
