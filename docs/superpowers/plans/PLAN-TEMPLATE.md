# Plan Template（精简版）

> 供 AI agent 创建实现计划时参考。比旧版去掉：逐步骤 TDD 仪式、完整代码片段、类型签名对照表——这些是执行时的活，不是计划的活。

## 必须保留的结构

```markdown
# [功能名称] 实现计划

> **面向 AI 代理：** 使用 subagent-driven-development（推荐）或 executing-plans 逐任务实现。

**目标：** [一句话]

**架构：** [2-3 句关键设计决策和理由]

**技术栈：** [语言/框架/测试]

---

## Scope Check

[这个改动跨不跨子系统？跨就拆成独立 plan。列出明确的不做范围。]

---

## 调研背书

[仅列需要改行为的函数/模块，不列新增文件。每条写：当前行为 → 改后行为 → 为什么安全。]

---

## 任务

### 任务 N：[短名]

**文件：** `exact/path.ts`（改什么）、`exact/path.test.ts`（测什么）

**做什么：** [2-4 句话描述改动，给实现者足够上下文但不写完整代码]

- [ ] 步骤描述（每步一个操作，不写 TDD 仪式）

---

## 验证

```bash
npx tsc --noEmit
npx tsx --test src/模块/__tests__/相关.test.ts
```

---

## 自检

- [需求1] → 任务X 覆盖
- 无 TODO/待定/后续实现
```

## 去掉的东西（为什么）

| 去掉 | 理由 |
|------|------|
| 逐步骤「写失败测试→运行→实现→运行→commit」 | TDD 是执行纪律，写在计划里是噪音。执行 agent 自己知道要 TDD |
| 完整代码片段 | 计划不需要。一行描述 + 文件路径足够。代码在执行时写 |
| 类型签名对照表 | 类型错误 tsc 会报。计划阶段穷举签名是过度工程 |
| `file:line-range` 精确行号 | 行号在 commit 之间会漂移。给函数名/区块描述更稳定 |

## 仍保留的（为什么）

| 保留 | 理由 |
|------|------|
| Scope Check | 防止一个 plan 越做越大，强制拆分子系统 |
| 调研背书 | 计划的最大价值：证明「我知道改动为什么安全」 |
| 精确文件路径 | 执行 agent 需要知道改哪个文件 |
| 验证命令 | 执行完跑什么来确认没坏 |
| 自检 | 最后一道关：需求和任务的映射是否完整 |
