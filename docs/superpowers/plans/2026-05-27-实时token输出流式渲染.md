# 实时 token 输出流式渲染 实现计划

> **面向 AI 代理的工作者：** 必需子技能：使用 superpowers:subagent-driven-development（推荐）或 superpowers:executing-plans 逐任务实现此计划。步骤使用复选框（`- [ ]`）语法来跟踪进度。

**目标：** 将 TUI 的文本输出从缓冲模式改为实时 token-by-token 流式渲染，让用户能够看到模型逐字生成的过程，提升交互体验和响应感知速度。

**架构：** 修改 `TurnStreamController` 在 stream 过程中实时推送 text delta，而不是缓冲到 stream 结束后再一次性推送。同时调整 TUI 端的 `BlockStreamWriter` 配置，降低缓冲阈值，实现更细粒度的文本块输出。

**技术栈：** TypeScript strict、node:test + assert/strict、现有 TurnStreamController/BlockStreamWriter/StreamOutput 组件。

---

## 1. 背景分析

### 1.1 当前实现问题

当前 TUI 的文本输出采用**缓冲模式**，存在以下问题：

1. **用户体验差**：用户在等待模型响应时，界面长时间显示"◌ Waiting for model…"，看起来像"卡住"
2. **响应感知慢**：即使模型已经开始生成文本，用户也要等到整个 stream 结束才能看到内容
3. **与主流 AI 产品体验不一致**：ChatGPT、Claude、Cursor 等产品都实现了实时 token-by-token 输出

### 1.2 当前缓冲机制

```typescript
// src/agent/turn-stream.ts
onTextDelta: (text) => {
  this.deps.appendStreamedText(text)
  turnDisplayBuffer += text  // 缓冲到 turnDisplayBuffer
},
// ...
// stream 结束后才推送
const dedupedBuffer = stripIntraTurnRepetition(turnDisplayBuffer)
input.callbacks.onTextDelta(dedupedBuffer)  // 一次性推送
```

### 1.3 业务场景

**场景 1：长代码生成**
- 用户请求生成一个复杂的函数或类
- 当前：等待 10-30 秒后一次性看到完整代码
- 期望：逐行看到代码生成过程，可以提前预览和打断

**场景 2：长文本回答**
- 用户请求详细的技术解释
- 当前：等待 5-15 秒后看到大段文本
- 期望：逐句看到文本生成，可以提前判断是否需要补充

**场景 3：调试和迭代**
- 用户请求修复 bug
- 当前：等待完整响应后才知道修复方案
- 期望：实时看到修复思路，可以提前判断方向是否正确

## 2. 技术方案

### 2.1 方案概述

**核心改动**：
1. `TurnStreamController`：在 stream 过程中实时推送 text delta，而不是缓冲到结束
2. `BlockStreamWriter`：降低缓冲阈值，实现更细粒度的文本块输出
3. 去重逻辑：保留跨 turn 去重，但移除 intra-turn 缓冲去重

### 2.2 详细设计

#### 2.2.1 TurnStreamController 改动

```typescript
// src/agent/turn-stream.ts
onTextDelta: (text) => {
  this.deps.appendStreamedText(text)
  if (this.deps.getStreamedTextLength() - this.deps.getLastPrewarmAt() >= 500) {
    this.deps.setLastPrewarmAt(this.deps.getStreamedTextLength())
    this.deps.maybePrewarm(text)
  }
  // 实时推送 text delta
  input.callbacks.onTextDelta(text)
},
```

**移除缓冲逻辑**：
```typescript
// 移除以下代码
let turnDisplayBuffer = ''
// ...
turnDisplayBuffer += text
// ...
const dedupedBuffer = stripIntraTurnRepetition(turnDisplayBuffer)
const nextFingerprint = displayTextFingerprint(dedupedBuffer)
if (dedupedBuffer && (isPromotedReasoning || nextFingerprint !== input.lastTurnTextFingerprint)) {
  input.callbacks.onTextDelta(dedupedBuffer)
}
```

**保留跨 turn 去重**：
```typescript
// 在 stream 结束后，记录 fingerprint 用于下一轮去重
const nextFingerprint = displayTextFingerprint(this.deps.getStreamedTextLength() > 0 ? 'streamed' : '')
```

#### 2.2.2 BlockStreamWriter 配置调整

```typescript
// src/tui/block-stream-writer.ts
const DEFAULT_CONFIG: BlockStreamConfig = {
  minChars: 20,      // 从 100 降低到 20
  maxChars: 200,     // 从 600 降低到 200
  idleMs: 100,       // 从 500 降低到 100
  maxBufferSize: 64 * 1024,
}
```

#### 2.2.3 StreamOutput 渲染优化

```typescript
// src/tui/stream.tsx
// 保持现有逻辑，但增加实时渲染优化
const textWithCursor = isStreaming ? text + '▊' : text

// 流式渲染时使用纯文本，避免 markdown 解析问题
{isStreaming ? (
  <Text>{textWithCursor}</Text>
) : (
  <Markdown text={textWithCursor} />
)}
```

### 2.3 去重策略调整

**当前策略**：
- intra-turn 去重：`stripIntraTurnRepetition(turnDisplayBuffer)`
- 跨 turn 去重：`lastTurnTextFingerprint`

**新策略**：
- 移除 intra-turn 去重（因为不再缓冲）
- 保留跨 turn 去重（防止重复推送相同内容）
- 增加增量去重：只推送新增的文本部分

## 5. 风险评估

### 5.1 性能风险

**风险**：频繁的文本更新可能导致 TUI 渲染性能下降。

**缓解措施**：
1. 保留 `BlockStreamWriter` 的缓冲机制，只是降低阈值
2. 使用 `memo` 优化 `StreamOutput` 组件
3. 监控渲染帧率，必要时调整缓冲配置

### 5.2 去重风险

**风险**：移除 intra-turn 去重后，可能出现重复文本。

**缓解措施**：
1. 保留跨 turn 去重（`lastTurnTextFingerprint`）
2. 增加增量去重：只推送新增的文本部分
3. 在测试中覆盖重复文本场景

### 5.3 Markdown 渲染风险

**风险**：流式渲染时，不完整的 markdown 可能导致渲染错误。

**缓解措施**：
1. 流式渲染时使用纯文本，不解析 markdown
2. stream 结束后再解析 markdown
3. 在测试中覆盖不完整的 markdown 场景
