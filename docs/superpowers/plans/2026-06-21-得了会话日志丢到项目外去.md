# 会话日志移出项目目录 实现计划

> **面向 AI 代理：** 使用 subagent-driven-development（推荐）或 executing-plans 逐任务实现。

**目标：** 将会话日志默认存储路径从 `<cwd>/.rivet/sessions/` 移到 `~/.rivet/sessions/<project-slug>/`，使 `glob`/`grep` 等尊重 `.gitignore` 的工具不再对 agent 自身日志失明。

**架构：** 修改 `getSessionDir()` 为唯一路径解析入口并导出，将所有硬编码 `join(cwd, '.rivet', 'sessions')` 替换为调用该函数。新默认路径为 `~/.rivet/sessions/<cwd-slug>`，保持通过 `RIVET_SESSION_DIR` 环境变量覆盖的能力。`.gitignore` 中删除 `.rivet/sessions/` 条目（不再存在于项目内），无需迁移已有数据（历史会话保留在原位，新会话写入新路径）。

**技术栈：** TypeScript strict, Node.js 22, `node:test` + `node:assert/strict`

---

## 问题根因

```
glob/grep → .gitignore 过滤 → .rivet/sessions/ 被排除 → agent 找不到自己的日志
```

`getSessionDir()` 返回 `<cwd>/.rivet/sessions/`，该路径在 `.gitignore` 第 35 行被忽略。`glob` 和 `grep` 是 agent 最主要的文件发现工具，它们尊重 `.gitignore`，导致 agent 的"眼睛"在找自己运维数据时完全失明。`read_file` 拼显式路径可以穿透 `.gitignore`，但 agent 需要先知道路径才能拼——鸡生蛋问题。

## 波及范围

| 文件 | 当前行为 | 改动 |
|------|---------|------|
| `src/agent/session-persist.ts` | `getSessionDir()` 未导出，默认 `join(cwd, '.rivet', 'sessions')` | **导出 `getSessionDir()`**，默认改为 `~/.rivet/sessions/<slug>` |
| `src/bootstrap.ts:322` | 硬编码 `join(cwd, '.rivet', 'sessions')` | 替换为 `getSessionDir(cwd)` |

## 任务列表

### Task 1: 导出 `getSessionDir()` 并改为全局路径

**文件：** `src/agent/session-persist.ts`

**当前代码（第 61-63 行）：**
```typescript
function getSessionDir(cwd: string): string {
  return process.env.RIVET_SESSION_DIR ?? join(cwd, '.rivet', 'sessions')
}
```

**改为：**
```typescript
import { createHash } from 'node:crypto'
import { homedir } from 'node:os'

function projectSlug(cwd: string): string {
  return createHash('sha256').update(cwd).digest('hex').slice(0, 12)
}

export function getSessionDir(cwd: string): string {
  return process.env.RIVET_SESSION_DIR ?? join(homedir(), '.rivet', 'sessions', projectSlug(cwd))
}
```

**验证：**

**预期：** typecheck 通过，session-persist 测试通过（测试通过 `RIVET_SESSION_DIR` 设置临时目录，不依赖默认路径）。

## 不改什么

- `RIVET_SESSION_DIR` 环境变量行为——仍然作为覆盖手段，优先级最高
- `.rivet/artifacts/` — `ArtifactStore` 有独立的路径构造链，与 session dir 无关
- `.rivet/playbook.jsonl`、`.rivet/knowledge/memory.jsonl`、`.rivet/cache-log.jsonl` — 这些是项目级持久化数据，应留在项目内。它们不阻塞 `glob`/`grep` 对 session 的发现（只迁移 sessions 后，这些路径仍在 `.gitignore` 中但不影响 session 查找）
- 已有 session 数据迁移 — 旧 session 留在 `<cwd>/.rivet/sessions/` 不动。`SessionPersist.listSessions()` 只列出新路径下的 session，历史 session 仍可通过 `read_file` 显式路径访问

## 安全不变量

1. `getSessionDir()` 必须始终返回有效路径——`~/.rivet/sessions/<slug>` 在首次调用时由 `ensureDir()` 自动创建
2. `RIVET_SESSION_DIR` 环境变量覆盖逻辑不变——测试通过该变量注入临时目录，生产环境按需覆盖
3. 多个项目使用不同的 `<slug>` → session 隔离不退化
4. `.gitignore` 删除 `.rivet/sessions/` 后，若项目内仍有遗留的 `.rivet/sessions/` 目录，`git status` 会显示 untracked——需确认用户是否在意

## 设计决策记录

| 决策 | 选项 | 选择 | 理由 |
|------|------|------|------|
| 全局路径格式 | `~/.rivet/sessions/` (flat) vs `~/.rivet/sessions/<slug>` (namespaced) | `<slug>` | 多个项目同时运行需要 session 隔离 |
| slug 算法 | `basename(cwd)` vs `sha256(cwd)` (12 hex) | sha256 | basename 在不同机器上有同名项目会冲突 |
| 是否迁移旧 session | 迁移 vs 不动 | 不动 | 迁移增加复杂度且 session 有时间衰减性；旧 session 仍可通过显式路径访问 |
| 其他 `.rivet/` 子目录 | 全迁 vs 只迁 sessions | 只迁 sessions | playbook / knowledge / meridian 是项目级数据，应留在项目内；artifacts 独立路径链 |
