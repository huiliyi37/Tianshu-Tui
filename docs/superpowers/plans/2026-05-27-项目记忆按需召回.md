# 项目记忆按需召回 实现计划

> **面向 AI 代理的工作者：** 必需子技能：使用 superpowers:subagent-driven-development（推荐）或 superpowers:executing-plans 逐任务实现此计划。步骤使用复选框（`- [ ]`）语法来跟踪进度。

**目标：** 将 `.rivet/knowledge/project-memory.md` 从默认 prompt 注入改为仅通过 `recall` 按需检索，降低 prefix cache 漂移和低相关上下文噪音。

**架构：** `volatile.ts` 不再读取或渲染 `<project-memory>`，`volatile-snapshot.ts` 不再启动时读取 `.rivet/knowledge/*.md`。`recall.ts` 保留项目知识搜索路径，作为唯一默认访问入口；测试锁定“知识不进 prompt、但 recall 可检索”的契约。

**技术栈：** TypeScript strict、node:test + assert/strict、现有 PromptEngine/volatile context、Recall tool、`.rivet/knowledge/*.md` 文件知识库。

---

## 1. Scope check

本计划只处理 **project-memory 注入策略**：

- 移除 prompt 层的 `.rivet/knowledge/*.md` 自动读取与 `<project-memory>` 注入。
- 保留 `recall` 工具对 `.rivet/knowledge/*.md` 的关键词检索。
- 更新测试，防止以后恢复默认注入。

不在本计划中处理：

- `src/agent/dream.ts` 写入门槛。该机制已由 curated memory gate 单独处理。
- `.rivet/knowledge/project-memory.md` 当前内容策展。该文件已单独改为 curated 格式。
- `recall` 语义检索、向量检索、BM25、RRF 等检索增强。
- `.rivet/knowledge/*.md` 文件格式迁移。
- Prompt static/system prompt 改动。避免触发更大范围 prefix cache 变化。

独立子系统判断：

| 子系统 | 是否纳入 | 原因 |
|---|---:|---|
| Prompt volatile 注入 | 是 | 当前 `<project-memory>` 注入点在这里 |
| Snapshot 启动读取 | 是 | `_knowledgeSnapshot` 是注入链路的一部分 |
| Recall tool | 是 | 需要验证仍可检索项目知识 |
| Dream 写入 | 否 | 写入门槛是独立任务，避免混合改动 |
| 文档/brief 索引 | 否 | 本计划只锁定运行时契约 |

结论：无需拆分成多个计划；本计划是一个独立、可测试的 prompt hygiene 改动。
