# 性能优化实现计划

> **状态：✅ 已全部实施** — 大型代码块懒加载 + markdown 渲染优化

**目标：** 优化 TUI 性能，包括 Markdown 渲染懒加载、组件重渲染优化和历史记录分页加载

**架构：** 通过三个独立但互补的优化策略提升性能：1) 对大型代码块实现懒加载，减少初始渲染开销；2) 使用 React.memo 和 useMemo 减少不必要的组件重渲染；3) 对历史记录实现分页加载，降低内存占用和渲染压力。

**技术栈：** React.memo, useMemo, useCallback, 虚拟化滚动, 懒加载

---

## 1. 范围检查

本计划涉及三个独立的优化方向，每个方向都可以独立实现和测试：
- Markdown 渲染优化（`src/tui/markdown-render.tsx`）
- 组件重渲染优化（多个 TUI 组件文件）
- 历史记录分页（`src/tui/app.tsx`, `src/tui/ring-buffer.ts`）

建议按顺序实现，每个优化完成后进行验证。

## 3. 调研背书

### 3.1 Markdown 渲染优化
**当前实现分析：**
- `markdown-render.tsx:422-460` - `renderCodeBlock` 函数立即渲染所有代码行
- 代码块没有行数限制，大型代码块（>100行）会导致性能问题
- 已使用 `memo` 和 `useMemo` 优化整体组件

**调用方：**
- `renderBlock` 函数（`markdown-render.tsx:470`）调用 `renderCodeBlock`
- `Markdown` 组件（`markdown-render.tsx:509`）渲染所有块

**边缘情况风险：**
- 语法高亮需要完整代码内容
- 用户可能需要复制代码
- 需要保持与现有样式的兼容性

### 3.2 组件重渲染优化
**当前实现分析：**
- 多个组件已使用 `memo`：`ToolCard`, `SystemMessage`, `AssistantMessage` 等
- `app.tsx` 中使用了 `useCallback` 和 `useMemo`
- 存在一些潜在的优化点

**调用方：**
- `renderStaticEntry` 函数（`render-entry.tsx:25`）渲染所有静态条目
- `App` 组件（`app.tsx:1196`）渲染历史记录

**边缘情况风险：**
- 过度优化可能导致代码复杂化
- 需要平衡性能和代码可维护性

### 3.3 历史记录分页
**当前实现分析：**
- `HISTORY_MAX_ITEMS = 1000`（`app.tsx:105`）
- 使用 `RingBuffer` 存储历史记录
- `Static` 组件渲染所有项目

**调用方：**
- `historyBufferRef` 存储历史记录
- `historyItems` 计算当前项目
- `Static` 组件渲染所有项目

**边缘情况风险：**
- 分页可能影响用户体验
- 需要处理滚动位置
- 需要保持与现有功能的兼容性
