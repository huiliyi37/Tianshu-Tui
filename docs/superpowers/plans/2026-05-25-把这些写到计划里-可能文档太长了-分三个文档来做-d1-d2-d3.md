> **面向 AI 代理的工作者：** 必需子技能：使用 superpowers:subagent-driven-development（推荐）或 superpowers:executing-plans 逐任务实现此计划。步骤使用复选框（`- [ ]`）语法来跟踪进度。

**目标：** 把本轮关于上下文入口治理、prefix cache 稳定、流程交付卫生的工程建议拆成 D1/D2/D3 三份短业务语义计划文档，便于独立实现、独立验证、独立提交。

**架构：** 本计划是总索引，不直接改实现代码。D1 聚焦“内容进入模型前的入口闸门”，D2 聚焦“消息构造与缓存风险审计”，D3 聚焦“运行时文件、ownership ledger、交付流程卫生”。三份子计划互相解耦，均采用 TDD、小步提交、精确文件清单。

**技术栈：** TypeScript strict、node:test、Ink/Node.js 工具系统、OpenAI-native message format、DeepSeek exact-prefix cache、Markdown implementation plans

## 1. Scope check

本需求横跨三个独立子系统，已拆成三份短业务语义计划文档：

| 文档 | 子系统 | 业务边界 | 独立性 |
|---|---|---|---|
| `docs/superpowers/plans/2026-05-25-d1-context-ingress.md` | 工具入口治理 | 文件和工具输出进入模型上下文前的分类、预览、范围读取策略 | 不修改 PromptEngine |
| `docs/superpowers/plans/2026-05-25-d2-prefix-cache-stability.md` | Prompt/cache 稳定 | 消息构造语义 helper、prefix cache 风险审计、下标断言替换 | 不改变工具行为 |
| `docs/superpowers/plans/2026-05-25-d3-agent-workflow-hygiene.md` | 流程交付卫生 | 运行时诊断文件隔离、ownership ledger 健康检查、交付报告噪音降低 | 不改变模型请求内容 |

推荐执行顺序：

1. D1：上下文入口治理 — 先减少未来工具输出进入上下文的体积。
2. D2：缓存稳定与审计 — 再把 prompt 测试和 cache audit 固化，避免后续改动误伤 prefix。
3. D3：流程与交付卫生 — 最后降低共享工作区噪音和交付误归因。
