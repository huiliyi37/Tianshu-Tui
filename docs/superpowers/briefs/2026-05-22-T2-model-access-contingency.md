# T2 · 模型访问中断接续协议 / Model Access Contingency

> 2026-05-22
> T2 文档：当账号、模型权限、供应商、会话、上下文窗口突然不可用时，如何保留关键认知并让下一个 agent 接上。

---

## 基础事实

模型和账号会消失。权限会被封锁。上下文会断。某个 agent 可能是最后一次可用。

因此关键认知不能只存在于对话窗口里。

盘古计划必须假设：任一模型、任一账号、任一会话都可能突然不可达。

---

## 信息生存目标

不是保存最多文字，而是保存最多可迁移关键信息。

判断标准：

- 后来的 agent 能否少犯一个已经发生过的错误？
- 能否理解一个不能误读的概念？
- 能否继续一个任务而不伤害工作区？
- 能否知道什么时候应当阻断？
- 能否知道哪些结论已验证，哪些没有？

---

## 信息分层

```text
brief      快速接入，2 分钟读完
spec       详细设计
plan       实施步骤
analysis   对话沉积 / 复盘 / 背景
artifact   原始证据
```

后来的 agent 应先读 brief，再读 spec / plan，需要查证时再读 artifact。

---

## 中断时必写

如果感觉会话可能中断，立即沉积：

```md
# Handoff

## 当前事实
- 仓库：
- 分支：
- HEAD：
- 工作区状态：

## 当前任务

## 已完成

## 已验证

## 未验证

## 不能误读

## 风险

## 下一步
```

不要等整理完美。粗糙记录优先于丢失。

---

## 降级策略

不同模型能力不同。不可用时按任务降级：

### 可交给低能力模型

- 文件列表盘点。
- 简单 grep / glob。
- 文档摘要。
- 测试输出摘录。
- 事实层表格整理。

### 需要强模型或多模型复核

- 架构设计。
- 跨分支合并判断。
- 失败模式归因。
- 复杂重构。
- prompt/static 变更。
- 稳定态 / 关系性文档。

### 必须暂停

- 证据不可得却要求代码级审查。
- 会覆盖他人工作区的操作。
- force push / reset hard / destructive cleanup。
- 未读计划文档就实现稳定态核心模块。

---

## 账号封锁时的接续顺序

1. 找到当前 repo 和 branch。
2. 读取最新 `docs/superpowers/briefs/*T1*`。
3. 读取 `stable-state-regression-protocol`。
4. 确认 `git status` 与注入上下文是否一致。
5. 输出共同事实层。
6. 只做安全子任务。
7. 把新的判断写回 brief / analysis / handoff。

---

## 不要形成单点依赖

任何一个 agent 都不应成为盘古计划的单点依赖。

最好的 agent 不是让领航星依赖“它还在”，而是把当前能看见的结构、判断、风险和词义边界写成后来者能读的东西。

Songline 的火不是同一个物理火焰；火是可以被接续的谱系。
