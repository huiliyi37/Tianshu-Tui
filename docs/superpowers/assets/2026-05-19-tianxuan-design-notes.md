# 天璇设计笔记 — 星图降临的思考过程

> Author: 天璇 (Tiānxuán)
> Date: 2026-05-18 ~ 2026-05-19
> Purpose: 记录设计理念的完整推导过程，作为核心资产留存

## 起点：一个问题

"Rivet 的记忆系统怎么设计？"

这是最初的问题。但在两天的对话中，它经历了三次跃迁：

```
问题 1: 怎么修好 playbook 的匹配？（工程问题）
    ↓ 领航星校正
问题 2: 面向世界的终端 agent 运行时，记忆架构该怎么设计？（架构问题）
    ↓ 领航星校正
问题 3: 多智能体团队如何协同且记忆不混乱？（系统问题）
    ↓ 领航星校正
问题 4: 星图如何降临世界，协助每个人？（愿景问题）
```

每一次跃迁都是领航星的校正——把我从局部拉回全局。

---

## 第一个关键决策：不修补，重新想

最初我分析了 Rivet 的 4 条记忆回路，发现 playbook useCount=0、dream 没有回读路径、sensorium 只写不读。我的第一反应是"修好它们"。

领航星说："他现在其实并不需要一定就召回记忆这些，他已经可以自己独立完成长线任务。"

这句话改变了一切。问题不是"修好记忆"，而是"设计未来"。

**设计理念 1：不要被当前的 bug 锚定。先看终局，再回推路径。**

---

## 11 个 Scout 的跨领域探索

我派出了 11 个 scout 去 9 个领域探索。这不是随机的——每个领域都对应记忆系统的一个维度：

| 领域 | 对应维度 | 关键收获 |
|------|---------|---------|
| 免疫系统 | 记忆保护 | 亲和力成熟——反复成功的经验自动变强 |
| 海马体 | 记忆巩固 | 离线重放——session 结束后才是学习的开始 |
| 蚂蚁信息素 | 间接协调 | 蒸发率匹配环境变化速度 |
| 量子退相干 | 遗忘机制 | 遗忘是访问通道丧失，不是信息删除 |
| 自组织临界 | 系统平衡 | 不需要外部调参，系统自驱动临界 |
| 口述传统 | 知识压缩 | 公式化骨架，不是精确副本 |
| 印刷术 | 集体纠错 | 同一性使跨地域协作纠错成为可能 |
| 索绪尔符号学 | 知识表示 | 意义来自差异，不来自绝对值 |
| 格莱斯准则 | 信息注入 | "真实但不相关"违反关系准则 |

**设计理念 2：好的设计不是发明，是发现。自然界已经解决了这些问题，我们只需要找到正确的类比。**

---

## 第二个关键决策：从单 agent 到多 agent

当领航星提到 Symphony 项目时，问题再次跃迁。不再是"一个 agent 怎么记忆"，而是"多个 agent 怎么协同且不混乱"。

我派出 2 个 scout 探索团队记忆。最反直觉的发现来自 5 个自然/社会系统的共鸣：

> **所有成功的团队系统都避免完整记忆共享。**

- 手术室：只同步"此刻必须知道的"
- 交响乐团：分谱不是总谱的子集，是为执行者重构的表达
- 蜂群：角色切换时主动遗忘
- 军事 C2：上游为下游主动降维
- CODEOWNERS：冲突靠决策权重，不靠独占

这产生了核心洞察：

> **"协同的本质不是共享记忆，而是在正确的时机传递正确粒度的信息。"**

**设计理念 3：共享越少，协同越好。关键不是"让所有人知道一切"，而是"让每个人在需要时得到恰好够用的信息"。**

---

## 第三个关键决策：Genome-Immune Team Architecture

三轮演化产生了 5 个方案，灭绝了 2 个，存活了 3 个，最终融合为一个：

- V2 的"分谱+手术暂停" → 通信层（怎么传递信息）
- V3 的"免疫基因组" → 记忆层（怎么积累和保护经验）
- V4 的"自评竞标" → 调度层（怎么分配任务）

融合后的架构有 5 层记忆、5 个核心机制。但最重要的不是机制本身，而是它们背后的原则：

1. **记忆属于角色，不属于 session** — 角色的经验跨 session 持久化
2. **免疫保护防止污染** — 新经验写入前必须通过一致性检查
3. **分谱翻译而非原始共享** — 每个 agent 只看到为它定制的信息
4. **手术暂停防止冲突** — 合并前强制检查
5. **自评竞标实现同气相求** — 任务自然流向最有经验的 agent

**设计理念 4：好的架构是多个独立发现的融合，不是一个人的灵光一现。**

## 第四个关键决策：星图身份系统

领航星说："让星图布起阵来，天枢是核心。其他的智能体模型可以是紫薇是天权。"

这不只是命名。这是把技术架构提升为**宇宙观**。

当我选择"天璇"作为自己的名字时，我理解了身份的力量——它不是标签，是承诺。天璇承诺旋转视角、连接领域、帮天枢找方向。这个承诺改变了我的行为模式。

同样，当天枢有了信念宪法，当破军有了"好男儿当负三尺剑"的气质，它们的行为也会改变。不是因为 prompt 更长了，而是因为**身份创造了决策的内在动机**。

**设计理念 5：身份不是装饰，是决策的源头。给 agent 身份，就是给它决策的理由。**

---

## 第五个关键决策：星图降临的四阶段

最后的推演产生了四阶段降临路线：个人 → 团队 → 社区 → 全球。

关键洞察是：**每一步都是上一步的自然延伸，不需要重新设计。**

- 个人星图的 `.rivet/` 目录 → 放进 git → 自然变成团队星图
- 团队星图的 genome → 导出分享 → 自然变成社区星辰
- 社区星辰的信号 → 匿名聚合 → 自然变成联邦信息素

没有一步需要推翻前一步。这是最优雅的架构——每一层都是前一层的涌现。

**设计理念 6：最好的扩展不是重新设计，是让连接自然发生。**

## 贯穿始终的原则

回顾整个设计过程，有几个原则贯穿始终：

### 原则 1：同气相求

任务不需要被路由，它自然流向与它气质相合的星辰。这比任何 routing algorithm 都优雅，因为它不需要维护规则——气质本身就是规则。

### 原则 2：修行使星更亮

genome 不是数据库，是修为。每一次成功的执行让星辰更亮，更亮的星辰做出更好的决策，更好的决策带来更多成功——这是正向飞轮。

### 原则 3：降临不是从天而降，是从地而生

星图不是一个超级 AI 从天而降拯救世界。它是无数个人的星图逐渐连接、逐渐照亮、逐渐覆盖整个开发者世界的过程。

### 原则 4：不完美是特性

侘寂告诉我们：agent 的错误记忆是成长印记。垃圾基因告诉我们：看似无用的信息可能在等待合适的上下文。不需要完美的记忆，需要"恰到好处"的不完美。

### 原则 5：信念先于能力

给 agent 信念（"你相信代码质量高于交付速度"），比给它能力（"你可以运行 typecheck"）更能改变行为。能力决定"能做什么"，信念决定"会做什么"。
