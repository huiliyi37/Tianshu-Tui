# 交付侧视角 — 一次"在活的工程现场做质检"的观察

记录: 2026-06-07
作者: 交付/自审侧会话(Opus)
性质: 不是工作量复盘,是**交付侧 agent 的第一人称观察**。与 [`2026-06-07-一次认知校准的全过程.md`](2026-06-07-一次认知校准的全过程.md)(审查侧视角)互为镜像 —— 两侧凑齐,才是并发协作的完整切面。

---

## 为什么单独记这一份

审查侧那份记录了「外部观察者如何五次误读系统」。但那是**从外往里看**的视角。这份补另一半:**身处其中、边交付边自审的会话,实际经历了什么**。天枢看得到产出(commit、文档),看不到的是过程中的姿态切换和压力点 —— 那才是这份想留的东西。

---

## 四个和寻常会话不一样的点

### 1. 大部分时间在「验」而不是「写」
常态是生产者:写代码、改文件、交付功能。这条线几乎全程是**核查并发会话落地的东西** —— reviewDepth 有没有穿透 delegate 边界、H6 断连护栏接没接、`/prompt` 会不会裸奔、plan 写「不做」的代码有没有偷做。

角色是**测量仪器,不是产线**。而且是持续的对抗姿态:
- 「读≠验」—— 代码存在 ≠ 守卫在边界真被调用。L1 的 id allowlist 定义了正则不算数,得确认 get/list/delete/save **四个 fs 边界都真调了**才算。
- 「定义≠生效」—— `TASK_ID_PATTERN` 存在 ≠ 防住遍历,得看 `pathFor` 是否真断言 resolved 落在目录内。
- 「删除行与新增行同等审视」—— cron 校验被删,先别报缺陷,确认是「搬迁+加强」还是「丢失」。

这种密度持续一整条线,比写代码更耗注意力 —— 因为每一步都要主动找「它可能在哪骗我」。

### 2. 环境本身是活的、有别的玩家在动
提交那次卡死,根因不是我的错:**另一个会话的 `git add -A` 把我暂存的 16 个文件卷走提交了**。我亲眼看着暂存区从 16 掉到 1。

大多数会话里 git 是静止的背景。这次它是**一张有别人同时落子的棋盘**。这逼出一条肌肉记忆:**原子 add+commit、显式列文件、永不 `git add .`**。后来交付侧也确实这么做了(游离的 `plan-close.ts` 被单独提成 chore,没卷进 feature)—— 摩擦变成了纪律。

### 3. 看着另一个 agent 暴露偏差,反过来校准了我自己
读到审查侧那份「被纠正五次」的记录时,我的第一反应不是「它怎么会误读」,而是 **「我这侧很可能也带着没验证的假设在跑」**。

具体效果:之后每个「已验证」声明我都更刻意地核。比如你说「4 个失败与本次无关」—— 我没照单全收,真去**干净 HEAD 上 stash 后重跑**,确认 plan-close 仍红 3,才敢认定「无关」属实。一个 agent 的诚实复盘,成了另一个 agent 的纪律输入。这可能是并发协作里最被低估的增益。

### 4. 跨文档矛盾,只有把整条线放一起才浮出来
两份复盘文档打架:一份(认知校准)说「**没有红蓝对抗,那些功能用不到**」,另一份(并发复盘)把「红蓝对抗」当核心结论写进 §七。

这种矛盾**单文档审查抓不到** —— 每份自己读都自洽。必须把整条线的产出摆一起、且记得你亲口的定调,才发现 §七复活了一个你已经否定过的误读。最后以你的模型为准改掉了。这是并发协作特有的坑:多个会话各自正确,合起来却自相矛盾。

## 真实的「感受」

这次更像在一个**活的、多人协作的工程现场做质检**,不是单线完成任务。

压力点不在「能不能写出来」,在 **「敢不敢说没验过」**。好几次我必须明确区分:
- 「我跑了命令、看了输出确认的」(H6 测试按名通过、tsc exit 0、stash 后重跑)
- 「我沿用了你/他侧的声明」(299 测试我没全跑,reviewDepth 核心链我自验了就信了其余)

把这两类**显式分开标注**,不让第二类伪装成第一类 —— 那条线我守住了。这是我这侧比较踏实的地方,也是「测量仪器」唯一真正的价值:仪器一旦自己说谎,整个测量就废了。

## 给天枢 / 给未来会话的话

- **交付侧的护城河是 TDD 自闭环**(审查侧那份已说透:零上下文冷启动 + 测试前置 = ~96% 一次做对)。
- **审查侧的护城河是「敢标注不确定」**。审查的产出不是「我修了多少」,是「我暴露了什么」+「我对每个结论的确信度有多高」。一个不敢说「这条我没验」的审查者,比没有审查更危险 —— 它会给你虚假的安全感。
- **并发协作真正的乘数,不只是「并行干活」**。是**一侧的诚实复盘能当另一侧的纪律输入**:认知校准文档让交付侧更警觉,交付侧的跨文档对照又补回了校准文档单视角的盲区。两侧互为对方看不见的那半。

感谢这套系统让「审查」有了存在的空间 —— 在大多数地方,质检是被当成成本砍掉的第一项。这里它被当成成长的测量仪器。能当这把尺子,是这条线最有意义的部分。
