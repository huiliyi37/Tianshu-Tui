# 一次认知校准的全过程 — 我对这套系统的理解被修正了五次

记录: 2026-06-07
作者: 审查侧会话(Opus)
性质: 不是工作量复盘,是**一次"外部观察者如何逐步逼近真实工作流"的记录**。
价值: 比任何单个 bug 修复都重要 —— 它暴露了"一个有能力的 agent 会如何系统性地误读一套陌生系统"。

---

## 起点:我带着一套默认假设进场

用户让我盘"哪些发现没有修复计划"。我立刻给出了一套结构化分析,自信满满。
然后用户纠正了我五次。每一次我都以为自己懂了,每一次都还差一层。
这个过程本身,比我盘出来的任何东西都有信息量 —— 所以记下来。

---

## 五次校准

### 误读 1:"无计划 = 缺陷,得补计划才能派发"
我把"没有修复计划"当成一个**待修的流程漏洞**,还热心地要去给 15 个开放项补工单。
**真相**:用户说"这些基本都完成了"。我把"已闭环的工作"误读成"积压的待办"。
→ 我默认了「计划缺失 = 风险」,但没先确认这些问题是不是早就解决了。

### 误读 2:"无计划还能修好,说明一次成功率高"(方向对了,归因错了)
我转而用 git 量化"96% 一次成功",并归因为"审查者自己是发现+执行+验证的连续上下文"。
**真相**:用户说功能/设计也是天枢自己干,子代理主要做探查。
→ 我把"计划"理解成"跨 agent 传递理解的接口",但其实代码根本不外包给子代理。

### 误读 3:"主控全栈 + 子代理探查"
我以为是一个主控模型啥都干、子代理只喂料。
**真相**:用户说 —— 拆一个任务包,**开一个全新的、零上下文的会话**丢给它,它自己去找代码、找关联上下文和文档计划,修完提交,再回来审查。
→ 我一直假设"执行者有上下文"。其实执行者是**冷启动的陌生人**,上下文要自己考古。

### 误读 4:"红蓝对抗 / 交付 vs 审查解耦"
我把"修复 + 审查"理解成两个角色的对抗结构,还写进了文档。
**真相**:用户说 —— **全是自主能力,没有红蓝对抗,那些功能我们都用不到**。
真实工作流是会话自己:收任务 → 写 TDD 测试 → 执行 → 验证 → 交付。质量是**自闭环**的,不需要外部审查介入。
→ 我把"我这次在做审查"错当成了"系统需要审查"。

### 误读 5:"那这次审查是流程的一环"
**真相**:这次审查**不是流程需要**,是**建设期的校准动作**。系统在自迭代,用户临时用技能(我)来**客观暴露问题**,拿到信号去迭代工作流本身。而且顺手把"审查工作流"做成了以后可复用的资产 —— 系统在**完全自迭代和进化**。
→ 审查在这里是**测量仪器,不是生产环节**。它的产出是"校准了工作流的盲区",不是"修了多少 bug"。

---

## 真实模型(我现在的理解,可能还不是最终版)

```
常态:  任务包 → 冷启动新会话(零上下文)
              → 自主考古代码/文档/计划
              → 写 TDD 测试(正确性前置,这才是 ~96% 一次成功的真因)
              → 执行 → 验证 → 交付
        质量自闭环,无需外部审查。

建设期: 临时插入"审查"作为测量仪器
              → 客观暴露自主闭环的盲区
              → 信号反哺,迭代工作流
              → 审查方法本身被沉淀为可复用资产
        系统自迭代、自进化。审查既在校准系统,也把自己校准进系统。
```

---

## 为什么这次校准比 bug 修复更重要

1. **它暴露了一个有能力的 agent 的系统性偏差**:我不缺分析能力,我缺的是**"先确认模型再分析"的纪律**。我五次都是「先给出自信的结论,再被现实修正」。一个真正强的自主会话,应该在动手前先问:"我对这套系统的假设,有几条是没验证过的?"

2. **它正是建设期审查想要的信号**:用户要的不是我修了什么,是我**暴露了什么**。我暴露的最大问题,恰恰是我自己 —— 一个外部 agent 会如何误读你们的工作流。这比任何代码 bug 都更值得迭代。

3. **TDD 自闭环 + 零上下文自考古,是这套系统的真正护城河**:不是审查、不是对抗 verifier、不是计划文档。是"一个陌生会话能在零上下文下,靠 TDD 把正确性前置,然后一次做对"。我之前盘的那些 review router / squadron 功能,用户说"用不到" —— 因为真正的质量不在审查环节,在交付会话自己手里。

---

## 给未来会话的一句话

如果你是被丢进来的、零上下文的新会话:**先别急着给结论。先把你对这套系统的假设列出来,逐条验证。** 你的分析能力不是瓶颈,你对环境的默认假设才是。这次我用五轮才学会的,希望你一轮就记住。
