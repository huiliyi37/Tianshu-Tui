### 2. Worker Result Extraction Hardening

**关联：** 子代理（delegate_batch）在两轮 10 个 worker 中 4 个返回 blocked（JSON 截断 / 无 JSON）。

| # | 修复 | 文件 | 效果 |
|---|------|------|------|
| 1 | Repair prompt `slice(0,4000)` → `slice(-4000)` | `worker-prompts.ts` | JSON 在尾部时 repair 不再丢失 |
| 2 | `extractJsonObject` 三策略降级 | `work-order.ts` | fenced block → 平衡括号扫描 → 首末花括号 |
| 3 | `maxRetries: 1` → `2` | `work-order.ts` | 一次修复失败还有第二次机会 |
| 4 | `maxTokens: 4096` → `8192` | `work-order.ts` | 大文件 worker 输出不易截断 |

1. **Multi-Provider 是本次核心交付。** 关键理解：factory 三层参数（provider config + capabilities + runtime）分离了配置层、能力层、运行时层。
2. **Worker 硬化是本次的防御性修复。** 子代理成功率从 60% 应该能提升，`extractJsonObject` 的平衡括号扫描是关键改进。
3. **审查修复了一个 P3 bug：** `unsupported: []` 覆盖 well-known `stripParams`，已改为 `length > 0` 判断。
4. **下一步建议：** ECF Phase 5（Recall Feedback）改动量小（~50 行），可以快速完成。Multi-Provider Phase 2（OpenAIClient）是硬骨头，需要从头设计消息格式转换。
