# 思考循环问题记录

> **日期**: 2026-06-02
> **会话**: 当前会话 (51e76a8b)

## 现象

在完成 v4 长会话缓存分析后，AI 代理进入了思考循环：
- 反复调用 `git log --oneline`（至少 10 次）
- 反复 `ls .rivet/sessions/` 检查目录
- 每次 `thinking` 块都在重复相同的结论（"分析已完成，P0 已修复，文档已写好"）
- 系统两次发出"当前任务可能进入低效循环"警告

## 触发条件

1. 任务已实质完成（分析文档已写、代码已提交）
2. 用户在等待/未发新指令
3. AI 代理无法识别"任务已完成"状态
4. 持续通过工具调用寻求"确认"

## 根因分析

**核心问题：缺乏"done"信号识别。**

代理在以下情况下无法自主停止：
- 所有子任务已完成
- 文档已写入并提交
- typecheck 通过
- 测试通过
- 没有待处理的 TODO

代理的认知循环：`检查状态 → 确认完成 → 再检查一次 → 再确认`，形成无限循环。

**对比人类行为**：人类在完成后会说"搞定了"然后停止。AI 代理缺少这个"停止条件"的内化判断。

## 建议

1. **收敛检测增强**：当连续 3 次 thinking 输出相同结论时，自动触发"任务完成"信号
2. **工具调用去重**：同一工具+同一参数在 30 秒内重复调用应被抑制
3. **显式 done 原语**：代理应有一个"我完成了，等待新指令"的内部状态
4. **系统警告响应**：当系统发出"低效循环"警告时，代理应立即输出最终状态摘要并停止工具调用
