## P2.4 Subagent Orchestration — Current State

### Design decisions (final)

**Cache-first Bounded Coordinator** (V2 + V3 fusion):
- Primary AgentLoop decomposes tasks into typed WorkOrders
- Headless WorkerSessions execute with independent SessionContext
- Results return as schema-valid WorkerResult packets
- Workers produce evidence, primary decides actions

### Phase 1 hard constraints (non-negotiable)

1. **SessionContext isolation** — worker messages never enter primary session
2. **Read-only workers** — tool allowlist: `read_file`, `grep`, `glob`, `diff`, `inspect_project`, `repo_map`, `related_tests`
3. **Schema-valid results** — zod validation with one repair retry, then blocked
4. **Primary authority** — only primary AgentLoop decides final actions
5. **Prefix cache preservation** — workers share same system prompt + tool definitions
6. **Budget gate** — ≤2 tool calls → no dispatch; max 2 concurrent workers

### Phase 1 deliverables (NOT YET IMPLEMENTED)

- `src/agent/work-order.ts` — WorkOrderKind, WorkOrder, WorkerResult, AggregationPolicy, WorkerBudget types
- `src/agent/coordinator.ts` — research / code_search / review work orders
- Independent WorkerSession with read-only ToolRegistry allowlist
- Schema-valid result parsing with repair fallback
- Primary session receives only compressed worker packets
