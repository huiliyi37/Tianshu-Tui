# 规划过程反思：实时 token 输出流式渲染

> 日期：2026-05-27
> 状态：已完成反思，记录改进建议

## 1. 背景

在做"实时 token 输出流式渲染"规划时，外部模型审查发现多个关键遗漏：
- CRITICAL：去重逻辑移除会导致 DeepSeek 重复输出
- HIGH：跨 turn 去重 fingerprint 被破坏
- MEDIUM：BlockStreamWriter 阈值过低
- MEDIUM：对现有架构理解有误
- LOW：stream.tsx 已有渲染逻辑
- LOW：集成测试设计不完整

## 2. 规划过程回顾

### 2.1 读取的文件
- `turn-stream.ts` - 看到了缓冲逻辑
- `stream.tsx` - 看到了渲染逻辑
- `block-stream-writer.ts` - 看到了缓冲配置
- `turn-stream.test.ts` - 看到了测试
- `tui-stall-visibility-fix.md` - 看到了背景分析

### 2.2 遗漏的关键文件
- `dedup.ts` - **没有读取**，不知道 `stripIntraTurnRepetition` 是为了处理 DeepSeek 重复输出
- `app.tsx` - **没有深入分析**，不知道 `onTextDelta` 回调已经连接到了 `BlockStreamWriter`

## 3. 遗漏的根本原因

### 3.1 速度过快，深度不足
- 快速读取了主要文件，但没有深入理解每个函数存在的原因
- 看到 `stripIntraTurnRepetition` 时，没有去读取它的实现和注释

### 3.2 先入为主的假设
- 假设"缓冲 = 不好"，没有理解缓冲背后的去重逻辑是必要的
- 假设需要修改 `BlockStreamWriter`，没有理解真正的瓶颈在 `TurnStreamController`

### 3.3 没有检查现有实现
- 没有检查 `stream.tsx` 是否已经实现了 `isStreaming ? <Text> : <Markdown>` 的分支逻辑
- 没有检查 `app.tsx` 中的 `onTextDelta` 回调是否已经连接到了 `BlockStreamWriter`

### 3.4 测试设计过于表面
- 只考虑了 happy path，没有考虑 edge case
- 没有考虑 DeepSeek 的重复输出问题

## 4. 改进建议

### 4.1 规划前的代码审查清单
- 读取所有相关文件，包括工具函数和注释
- 理解每个函数存在的原因，而不仅仅是它的实现
- 检查现有实现是否已经解决了问题

### 4.2 规划时的假设验证
- 不要假设"缓冲 = 不好"，要理解缓冲背后的逻辑
- 不要假设需要修改某个组件，要先理解真正的瓶颈在哪里

### 4.3 规划后的自我审查
- 检查是否遗漏了关键文件
- 检查是否考虑了 edge case
- 检查是否与现有实现重复

### 4.4 测试设计的深度
- 考虑 edge case，而不仅仅是 happy path
- 考虑外部模型的已知行为（如 DeepSeek 的重复输出）

## 5. 总结

这次规划的问题不是"做的太快"，而是"深度不足"。在读取文件时没有深入理解每个函数存在的原因，也没有检查现有实现是否已经解决了问题。

**改进方向：**
1. 规划前：读取所有相关文件，包括工具函数和注释
2. 规划时：理解每个函数存在的原因，而不仅仅是它的实现
3. 规划后：检查是否遗漏了关键文件，是否考虑了 edge case

这些改进将帮助未来的规划避免类似的问题。
