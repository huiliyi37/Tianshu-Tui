### 3.2 Runtime Hook Kernel

新增：

- `src/agent/runtime-hooks.ts`
- `src/agent/__tests__/runtime-hooks.test.ts`

支持 phase：

```text
preTurn
afterPerception
postTool
postTurn
```

当前实际注册：

```text
preTurn:
  - perception-runtime
  - dissipative-kick

afterPerception:
  - vigor-after-perception

postTool:
  - theta-runtime
  - stigmergy-runtime
  - vigor-post-tool
```

重要边界：

```text
snapshot = hook 读取 runtime 状态
effects  = hook 请求 loop 执行受控副作用
```

已支持 effects：

- `setSensorium()`
- `setStrategy()`
- `setVigor()`
- `setGitChangeRate()`
- `injectUserMessage()`
- `requestThetaCheck()`
- `emitPhaseChange()`

`set*` effects 会同步更新 `snapshot`，因此同一 phase 中后续 hook 可以读到前序 hook 的输出。

## 五、与原计划的偏差

### 5.1 刻意没有实现完整 Edge Protection / Soft Landing

原计划包含：

```text
Edge Protection
Soft Landing
ELM micro-release
```

本轮实际完成：

```text
ELM micro-release request + theta telemetry ✅
Edge Protection / Soft Landing 强行为 ⏸️ 延后
```

原因：

1. Soft landing 涉及 checkpoint/session handoff，不应绕开现有 `checkpoint.ts` schema。
2. Edge protection 会触碰 compact/context 行为，必须遵守 ACF 硬约束，不能在 Vigor 主线中顺手改。
3. 当前更高收益是先让 Vigor/Hook/Perception 稳定落地。

### 5.2 没有一次性把 `loop.ts` 压到 300 行

原计划希望 `loop.ts` 缩减到约 300 行。实际本轮选择渐进迁移：

```text
先迁独立器官：theta / stigmergy / kick
再迁 perception 计算
保留 stream/tool core loop 与 compaction 主流程
```

这是有意的工程修正：中心 agent loop 承担 stream/tool/session 生命周期，不宜为了行数目标做大爆炸重构。

仍保留：

- compaction / context ceiling

- prewarm

- stream callbacks
- tool execution pipeline
- session message assembly
- cerebellar hint integration
- turn-end processing
- cache diagnostics
- final delivery flow

这些职责仍然合理地属于 `AgentLoop` 或下一轮可拆的独立 seam。

## 七、架构结果

TUI 2.2 后的运行时结构：

```text
AgentLoop
  ├── compact/context lifecycle
  ├── stream/tool lifecycle
  ├── RuntimeHookPipeline
  │   ├── preTurn
  │   │   ├── perception-runtime
  │   │   └── dissipative-kick
  │   ├── afterPerception
  │   │   └── vigor-after-perception
  │   └── postTool
  │       ├── theta-runtime
  │       ├── stigmergy-runtime
  │       └── vigor-post-tool
  └── turn-end/cache/finalization
```

这标志着 StarFlow v2 从“loop.ts 内联生理系统”演化为“runtime hook 器官网络”。
