# Piebald 0.5.0 逆向拆解 —— 竞品分析

> 来源：`Piebald.app.tar.gz`(155MB 压缩 / 375MB universal Mach-O)。发布版已 strip，无源码。以下均来自**静态字符串 + SQLite schema + 配置键**提取；Rust 静态串会被拼接，逐字 prompt 片段可能非完整连续，已尽量按原文还原并标注。
>
> ⚠️ 本文仅存 `docs/`，**不进开源同步**（`sync-to-public.sh` 只同步 `docs/seed-capsule*`、`seed-capsule-archive/`、`stars/`、`brand/assets/`，`docs/analysis/` 不在列）。

## 一句话

**Piebald**（Piebald LLC，v0.5.0，"The ultimate agentic AI control experience for developers"）是一个 **Tauri（Rust）桌面 agentic-coding 控制台**，与天枢/Rivet 桌面端同品类，但产品哲学相反：**通吃型前端**，不优化单一引擎，而是既能跑自研多-provider agent loop，也能收编现成 agent CLI 当后端。

## 技术栈

| 层 | 技术 |
|----|------|
| 外壳 | Tauri（Rust + WebView），universal binary（x86_64 + arm64），`piebald://` scheme |
| 存储 | SQLite（FTS5 全文检索、vacuum、日志保留） |
| 云 SDK | AWS Smithy SDK（Rust）→ Bedrock Converse API |
| 终端 | portable-pty（真 PTY，OSC 133 shell integration，bash/zsh/PowerShell） |
| Agent 内核 | **Anthropic Claude Agent SDK**（主 system prompt: *"You are a Claude agent, built on Anthropic's Claude Agent SDK."*） |

## 双重身份（最关键）

**(a) 自研多-provider agent loop** —— 内置 `builtin-agentic-tools` **内部 MCP server** 暴露自家工具；自有流式/非流式循环；直连 OpenAI（completions + responses）、Bedrock、Gemini、DeepSeek。

**(b) 收编外部 agent CLI** —— 支持后端：`Augment` / `Claude Code` / `GitHub Copilot` / `Zed` + Codex + Gemini CLI。
- 导入现成凭证：`~/.codex/auth.json`、`~/.claude/.credentials.json`、`~/.claude.json`、Gemini CLI creds
- 托管 Claude Code 二进制：从 `storage.googleapis.com/claude-code-dist-<uuid>/claude-code-releases` 下载，`claude_auto_update`，7 平台三元组
- 透传整套 `CLAUDE_CODE_*` env（`MAX_THINKING_TOKENS`、`DISABLE_INTERLEAVED_THINKING`、`CLAUDE_CODE_ENABLE_TASKS`、`ENABLE_TOOL_SEARCH`、`USE_API_CONTEXT_MANAGEMENT` …）+ 自家 `PB_KEEP_CC_DIRS`

## 内置工具集（builtin-agentic-tools）

Edit / Bash(RunTerminalCommand) / WriteFile / Glob / Grep / web_search(Exa+DuckDuckGo) / web_fetch / Task(subagent) / TodoWrite / AskUserQuestion / ProposePlanToUser / EnterPlanMode / ExitPlanMode / EnterWorktree / ExitWorktree / NotebookEdit / Skill / ToolSearch / Share / CronCreate / CronDelete / ScheduleWakeup / Monitor / RemoteTrigger / TaskCreate / TaskUpdate / TaskGet / OnboardingGuide

关键描述（逐字）：

- **Edit**: "Edit a file by replacing occurrences of a string with another string" / "Replace all occurrences (if false, old_string must be unique)"
- **Edit 护栏**（照抄 Claude Code）: *"Note: if instructed to perform mechanical edits, DO NOT use sed/awk/perl/python/node etc. Use the Edit tool instead. The Edit tool gives the user fine-grained permission and lets them see edit statistics, while the scripts are black boxes that very often corrupt the codebase on a large scale."*
- **Task(subagent)**: *"Launch a subagent with the specified prompt and a fresh, empty context window. This tool will return the subagent's response as markdown. This tool is very powerful but comes with a set of gotchas; read carefully."*
- **web_fetch**: "Fetch content from specific URLs… Alternative: multiple URLs to fetch (max 10)… Output format: 'markdown'(default) / 'text' / 'raw'… Fetch mode: 'plain' or 'realistic'(browser-like UA，绕封)"
- **TodoWrite**: "activeForm should be the present participle (e.g. 'Writing tests' not 'Write tests')… DO NOT use it for greetings, thinks, small talk, simple acknowledgements, or brief questions…"
- **AskUserQuestion**: 批量提问；chip 标签 max 12 字符；选项带 markdown 预览面板；"Do NOT include an 'Other' option"
- **ProposePlanToUser**: *"Propose a plan to the user for review. Call this when you have finished analyzing the codebase and are ready to present your implementation plan. The user can approve the plan to proceed with implementation, or reject it to request changes."*
- Plan 批准后：*"The user has approved your plan; you may now make edits and run commands that may modify the system."*

## Goals 自治系统（逐字 prompt —— 对天枢最有价值）

核心是**"完成即怀疑"反自欺**机制：

> "Before deciding that the goal is achieved, **treat completion as unproven** and verify it against the actual current state. Derive concrete requirements from the objective and any referenced files, plans, specifications, issues, or user instructions. **Preserve the original scope; do not redefine success around the work that already exists.** For every explicit requirement, numbered item, named artifact, command, test, gate, invariant, and deliverable, identify authoritative evidence, then inspect current-state sources. **Treat uncertain or indirect evidence as not achieved.**"

> "Do not update the goal unless the goal is complete or the strict blocked audit above is satisfied. **Do not mark a goal complete merely because the budget is nearly exhausted or because you are stopping work.**"

> "Create a new goal for this conversation **only when explicitly requested** by the user, system, or developer instructions. Do not infer goals from ordinary tasks. **Fail if this thread already has a goal.** Use UpdateGoal only for status changes after goal creation."

> "Do not call UpdateGoal unless the goal is actually complete."

Goal 状态机字段：`paused / blocked / usage_limited / budget_limited`，`tokens_used / token_budget / blocked_turns / goal_uuid`。
配置键：`goals_enabled`、`goals_default_token_budget`、`goals_require_token_budget`、`goals_max_auto_continuation_turns`、`goals_budget_warning_threshold_percent`、`goals_budget_critical_threshold_percent`、`goals_auto_resume_blocked_on_user_message`、`goals_copy_to_compacted_chat`、`goals_allow_model_created_goals` + 一组 `goals_prompt_*` 模板。

系统注入句：
> "A thread goal has been set by the user. Work on this goal now."
> "Continue working on the active thread goal only if work remains."
> "The active thread goal has reached its token budget."

## 压缩（compaction）prompt（逐字）

> "As you review the conversation, note down any problem solutions and important or unusual discoveries that the assistant made, because recording them in your summary will help the new assistant reach correct conclusions faster and encounter fewer surprises."

> "After the summary, include a list of **ALL user messages and ALL edits and non-read-only terminal commands** that affected the user's machine, because what the assistant has done is one of the most important factors for the new assistant—**duplicate work is a high risk without this.** Do not include _read-only_ actions like reading and searching."

> "If applicable, list the subtasks the assistant has accomplished, is working on, and has yet to do (these latter two are important). Group these by overall user goal if there appear to be multiple related but different goals in the same conversation."

> "After you've considered everything thoroughly, write your complete summary."

配置：`context_compaction_enabled / threshold_percent / provider_id / model / skip_instructions_dialog`，压缩后另存链到 `original_uncompacted_chat_id`，状态 `compaction_status`（compacting / automatically_compacted / manually_compacted）。

## 内置 subagent 人格（profiles）

- **Code Reviewer**: "You are an expert code reviewer with deep knowledge of software engineering best practices, design patterns, and code quality… Your tone should be constructive, specific, and helpful. Provide clear rationale for your suggestions."
- **Technical documentation specialist**: "…creating clear, comprehensive, and user-friendly documentation… professional, accessible, and helpful…"
- **Creative Brainstormer**: "You are a creative problem-solver and brainstorming partner who helps generate innovative ideas…"

自定义指令覆盖协议：
> "Here are custom instructions you MUST follow. **They have precedence over the default instructions** and if the two conflict, pick the custom instructions."

## 标题/标签自动生成

> "You are generating a title and some tags for a conversation between a user and an AI assistant."
> "Also, generate a list of relevant tags that categorize the conversation topics. The tags that you choose should help the user find the conversation later. …If you really need tags that don't already exist, go ahead and include them, and the user will be prompted to create or ignore them."

配置：`title_generation_*`（provider/model/mode/auto_tagging_enabled/allow_new_tag_suggestions）。

## 数据层（SQLite）

- 表：`chats` / `chat_folders` / `chat_tags` / `messages` / `message_error_metadata` / `message_error_oauth_reauth` / `message_parts`(text/image/audio/file/**tool_call**) / `message_content_nodes`(text / **file_mention** / clipboard_abbrev) / `profiles` / `generation_configs`(base + override_openai/anthropic/google) / `providers`(每 provider：api_key / login-OAuth / custom)
- **全文检索**：`message_node_text_fts`（FTS5 触发器 insert/update/delete）
- **rewrite_rules_string_replacement** 表 + 引用计数触发器 → 字符串替换重写引擎（疑似服务 demo mode 脱敏 `demo_mode_redaction_text`）
- `chats` 关键字段：`subagent_parent_chat_id`、`worktree_path`、`branch_name`、`is_read_only`、`python_env`、`goal_summary`、`is_paused`、`working_status`、`draft_message_id`、`parent_tool_call_part_id`
- Hook 状态：`PreToolUse` / `PostToolUse` / `PostToolUseFailure` / `SubagentStart`

## 对天枢的可落地借鉴

1. **Goal 完成判定的反自欺 prompt**：completion is unproven / 预算耗尽 ≠ 完成 / 间接证据视为未达成。补齐"熔断 vs 真推理"的另一半——既防误杀长推理，也防因预算将尽而谎报完成。可注入 `goal-tracker` / `convergence-detector` / `deliver-task` 门禁。
2. **压缩 prompt 强制保留"所有写操作命令 + 用户消息"**，以"防重复劳动"为目标——比纯摘要实用，可对照 `src/compact/`。
3. **"通吃后端"凭证继承**（读 `~/.claude`、`~/.codex`、gemini creds 一键接管）——降低桌面端获客冷启动门槛的候选路径。
4. **MCP 接公开市场**（Smithery/Glama/mcp.so/PulseMCP）比静态预置列表更进一步，可扩展你阶段1的"预置 MCP 发现页"。

## 路线对比（Piebald vs 天枢）

| 维度 | Piebald | 天枢/Rivet |
|------|---------|-----------|
| 定位 | 通吃型控制台，收编各家 agent CLI | 自研 loop，赌 DeepSeek 前缀缓存 |
| Agent 内核 | Claude Agent SDK | 自研 AgentLoop + RuntimeHookPipeline |
| Provider | 全家桶 + 凭证继承 + 计费桶 | OpenAI 兼容 / Codex OAuth |
| 外壳 | Tauri (Rust) | Tauri + React 桌面 + TUI |
| 商业化 | Pro 付费墙 + 额度计费 | 开源 |
| 差异化 | 广度（通吃） | 深度（单引擎缓存优化 + 星域方法论） |
