## 关键发现

### 1. 命中率低于 v3 预期

v4 稳态命中率 95.3%，p50=840，明显低于 v3 的 97.5%/p50=431。

**可能原因**：
- **代码版本不匹配**：v4 可能未运行 `ce34bdc` (frozen appendix) 代码。缓存特征更接近 P1 standalone appendix（p50 ~800 vs frozen 的 ~430）
- **22 轮样本量小**：v4 只有 22 轮 vs v3 的 50 轮，统计波动更大
- **工具密度高**：22 轮中至少 3 次大 read_file（turns 3, 6, 8），每次产生大量新 tokens

### 2. 大工具输出是主要 drop 原因

Turn 6 (read_file): input +3.4K, 命中率 85.7%
Turn 8 (read_file): input +6.4K, 命中率 79.4%

这些是正常的工具输出增长，非前缀缓存断裂。排除大工具输出后，稳态命中率在 94-98.7%。

### 3. 末期趋势向好

Turns 14-19：命中率 97.6-98.6%，p50 create ~800。随着上下文增长，appendix 占比下降，命中率自然上升。

### 4. 需确认代码版本

v4 的缓存特征（p50=840）介于 v2 standalone（p50=2632）和 v3 frozen（p50=431）之间，更接近 P1 standalone 行为。建议确认：
- agent 是否在 ce34bdc 之后 rebuild 了代码
- 或者 session 是否使用了缓存的旧 build

v4 会话是有效的长会话验证，共 22 轮 API 调用。缓存表现（95.3% 稳态）明显优于 v2 standalone（90.2%），但低于 v3 frozen（97.5%）。建议确认代码版本一致性后重新测试。
