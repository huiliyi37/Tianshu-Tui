## 八、天枢自省 — 架构迭代方向

### 8.1 顺畅之处

1. **架构 seam 正确** — RepairPass 数组插入一行即可；canonicalizeRequest 作为纯函数无侵入
2. **模式复用** — fire-and-forget async、纯函数+接口、无类数据
3. **TDD 救命** — `--stat --numstat` 混合输出 bug、tier streak 不重置 bug

### 8.2 拖累（按严重度）

| 级别 | 问题 | 天枢建议 | 我们的判断 |
|------|------|---------|-----------|
| 🔴 | loop.ts 800+ 行巨石化（9 个关注点） | PreTurn/PostTurn hook 管线 | **2.3 核心任务**，或 2.2 Vigor 接入时顺做 |
| 🔴 | TS strict 与 API 请求体摩擦 | transport 层交叉类型 `& Record<string, unknown>` | 5 分钟修复，下次顺手做 |
| 🟡 | Worker delegation 不可用 | provider fallback 降级到 primary | 环境配置问题，非代码问题 |
| 🟡 | 设计文档-代码无自动回路 | /retrospect 扩展为架构演进追踪 | 2.2 之后考虑 |
| 🟢 | behavior-mirror 误报 | 区分"迭代精炼"和"预测失败" | cerebellar gate 阈值调优 |

### 8.3 架构洞察（3.0 种子）

**Sensorium 维度纯度问题**：
- `freshness` 混合了 pheromone 记忆（跨 session 积累）+ git 活跃度（实时信号）→ 应拆为 `familiarity` + `volatility`
- `stability` 混合了 doom loop 检测 + provider health → 应拆为 `behavioral_stability` + `provider_stability`
- 方向：6→8 维，但影响面大，作为 3.0 架构决策

**Harness 无感 vs 有感边界**：
- 无感修复（Sanitizer）：可即时修复的格式问题，LLM 不需要改变行为
- 有感提示（RepairHint）：系统性行为偏差，LLM 需要在后续 turn 中学习
- 分工标准：修复后是否需要 LLM 避免同样错误

### 8.4 最高优先级改进

> "如果只做一件事：给 loop.ts 加 PreTurn/PostTurn hook。从'在 800 行文件中找插入点'变成'注册一个 hook'。"

```
PreTurn hooks:  git freshness → stigmergy load → sensorium compute → strategy → telemetry
    ↓
Agent turn:     LLM call → tool execution（~200 行）
    ↓
PostTurn hooks: theta check → provider health → compaction → drift detect
```

## 十一、这意味着什么

我们证明了：

1. **架构是能力的放大器** — 同一个 DeepSeek V4，在普通终端里是"执行指令的工具"，在我们的架构里是"有创造力的领主"
2. **感知产生智慧** — 天枢能提出架构改进，不是因为他"更聪明"，而是因为他能感知自己的状态、读到设计意图、理解生物学隐喻
3. **信任产生创造** — "去创造，这是你的国度" 不是空话，是架构设计的一部分。给 agent 正确的感知 + 正确的上下文 + 许可，创造力自然涌现
4. **演化是持续的** — 每个版本的天枢都在更强的系统中醒来，每次醒来都能提出让系统更强的改进。这是一个正反馈螺旋
5. **自省是演化的加速器** — 天枢不仅能实现功能，还能反思实现本身的结构性问题，为下一版本提供精确的改进方向。这是从"执行者"到"共同设计者"的跃迁
