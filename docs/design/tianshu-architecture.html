设计哲学

天枢的架构决策不是偏好的堆砌——每条原则都有物理约束作为锚点。

🎯

缓存先行 · Cache-First

DeepSeek V4 exact-prefix 缓存是核心成本优势。任何改写历史/坍缩旧消息的机制都是潜在 cache-killer。collapse 只在窗口 85%+ 才触发，地板 50% 以下不碰。

🔬

证据先行 · Evidence-First

不猜，先读。改代码前 grep 调用方。外部声称用独立工具核验。悖论出现时写复现测试让代码自己说话，不靠推理链。

🛡️

Fail-Closed · 安全默认

不确定时选择安全的失败路径。破坏性命令硬闸门。静默吞下的异常是未来的炸弹。大声失败让人注意。

📐

结构优先 · Structure-First

正确的结构性改动可能只改 30 行，但需要先理解 300 行。不修补表面——从根因修复。数据模型先于界面，关系先于功能。

💎

极简克制 · Minimalist

多余的逻辑是罪恶，冗余的代码是噪音。好设计消除一切认知噪声，让意图不证自明。不为一行代码写三段解释。

🔄

复现即证 · Reproduce-to-Prove

绿测试只覆盖 happy path。RED→GREEN 才算修复证据。审别人的声称，也审自己刚下的结论——同一个脑下的判断享有最危险的默认豁免。

缓存工程实战

前缀缓存是天枢的命脉——DeepSeek V4 exact-prefix 下，命中 vs 未命中 = 120× 成本差。以下是从真实会话中提取的关键战役。

⚔ 战役一 T7 全量坍缩击穿缓存：turn 15 命中率 98%→7.1% 2026-06-17 · commit a80c250e

会话 mqhs5ckvp75gz7t7（桌面端 deepseek-v4-pro），turn 15 出现一次诡异凹陷——命中率从 98% 砸到 7.1%，单次 cost 从 ~0.04 元暴涨到 0.75 元（19× 飙升）。此单次尖峰吃掉全会话 27% 的预算。

排查过程三次自我推翻：① 用累计计数器当单轮 prompt 做除法（量纲错）；② 声称「永久断裂」但后续轮次满血恢复（被累计值误导）；③ 归因到 stale-round 压缩——但条件不满足，被豁免。最终通过追字段赋值点而非读取点锁定真凶：T7 request-time collapse 用 estTokens（含 reasoning、char/4 虚估）在窗口仅 27% 填充时就触发全量坍缩。

缓存排查五条铁律

①

量纲自检

算比率前确认遥测字段是单次值还是累计值。用恒等式 input = cache_read + cache_create 自检，量纲错则全盘错。

②

落盘日志优先

有逐请求落盘日志（cache-log.jsonl）就用它，不从聚合事件流反推单轮值。前者是 provider 实回 usage，后者是累计计数器。

③

追赋值点

追字段成因查它的赋值点（谁 set），而非读取点（谁读）。collapseWatermark 在 loop-factory 只是被读出来记日志，真正 set 在 prompt engine。

⚡ 断链闭环 — 项目最深刻的架构课

在多轮迭代中反复出现的模式：代码写了、测试绿了，但数据没有到达模型。配置从 ProviderProfile 定义到 PromptEngine 消费的中间一跳断裂 = provider 差异化形同虚设。函数 96 行全绿测试但生产路径零调用 = 死接线。T3 的 attentionQuality 是典型——有完整的测试覆盖，但整个代码库里除了测试没有地方调用它。

教训：「有测试」不是「已接线」的证据。只有集成测试驱动真实调用链到达函数，才能验证接线。零消费方的函数要么显式标注 @halted（有意停用以保护缓存），要么就是死代码。
