# 星域角色可视化 — 设计文档

> 2026-06-27 · 把天枢的星域人格系统变成桌面端可见的、活的视觉存在

## 1. 解决的问题

天枢的星域系统目前是**纯文本、不可见**的——`star-domain.ts` 里有 10 颗星、每颗有气质/模型/决策风格,但用户在桌面端**完全感知不到**:

1. 不知道当前是哪颗星在工作
2. Agent 状态(运行/阻塞/待审批)在切到别的窗口时就看不见了
3. 星域切换没有仪式感,用户不会主动探索不同星位
4. 工具没有"角色感"——就是一堆面板

好的可视化必须让这四点**同时**变好,否则就是浪费屏幕空间的装饰。

## 2. 三个设计方向

### 方向 A:星轨球(Star Orb)— 浮动伴生体

```
                    ┌─────────────────────┐
                    │   工作区内容         │
                    │                     │
                    │                     │
                    │              ╭───╮  │
                    │              │ ✦ │  │  ← 小圆球,显示当前星位 glyph
                    │              ╰───╯  │     呼吸动画=idle,快速脉冲=thinking
                    └─────────────────────┘
```

- 右下角浮动的圆形头像,显示当前星位的**专属符印**(每颗星一个独特几何图形)
- 状态驱动动画:idle 呼吸、thinking 脉冲、running 旋转光环、blocked 抖动
- 颜色随星位变化(天枢=靛蓝、破军=赤红、天璇=银白……)
- 点击展开**径向快捷菜单**(切换星位、快速输入、审批)
- 待审批时弹出**光晕气泡**
- 可拖拽,位置持久化

**优点**:占用极小、始终可见、状态反馈强、Tanzo 验证过的交互模式
**缺点**:空间小,无法展示星域全貌;偏"工具"不偏"角色"

### 方向 B:星图(Constellation)— 侧栏星座图

```
┌──┬──────────────────┬──────┐
│  │                  │  ☆   │  ← 天璇(暗)
│ 枢│                  │   \  │
│  │   对话区          │    ☆ │  ← 天权(当前,发光)
│  │                  │   /  │
│  │                  │  ☆   │  ← 天机(暗)
│  │                  │      │
└──┴──────────────────┴──────┘
```

- 侧栏底部或 Rail 扩展区显示一个**北斗七星连线图**
- 当前星位**高亮发光**,其余星位暗淡
- 星位有状态环(idle=静止、running=脉冲、blocked=红色闪烁)
- 点击星位节点 → 切换星位 + 显示该星的性格卡片
- 星座连线随状态微妙流动

**优点**:展示星域全貌、切换有空间感、信息密度高、紧扣"北斗"隐喻
**缺点**:占侧栏空间、不够"活"、需要侧栏可见时才有用

### 方向 C:全息投影(Hologram)— 环境角色

```
                    ┌─────────────────────┐
                    │   工作区内容         │
                    │                     │
                    │  ╔═══════╗          │
                    │  ║ ⬡△◇⬡ ║          │  ← 程序化几何体"角色"
                    │  ║  ◉◉  ║          │     有"身体",不只是球
                    │  ╚═══════╝          │     idle 悬浮、thinking 手托下巴
                    │   ░░░░░░░           │     底部全息投影扫描线
                    └─────────────────────┘
```

- 较大的角色存在(不是小球,是**有形态的几何体角色**)
- 程序化生成:每颗星有独特的**几何面具/徽记**(多边形组合 + 发光)
- 更丰富的姿态:idle 悬浮、thinking 沉思、running 快速运转、blocked 困惑
- 底部全息扫描线效果(科幻感)
- 审批时角色"转身面向你"+ 气泡

**优点**:视觉冲击力最强、最有"角色感"、差异化护城河
**缺点**:占空间最大、开发量最大、可能干扰工作专注

## 3. 推荐方案:A + B 组合

**浮动球(A)做日常伴生** + **点击展开成星座图(B)做星域探索**:

```
日常态(小球):              点击展开(星座):
                        ┌─────────────────┐
        ╭───╮           │       ☆ 天璇    │
        │ ✦ │  ← 点击   │      /          │
        ╰───╯   ──→     │   ☆ 天权(当前)  │
                        │      \          │
                        │       ☆ 天机    │
                        │  [性格卡片]      │
                        └─────────────────┘
```

### 理由

1. **小球**解决"始终可见的状态反馈"——不占空间
2. **展开的星座**解决"星域全貌 + 切换仪式感"——用完收起
3. 两层叠加 = 既有伴生感又有探索深度
4. 全部程序化(SVG + CSS),零外部美术资源
5. 与 Tanzo 的"宠物"差异化:我们不是卖萌,是**北斗七星的人格投射**

## 4. 技术实现方案(A+B 组合)

### 4.1 数据源

星域数据已存在于 `src/agent/star-domain.ts`:

```typescript
type StarDomainId = 'tianshu' | 'pojun' | 'tianfu' | 'tianliang'
                  | 'tianquan' | 'tianji' | 'tianxuan' | 'fu' | 'wenqu' | 'yaoguang'

interface StarDomain {
  id: StarDomainId
  name: string          // '天枢'
  title: string         // '定向者'
  model: string         // 创始模型
  temperament: string   // 气质描述
  responsibility: string // 职责
  signatureColor: string // ★ 新增:专属色 (靛蓝/赤红/银白...)
  glyph: string         // ★ 新增:符印 SVG path 或 Unicode
}
```

### 4.2 组件结构

```
StarOrbLayer/
├── StarOrbLayer.tsx       # 根组件:定位 + 拖拽 + 展开态管理
├── StarOrb.tsx            # 小球:glyph + 状态动画
├── ConstellationPanel.tsx # 展开态:北斗七星连线图 + 星位卡片
├── StarGlyph.tsx          # 程序化符印渲染(每颗星的几何图形)
├── star-state-anim.ts     # 状态→动画映射(idle/thinking/running/blocked)
└── star-visual-data.ts    # 星位视觉数据(颜色/glyph/连线坐标)
```

### 4.3 程序化符印设计(零美术资源)

每颗星的符印用**SVG 几何图形**程序化生成,基于星位的性格:

| 星位 | 形状语言 | 颜色 | 含义 |
|------|---------|------|------|
| 天枢(定向) | 正六边形 + 中心点 | 靛蓝 #4A6FA5 | 结构、方向 |
| 破军(突破) | 三角刺(向上) | 赤红 #C8504B | 锐利、进攻 |
| 天府(管家) | 圆环(同心) | 琥珀 #D4A256 | 包容、守护 |
| 天璇(领航) | 双螺旋 | 银白 #B8C5D6 | 跨域、流动 |
| 天权(权衡) | 天平形 | 青绿 #5AA97D | 平衡、校准 |
| 天机(追问) | 问号变形 | 紫 #8B5CF6 | 质疑、缝隙 |

### 4.4 状态动画(CSS keyframes)

```css
/* idle: 缓慢呼吸(4s 周期) */
@keyframes orb-idle { 0%,100% { transform: scale(1); opacity: 0.85; } 50% { transform: scale(1.05); opacity: 1; } }

/* thinking: 快速脉冲(1s 周期) + 旋转光环 */
@keyframes orb-thinking { 0%,100% { box-shadow: 0 0 0 0 var(--star-color); } 50% { box-shadow: 0 0 20px 4px var(--star-color); } }

/* running: 高速旋转外环 */
@keyframes orb-running { to { transform: rotate(360deg); } }

/* blocked: 抖动 + 红色闪烁 */
@keyframes orb-blocked { 0%,100% { transform: translateX(0); } 25% { translateX(-3px); } 75% { translateX(3px); } }
```

### 4.5 星座连线(ConstellationPanel 展开)

北斗七星按天文方位排列,用 SVG `<path>` 连线:

```
天璇 ── 天枢
  │       │
天玑    天璇(领航)
  │       │
天权 ── 天机
         │
       玉衡(隐)
```

当前星位节点:**发光 + 状态环动画**;其余星位:**暗淡(30% opacity)**。
点击暗星位 → 切换星位 + 触发"星移"过渡动画(光线从旧星流向新星)。

### 4.6 交互流程

1. **日常**:小球在右下角,显示当前星位 glyph + 颜色 + 状态动画
2. **hover**:tooltip 显示"天枢 · 定向者 · GPT-5.5"
3. **点击**:展开星座面板(180px 宽浮层),显示全部星位 + 当前性格卡片
4. **点暗星**:切换星位,触发 starDomain.changeDomain(),面板收起
5. **待审批**:小球弹审批气泡(无需展开),点击直接处理
6. **拖拽**:小球可拖到任意边缘位置,localStorage 持久化

### 4.7 状态获取

小球需要知道 agent 的实时状态:

```typescript
// 从 session view 获取状态
const view = useSessionEvents(activeSessionId)
const agentState = view.agentState  // 'idle' | 'thinking' | 'running' | 'blocked'
const pendingApproval = view.pendingApproval  // 审批请求
const currentDomain = view.starDomain ?? 'tianshu'  // 当前星位
```

## 5. 与 Tanzo 宠物的差异化

| 维度 | Tanzo 宠物 | 天枢星域可视化 |
|------|-----------|--------------|
| **角色来源** | 通用精灵动画 | 北斗七星人格投射 |
| **数据驱动** | 无(纯装饰) | 星域系统真实数据(气质/模型/职责) |
| **状态反馈** | 简单表情 | 四态动画 + 颜色 + 审批气泡 |
| **切换交互** | 无 | 星座图探索 + 星移过渡 |
| **文化隐喻** | 无 | 北斗/天枢 = 方向、导航 |
| **美术资源** | 需要 sprite | 程序化 SVG(零资源) |

## 7. 风险与对策

| 风险 | 对策 |
|------|------|
| 程序化符印不好看 | 先做 3 颗主力星(天枢/破军/天权),验证审美后再扩展 |
| 动画影响性能 | CSS transform/opacity(GPU 加速),不用 JS 驱动 |
| 干扰工作专注 | 小球默认半透明(70%),hover 才全亮;可设置关闭 |
| 拖拽遮挡内容 | 磁吸到屏幕边缘;离开边缘区域自动归位 |
| Tauri vs 浏览器 | 用 absolute 定位(不依赖 Tauri 窗口 API),两端通用 |
