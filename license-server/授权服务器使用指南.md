# 天枢授权服务器使用指南

> 本文档仅限内部使用，不同步到开源仓库。

## 一、概述

授权服务器部署在 Cloudflare Workers 上，负责：
- 激活码生成与管理
- 设备绑定与吊销
- Ed25519 签名 token 签发与验证
- 桌面端激活状态心跳校验

**生产地址**：`https://tianshu-license-server.huiliyi37.workers.dev`

## 二、管理后台

### 访问

浏览器打开：`https://tianshu-license-server.huiliyi37.workers.dev/admin`

输入管理密钥登录（当前：`Heye@978796`，可通过 `wrangler secret put ADMIN_TOKEN` 修改）。

### 生成激活码

1. 点击右上角「+ 生成激活码」
2. 填写参数：
   - **数量**：一次生成几个码（1-200）
   - **设备上限**：每个码可绑定几台设备（默认 2，主力+备用）
   - **等级**：pro / standard
   - **有效期天数**：留空=永久；填 365=一年后到期
   - **备注**：推荐填用户邮箱，便于追溯
3. 点击「生成」，码自动复制到剪贴板

### 管理码

- **搜索**：按码 / 备注 / 设备 ID 过滤
- **状态筛选**：全部 / 正常 / 已吊销 / 已满
- **吊销/恢复**：单行操作或批量勾选后底部「批量吊销」
- **查看设备**：点击设备列的数字，查看该码绑定的所有设备及最后心跳时间
- **复制码**：单行复制按钮

### 码的状态说明

| 状态 | 含义 |
|------|------|
| 正常 | 未吊销，未用满 |
| 已满 | 已绑定到设备上限 |
| 已吊销 | 被管理员吊销，客户端下次心跳被锁 |

## 三、激活流程

### 用户首次激活

1. 用户安装天枢桌面端
2. 启动时，Rust 侧检查本地 license token
3. 无 token → 不拉起 agent sidecar → 前端显示激活界面
4. 用户输入激活码 → 前端 POST `/activate` → 服务器签发签名 token
5. Rust 侧 Ed25519 验签 token → 通过则落盘 → 重启拉起 sidecar

### 心跳校验

- 启动后 15 秒 + 每 6 小时一次 POST `/verify`
- 服务器验签 + 检查吊销状态 + 续签 token
- 续签失败或被吊销 → 客户端自动 deactivate → 下次启动锁死

### 离线宽限

- 最近一次成功心跳后 10 天内，即使服务器不可达仍可使用
- 超过 10 天 → 锁死，需重新联网激活

## 四、密钥管理

### 生成密钥对

```bash
cd license-server
node scripts/genkeys.mjs
```

输出：
- **PRIVATE KEY**（PKCS#8 base64）→ 设为 Worker secret：`wrangler secret put SIGNING_KEY_PKCS8`
- **PUBLIC KEY**（raw 32 bytes base64）→ 硬编码到 `desktop/src-tauri/src/activation.rs` 的 `PUBLIC_KEY_B64`

⚠️ 私钥绝不进客户端代码，只在 Worker 上使用。

### 当前密钥

- 已生成并部署到 Worker（secret）
- 公钥需替换到 Rust 验签器（当前仍为全零占位符）

## 五、API 端点

### 公开端点

| 端点 | 方法 | 说明 |
|------|------|------|
| `/health` | GET | 健康检查，返回 `{"ok":true}` |
| `/activate` | POST | 激活码兑换，返回签名 token |
| `/verify` | POST | token 验签 + 吊销检查 + 续签 |

### 管理端点（需 Bearer ADMIN_TOKEN）

| 端点 | 方法 | 说明 |
|------|------|------|
| `/admin` | GET | 管理后台页面 |
| `/admin/api/codes` | GET | 列出所有码 |
| `/admin/api/codes` | POST | 批量生成码 |
| `/admin/api/codes/:code` | PATCH | 吊销/恢复/修改码 |
| `/admin/api/codes/:code/devices` | GET | 查看码绑定的设备 |

### 命令行生成码

```bash
# 生成 10 个码，每码 2 台设备，30 天有效期
node scripts/gencode.mjs --count 10 --devices 2 --days 30 2>/dev/null > /tmp/codes.sql
./node_modules/.bin/wrangler d1 execute tianshu-licenses --remote --file=/tmp/codes.sql
```

## 六、安全注意事项

1. **ADMIN_TOKEN** 生产环境用强密码，当前 `Heye@978796` 仅用于测试
2. **license-server/ 目录不同步到开源仓库**（sync-to-public.sh 已排除）
3. 私钥只在 Cloudflare Worker secret 中，不在代码里
4. 桌面端 Rust 验签使用编译进机器码的公钥，前端 patch 无法绕过
5. 占位公钥（全零）必须替换为真实公钥，否则所有激活失败（fail-closed）

## 七、故障排查

| 现象 | 原因 | 解决 |
|------|------|------|
| 所有激活失败 | Rust 公钥未替换 | genkeys → 替换 activation.rs → 重新编译 |
| 管理后台 401 | ADMIN_TOKEN 错误 | wrangler secret put ADMIN_TOKEN 重设 |
| 用户无法激活 | 激活码已满/已吊销/已过期 | 管理后台查看状态，生成新码 |
| 离线后无法使用 | 超过 10 天宽限期 | 重新联网，系统自动心跳恢复 |
